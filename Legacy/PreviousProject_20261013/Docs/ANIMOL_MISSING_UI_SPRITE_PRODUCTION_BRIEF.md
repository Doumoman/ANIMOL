# ANIMOL 미완성 UI · 외부 제작용 화면 및 스프라이트 명세

작성일: 2026-10-04 · 기준 프로젝트: Unity 6000.3.8f1 / ANIMOL

**제작 우선순위: 상점 → 설정·조작 설정 → 경쟁전 유형·비공개 방 설정 → 대기방 → 계정·이모티콘·기록·도움말.**

이 문서는 현재 프로젝트에 있는 기본 화면을 완성된 게임 UI로 제작하기 위한 전달서다. 현재 코드·프리팹·PNG·기존 캡처를 조사했다. 이번 작업에서 게임 UI를 수정하거나 새 Play Mode 검증을 실행하지 않았다. 아래 신규 파일명·픽셀 크기·화면 배치는 **제작 제안**이며, 이미 구현된 기능이나 확정된 서버 정책이 아니다.

외부 제작자는 이 문서의 **4~8절을 제작 범위**, **3절을 재사용 목록**, **9절을 납품 기준**으로 사용한다. 프로그램 구현 담당자는 2·10절의 연결 제한도 함께 확인한다.

## 2. 경쟁전 ‘유형’과 ‘방 만들기’를 구분하기

현재 버튼에 있는 **일반 경쟁 / 랭크 경쟁**은 경기 규칙의 구분이다. **비공개 방**은 방에 들어가는 방식이다. 비공개 방에 어떤 경기 규칙을 허용할지는 운영 계약이 아직 없으므로, 세 항목을 임의의 서버 모드 ID로 만들지 않는다.

| 구분 | 제작할 표현 | 데이터/정책 주의점 |
|---|---|---|
| 일반 경쟁 | 일반 경쟁 카드, 보유 성장 적용 안내 자리 | 실제 계정/동물 성장 스냅샷을 나중에 연결 |
| 랭크 경쟁 | 랭크 카드, 동일 성장 프리셋 안내 자리 | 티어·점수·보상표·시즌 구조는 미정. 임의 배지 체계 제작 제외 |
| 비공개 방 | `방 만들기` / `코드로 참가` 2개 진입 | 방 ID/코드/초대 값은 서비스가 발행. 클라이언트에서 번호 생성 금지 |
| 경쟁 인원 | 인원 표시 및 필요 시 선택 부품 | 기존 범위 **4~8인** 유지. 모든 정수 인원을 방장이 선택 가능한지는 미정 |
| 경기 규칙 | 서버 정책 요약 카드 | 기존 3맵 경기·경쟁 참가자 간 동일 동물 허용 유지. UI에서 중복 금지/선점 토글 추가 금지 |
| 협동 | 같은 부품, 다른 모드 설명 | 기존 범위 2~4인. 경쟁의 3역할·중복 규칙을 무조건 복사하지 않음 |

제안 흐름(신규 화면명은 **디자인용 이름**이며 기존 SC 번호가 아님):

```text
기존 로비 → 경쟁 허브
  ├─ 일반 / 랭크 → 모드 설명·진입 확인
  └─ 비공개 방
       ├─ 방 만들기 → 방 옵션·요약
       └─ 코드로 참가 → 코드 조회·방 요약
                            ↓
                기존 Phase3 동물 선택·3종 확인
                            ↓
                실제 입장 승인 → 기존 대기방
```

위의 중간 화면은 호스트의 진입 의도를 준비하는 UI다. `방 만들기`를 눌렀다는 이유로 동물 3종 확인 전에 방 생성/참가를 별도 실행하지 않는다. 승인 전 대기방 이동도 하지 않는다. 초대 확인은 기존 플랫폼/서비스 초대 계약이 생길 때 같은 방 요약 패널을 재사용한다.

이번 스프라이트 발주에 **공개 방 목록, 친구 목록, 채팅, 파티 초대 시스템, 팀 배정, 비밀번호, 맵 투표, 관전, 티어/시즌 보상 체계**는 포함하지 않는다. 필요해지면 먼저 운영 정책을 확정한다. 코드 참가에 비밀번호 입력을 임의로 붙이지 않는다.

**스타일 기준:** 현재 공용 패널·버튼과 동물 UI의 픽셀 표현을 우선한다. 어두운 외곽선, 밝은 판면, 청록 주 버튼, 명확한 상태 아이콘을 일관되게 사용한다. 메인 v7 배경 20개와 토끼 시트 2개는 변경하지 않는다. 구형 배경을 가져와 빈 화면을 채우지 않는다.

## 4. 상점 제작 패키지

### 화면 구성

| 화면 | 필수 구성 | 함께 그려볼 상태 |
|---|---|---|
| 상점 목록 | 제목/뒤로, 검증된 코인 자리, 상품 카드 반복 영역, 구매 복원, 상세 진입 | 조회 중 / 판매 준비 중 / 판매 가능 / 보유 / 상품 없음 / 조회 실패 |
| 상품 상세 | 상품 그림, 이름, 전체 구성품, 적용 범위, 실제 가격 자리, 조건 안내, 닫기/구매 | 가격 미조회 / 구매 가능 / 이미 보유 / 구매 불가 사유 |
| 구매 확인·처리 | 선택 상품/전체 비용/적용 대상, 취소/확정, 처리 상태 | 확정 전 / 처리 중 / 실제 승인 / 최종 거절 / 결과 미확인 |
| 구매 복원 | 안내, 진행 표시, 실제 복원 결과 목록 | 진행 중 / 복원 항목 없음 / 복원 완료 / 오류 |

목록은 우선 기존 **성장 완료 팩·이모티콘 번들** 2종을 담을 수 있게 만든다. 상품 수가 늘어도 같은 카드 템플릿을 재사용한다. 카테고리 탭은 확정된 상품군이 늘어날 때 적용하며 빈 탭을 필수로 만들지 않는다.

성장 완료 팩은 **계정 공통 3트랙만 대상**이다. 동물 해금·동물 액티브/패시브가 포함된 것처럼 동물 초상을 상품 그림에 넣지 않는다. 코인 교환/유료 이모티콘의 실제 종류와 가격은 미설정이다. 할인율, 기간 한정, 추천 순위, 품절 수량, 젬/보석 판매를 임의로 추가하지 않는다.

## 5. 설정·조작·계정 제작 패키지

### 화면 구성

설정 첫 화면은 상단 제목·뒤로, 중앙 세로 목록, 하단 초기화로 구성한다. 항목이 늘면 목록만 스크롤하고 뒤로/핵심 버튼은 Safe Area 안에 둔다.

| 영역 | 디자인할 항목 | 현재 동작과 남은 연결 |
|---|---|---|
| 소리 | BGM/SFX 각각 아이콘·슬라이더·음소거·값 자리 | 현재 SC13은 요약 문구다. 실제 볼륨 적용/저장 바인딩 필요 |
| 조작 설정 | 크기·위치·투명도·좌우손 배치·전용 하향 버튼, 조작 미리보기 | SC19의 기존 preferences를 재사용. 자유 드래그 편집기는 현재 기능으로 가정하지 않음 |
| 접근성 | 큰 글씨, 진동, 한국어/English 선택 | 기존 설정 코드 존재. 언어 선택 저장과 모든 문구의 번역 완료는 별개 |
| 계정·저장 | 계정 상태와 하위 화면 진입 | SC20 화면은 있으나 현재 Portrait 로비의 노출 동선 보강 필요. 설정에서 연결하는 안을 제안 |
| 도움말·기록 | 기존 하위 화면으로 가는 메뉴 행 | 현재 로비에서 실제 노출되는 경로는 구현 시 재확인. 그림만 납품해 연결 완료로 보지 않음 |
| 초기화 | 대상/영향 설명, 취소/확인 | SC13의 기존 초기화는 토스트만 표시. SC19의 ControlReset은 실제 preferences 초기화. 범위를 구분해 연결 |

## 9. 외부 제작자 납품 요청

권장 패키지 이름: `ANIMOL_Utility_Store_Multiplayer_UI_v1`.

```text
ANIMOL_Utility_Store_Multiplayer_UI_v1/
  README_KO.md                  # 사용법, 완성/조건부/미제작 목록
  sprites/common/               # 신규 위젯
  sprites/store/                # 상품 프레임/그림/가격 바탕
  sprites/settings/             # 설정/계정 아이콘
  sprites/multiplayer/          # 유형/참가자/방 관련 부품
  sprites/emotes/               # 기존 무료 3종
  sprites/help/                 # 제안 도해
  backgrounds/                  # 선택 제작분만
  source/                       # 편집 가능한 원본, 레이어 유지
  previews/                     # 레이아웃 시안; 런타임 sprite 아님
  manifest.json                 # 파일별 규격/상태/용도/수입 설정
```

manifest의 각 파일에는 `id`, `path`, `size`, `pivot`, `borderLBRTop`, `imageType(Simple/Sliced)`, `states`, `screens`, `transparent`, `palette`, `safePadding`, `minDisplaySize`를 기록한다. 별도 atlas는 선택 사항이며 개별 PNG도 반드시 제공한다. Unity `.meta` GUID를 새로 만들어 기존 GUID와 섞는 방식은 피하고 프로젝트 담당자가 통합한다.

납품 전 확인:

- 상점 목록·상품 상세, 설정·조작 설정, 경쟁 허브·방 옵션·코드 참가·대기방 시안을 각각 제공한다.
- 1080×1920/1080×2400과 Safe Area, 긴 한글/영문, 목록/상세 스크롤, 고정 하단 버튼을 보여준다.
- 테스트 데이터는 시안 설명에 `예시`로 표시한다. 운영 ID·가격·방 번호·랭킹을 확정값처럼 전달하지 않는다.
- 대기방은 빈 슬롯·4인·8인, 준비 전/후, 끊김/재연결 상태를 보여준다. 서버 연결 확인 결과로 보고하지 않는다.
- 코드 입력은 키보드가 올라온 상태도 디자인한다. 코드 길이 확정 전에는 유연한 입력 영역을 유지한다.
- 로딩·실패·미설정·결과 미확인 시안에서도 뒤로/닫기/재확인 가능 여부를 명시한다.
- 기존 15종 초상/로비 배경/폰트와 새로 제작한 파일을 구분한다. 이미 있는 자산을 재제작 목록으로 청구하지 않는다.
- 전체 화면을 한 장의 PNG로 납품하지 않는다. 장식에 가려지는 텍스트, 클릭 영역을 가리는 그림, 사각 프레임에 잘린 초상을 만들지 않는다.
