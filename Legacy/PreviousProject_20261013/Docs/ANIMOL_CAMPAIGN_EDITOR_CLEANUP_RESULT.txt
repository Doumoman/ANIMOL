ANIMOL 캠페인 맵 편집기 정리 결과 (2026-10-06)

사용 방법
- ANIMOL > Campaign Maps (Ctrl+Shift+M)에서 캠페인 스테이지를 선택한다.
- 연결된 맵은 [편집]으로 바로 V4 Scene 편집기에서 연다.
- 미연결 스테이지는 기존 정규 경로의 맵을 후보로 표시한다. [선택한 맵 연결]로 참조를 저장한다.
- 기존 맵이 다른 경로에 있어도 맵 원본 필드에서 연결할 수 있다. 스테이지/테마 불일치와 중복 연결은 거절한다.
- 맵이 전혀 없는 스테이지만 [빈 V4 맵 생성 및 연결]로 생성한다. 같은 ID의 기존 파일은 덮어쓰거나 복제하지 않는다.
- 맵 연결은 Ready, 보상, 사람의 플레이 검증 상태를 승격하지 않는다.
- Unity를 닫은 상태에서 Tools/OpenCampaignEditor.cmd를 실행하면 D3D11로 편집기를 연다.

구조 변경
- 구형 CampaignMapEditorWindow 본문을 작은 캠페인 탐색/연결 창으로 교체했다.
- 구형 TerrainStructures 패널, 별도 Saved Map Editor, 별도 preview 생성기, 구형 workspace 자동 갱신기를 삭제했다.
- StageMapAuthoringWorkspace에는 기존 호출/에셋 호환용 얇은 연결부만 남겼다. 기존 씬 변경/저장 및 update/selection 후크는 없다.
- 맵 저장 연결은 TerrainEditorAdapter가 소유한다. 캠페인 목록을 열거나 닫아도 편집기의 연결을 뺏지 않는다.
- 목록 렌더링 중 맵 Ready 판정/콘텐츠 해시 계산/정규 경로 탐색을 반복하지 않는다.
- V4 Scene 팔레트는 자유형 지형과 START/EXIT/방울/체크포인트 4종만 노출한다.
- 구형 덩어리/장애물 팔레트, V1~V3 아트 전환 UI와 105개 구형 부품/객체 목록의 썸네일 생성 경로를 Scene 편집기에서 제거했다.
- 단순 마우스 이동은 커서만 갱신한다. 실제 브러시 입력 때만 후보를 만들며 같은 셀의 중복 갱신을 생략한다.
- 맵 밖 및 한 번에 65,536셀을 넘는 드래그를 거절한다. 격자 선 개수에도 상한을 적용했다.
- 지형 카탈로그 JSON 파싱 결과와 맵 참조를 캐시한다. 객체 카탈로그는 필요할 때 불러온다.
- V4 지형/맵 설정의 변경 전 백업은 UserSettings/ANIMOL/MapBackups에 저장한다. AssetDatabase 임포트/전체 배치 갱신을 하지 않는다.
- 기존 Assets/ANIMOL/MapBackups 백업도 조회할 수 있다. 구형 객체 호환 API의 백업 경로는 보존했다.
- ANIMOL 메뉴는 Campaign Maps 1개, 현행 Main UI V7 3개, Portrait Preview 2개만 남는다.
- 미커밋 로컬 빌더의 소스를 건드리지 않기 위해 그 메뉴는 시작 시 등록 해제한다. 현행 테스트/호환 코드가 참조하는 빌더 메서드는 남아 있다.

크래시 근거와 실행 확인
- 작업 전 Editor.log의 실제 종료 스택은 NVIDIA nvwgf2umx -> Unity D3D12DeviceState::ClearRenderTargets다.
- 직전에는 m_CmdState == kEmpty 네이티브 assertion이 반복됐다. 데이터 충돌만으로 원인을 단정할 근거는 없다.
- 프로젝트 Graphics/Player 설정을 수정하지 않고 D3D11 실행기를 추가했다.
- 실제 GUI Editor에서 Direct3D11을 확인했다. T01-S01 첫 열기 443ms, 이후 캠페인 파일 8개 전환 3~24ms였다.
- 8개 모두 열렸고 파일 내용은 불변이었다. 마지막 Console 오류 0개이며 T01-S01 편집기와 캠페인 목록을 열어두었다.
- 이 수치는 해당 세션의 관측값이다. 모든 그래픽 환경/장시간 작업의 크래시가 해결됐다는 보장은 아니다.

검증
- Unity 6000.3.8f1 / Direct3D11.
- 관련 EditMode 70개: 첫 실행 66 통과, 구형 비공개 preview 함수에 의존한 4개 실패.
  해당 테스트를 현재 CopySprites 경로로 갱신하고 새 연결 테스트와 함께 재실행: 13/13 통과.
- 마지막 브러시 후보 초기화 수정 후 CampaignMapAccessTests 10/10 재통과. 연속 새 스트로크의 임시 데이터 격리 회귀 테스트 포함.
- PlayMode 7/7 통과: 자유형 20스타일 착지, 단방향 발판, 기존 구조물 충돌/빈 공간.
- CommercialPolishPolicyTests 포함. 각 테스트의 최종 결과 78/78 통과 (EditMode 71 + PlayMode 7).
- 초기 -nographics 실행은 기존 Camera.Render 이미지 비교 테스트에서 네이티브 크래시가 났다.
  이후 넓은 구버전 아트 검증 2회는 완료 전 중단하고 변경과 관련된 검증으로 범위를 좁혔다.
- 상세 결과: Docs/Validation/CampaignEditorCleanup.json.

보존 범위 / 남은 작업
- 기존 미커밋 파일은 작업 시작 시 내용 그대로 보존하고 이번 커밋에서 제외했다.
- 기존 캠페인 맵의 배치와 참조 중인 장애물/덩어리/구버전 아트 에셋을 실제 삭제하거나 일괄 변환하지 않았다.
  편집기 팔레트와 구형 진입점에서 제거한 범위다. 기존 배치 삭제 여부에 대한 비동기 질문에는 작업 중 답변이 없었다.
- 따라서 기존 맵에는 이전 지형/장애물이 그대로 보일 수 있으며 런타임 호환 리더도 유지된다.
- 신규 맵과 자유형 브러시 저장은 V4를 사용한다. 기존 에셋의 물리 삭제는 배치 변환/삭제 범위 확정 후 참조 정리가 필요하다.
