# ANIMOL · 55문항 결정 기록과 Unity UI 후속작업 명령 v1.1

작성일: 2026-09-28  
추가 결정 반영: 2026-09-28 — 경쟁전 동물 중복 허용, 캠페인 결과 광고는 기본 코인만 2배, 일반 광고와 결과 광고 합산 일 3회.  
적용 순서: 이번 사용자 답변·추가 설명 → 이 문서 → `ANIMOL_UNITY_CLI_UI_CORE_IMPLEMENTATION_ORDER_v1.0.md` → 이전 기획안.  
근거 자료: 사용자가 제공한 `ANIMOL_UI_IMPLEMENTATION_STATUS.md`(M0~M5 완료 보고).  
범위: 디자인 결정과 다음 구현 작업. 이 문서 자체가 Unity 프로젝트의 변경 완료 증거는 아니다.

## 0. 이미 확정된 변경 불가 조건

- 게임명은 **ANIMOL**. 모바일 가로 화면, UI 기준 1920×1080, 가로로 더 넓으면 높이를 유지하며 가로 영역을 적절히 확장하고 Safe Area를 적용한다. 실제 기기의 물리 해상도가 1920×1080보다 작을 때는 비례 축소한다.
- 원본 픽셀아트 타일은 16×16px. 현재 아트는 대략적인 임시 표현이며 실제 에셋은 나중에 교체한다.
- 캠페인은 5개 테마 × 테마당 20개 스테이지, 총 100개. 각 스테이지는 플레이 맵 하나이며 **캠페인의 사용 동물은 스테이지가 고정**한다. 캠페인 입장 전에 동물 선택 화면을 만들지 않는다. 경쟁·협동에서만 출전 동물을 선택한다.
- 해당 맵에서 방울 세 개를 획득한 후 출구가 열리며, **실제로 출구에 도착해야** 완료된다.

## 1. 사용자 답변 55개: 번호와 구현 의미

선택지의 원래 문항을 기준으로 옮겼다. 사용자의 추가 문장은 같은 번호의 A/B/C보다 구체적인 최종 지시다. 숫자·효과·가격·서버 정책을 임의로 채우지 않는다.

## 2. 첨부 완료 보고서로 확인한 현재 구현 상태

## 3. Unity CLI / MCP 후속 구현 명령

다음 블록을 **Unity 프로젝트 루트에서 작업하는 에이전트**에게 전달한다. 기존 M0~M5를 재생성하지 말고 현재 프로젝트와 완료 보고서를 비교해 **차이만 구현**한다.

> 게임 이름은 ANIMOL로 유지하라. `ANIMOL_55문항_확정사항과_UI_후속작업_명령_v1.1.md`를 최신 제품 결정으로 읽고, 프로젝트 루트의 `ANIMOL_UNITY_CLI_UI_CORE_IMPLEMENTATION_ORDER_v1.0.md` 및 `ANIMOL_UI_IMPLEMENTATION_STATUS.md`를 함께 확인하라. 기존 M0~M5 결과를 다시 만들거나 임의로 완료 처리하지 말고, 아래 Δ1~Δ5를 실제 C# 코드·UI 프리팹·데이터 정의·검증으로 반영하라. Unity 에디터에서 컴파일하고 영향받는 화면을 PlayMode와 16:9/20:9 Game View에서 확인하며, 각 항목에 구현 상태와 증거 경로를 남겨라. 운영 콘텐츠·SDK·서버·경제 수치가 없으면 차단 상태와 UI를 정확히 표시하고 가짜 지급/로그인/매치를 하지 말라.

### Δ1 — 캠페인과 결과

1. 순차 해금과 스테이지별 고정 동물을 유지하고, 타이머 만료 실패·체크포인트 복귀·동일 배치 재도전·최고 시간 갱신을 서로 다른 상태로 구현한다. 스테이지의 제한시간/빠른 클리어 기준·추가 보상·부가 목표는 버전 있는 데이터로 정의하되 미정 숫자를 임의로 채우지 않는다.
2. 미발견 방울은 지도/HUD/가장자리 화살표에서도 숨긴다. 발견 규칙을 콘텐츠에 둔다. 기본 방울 획득은 실제 물리 접촉이고, 세 개 후 출구 접촉만 성공이다.
3. 결과 화면에는 성공/시간초과/최고 기록, 최초·재클리어 구분, 기본·시간·선택 목표·광고 추가 보상의 분해 표시와 승인 대기를 추가한다. 테마 20번째에는 이야기/연출 슬롯을 제공하되 미작성 콘텐츠를 실제 스토리로 표시하지 않는다.
4. 초기 캠페인 맵의 지형·동선이 이동→점프→방울→출구→변신/특수 동작을 점진적으로 가르치도록 콘텐츠 제작 규칙을 작성한다. 실제 맵이 없을 때는 튜토리얼 구현/검증을 완료로 기록하지 않는다.

### Δ2 — 매치 룸·멀티 HUD·서버 계약

1. 경쟁 룸 4~8인, 협동 룸 2~4인 가변 렌더링. 경쟁 3개 맵 연속 경기, 맵별 결과/누적 결과, 방울 선점·재생성 카운트다운, 선두 완주 뒤 남은 시간, 서버 점수·미완주·재접속 상태를 읽는다. 협동은 팀 방울 3개와 `탈출한 팀원 x/n`을 동시에 표시한다.
2. 멀티 전용 지상·공중·특수 각 1마리 로드아웃과 캠페인 진행 기반 동물 해금을 구현한다. **경쟁전의 참가자 간 동물 중복은 허용**하며 중복을 이유로 Ready를 거절하지 않는다. 협동전은 기존 중복 금지 규칙을 모드별 룰 데이터로 유지한다. 양쪽 모두 잠긴 동물 선택은 거절한다.
3. 랭크는 계정·동물 성장 최대 프리셋, 일반/협동은 실제 보유 레벨을 적용한다. 두 경우 모두 서버 승인 스냅샷을 표시. 20:9 랭크에서도 월드 가시 영역이 넓어진다는 최신 정책에 맞춰 구형 16:9 중앙 마스크를 제거하고 카메라·공정성 검사를 다시 실시한다.
4. 협동의 위치 핑과 이모티콘은 명시적인 터치 영역·발송 실패/쿨다운 상태를 가진다. 서버 없이는 미리보기와 운영 기능을 분리한다.

### Δ3 — 성장·로그인·상점·광고

1. 계정 성장 수치는 플레이 검증 전까지 **초안**으로 표기. 동물별 두 트랙·Lv.5·숙련도/공유 코인·캠페인 해금 상태 UI/데이터 계약을 추가한다. 효과/가격/숙련도 획득량을 창작하지 말고 정의 미설정이면 구매 불가를 유지한다.
2. 게스트 시작→Google 계정 연결→온라인/구매 게이트를 표시하고, 오프라인 캠페인 기록과 온라인 확정 코인 잔액을 구분한다. 로컬/클라우드 기록 선택 화면에는 어느 쪽이 남는지 요약한다. 인증 기술·서버가 없으면 연결 성공을 가장하지 않는다.
3. 팩 상세에서 계정 공통 3트랙만을 구성으로 표기하고, 이미 쓴 코인의 코스메틱 교환 재화 전환 정책 미확정 상태에서는 팩 구매를 활성화하지 않는다. 무료/코인/유료 이모티콘 획득 경로를 서로 구분한다.
4. 로비의 일반 선택 광고와 캠페인 클리어의 기본 코인 2배 광고를 **서로 다른 제안/지급 타입**으로 모델링하되, **하나의 계정별 일일 3회 한도**를 공유한다. 결과 코인이 `기본 코인 B + 시간 보너스 T + 부가 목표 보너스 O`일 때, 광고를 승인받은 동일 클리어 결과의 총액은 `2B + T + O`다. 결과 ID와 광고 증명 ID로 중복 지급을 막는다. 성공적으로 검증·확정된 지급만 1회로 세고 실패·취소에는 횟수를 차감하지 않는다. 실제 광고 SDK/원장이 없으면 잔액이나 사용 횟수를 성공 처리하지 않는다. UI의 남은 횟수·초기화 시각은 서버가 돌려준 값으로 표시한다.

### Δ4 — 조작·HUD·가로 화면·접근성

1. 좌우 스와이프 이동, 별도 점프·특수 동작 버튼, 좌하단 동물 아이콘 직접 전환, 우하단 능력 버튼을 구성하고 터치 ID별 입력을 분리한다. 버튼 이동/크기/투명도 설정을 적용할 때 Safe Area 및 겹침 회피 범위를 검증한다.
2. 좌상단 스테미나와 인접 동물 초상화, 상시 표시되는 시간·방울·능력 상태 및 가장자리 안내를 확인한다. 시간 위치는 사용자의 시각 기준에 맞출 수 있는 앵커로 두고 근거 없는 수치 좌표를 고정하지 않는다.
3. 전 모드에서 가로 폭이 늘어나면 월드 시야도 확장하도록 카메라와 HUD를 검사한다. 기존 랭크 공통 16:9 마스크는 최신 결정을 따른다. 1920×1080, 2400×1080, Safe Area 및 더 작은 물리 해상도에서 레이아웃/터치 확인. 실기기 결과는 실제 기기 검증 후에만 Pass라고 기록한다.
4. 한국어/영어 표시, 글자 크기, 색 외 상태 구분, 진동 조절, 캠페인·경쟁·협동 큰 로비 카드와 하단 성장/상점 메뉴를 반영한다. 필수 튜토리얼 팝업은 자동 시작하지 않는다.

### Δ5 — 검증·상태 문서

- 의미 있는 검사만 추가한다: 캠페인 시간초과와 체크포인트/동일 배치, 미발견 방울 누설, 경쟁 4/8명·3연속 맵·방울 선점 재생성, 협동 2/4명 전원 도착, 동물 3슬롯·잠금/중복 정책, 게스트/로그인 게이트·저장 선택, 광고 결과의 단 한 번 지급과 지급 실패, 좌우 스와이프+점프+특수+변신 동시 터치, 16:9/20:9 HUD.
- `ANIMOL_UI_IMPLEMENTATION_STATUS.md`에 **기존 M0~M5 기록을 보존**하고 별도의 `v1.1 결정 반영` 표를 만들어 Δ1~Δ5 각각 `Implemented`/`DevOnly`/`Unconfigured`/`Blocked`, 실제 변경 파일, 테스트 명령/결과, 캡처 경로를 기록한다. UI만 있는 온라인 기능을 운영 실매치 완료로 쓰지 않는다.
- 위 구현이 끝나면 핵심 잔여 차단 항목과 실제 콘텐츠/백엔드 요구를 정리하여 보고한다.
