## 검사 방식

전체 HTML 스크립트를 Node VM에서 실행하고 @napi-rs/canvas로 실제 그림을 그렸다. 조작 콜백과 고정 스텝 물리를 실행했다. 최종 경로 검증은 좌표·방울 상태를 강제로 바꾸지 않고 입력만 제공했다. 경로와 이벤트를 player_route_inputs.json과 player_audit.json에 기록했다.
바닥·경계의 C02/C03은 지형 위의 빈 셀에 놓았다. C02는 SIDE로 body/cap에 참여하지 않으며 C03은 TOP/ReplaceCap이다. C03 물리 윗면은 눈에 보이는 28px 발사판 범위를 사용한다. 기존 v2의 전체 셀 몸체 때문에 생기던 C02 접합 배치 경고는 이번 표준 예시에서 없어졌다. 의도적으로 작동 면을 막은 입력은 단위 테스트에서 여전히 검출된다.
고정 Unity QA용 initial/collapsed 그래픽 rect와 프레임 파일 경로도 같은 선택기로 생성했다. 이 표는 C05 한 개가 있는 테스트 씬 전용이며 운영 맵의 정본·접합기를 대체하지 않는다.

## 육안 확인

공통 45개 비교판, 옆스프링의 최근접 8배 접합, 전체 테스트 맵, 실제 클리어 화면을 열어 확인했다. 옆스프링 위에 덮개가 없고 상향 코일 전체가 바닥 위에 보인다. 기존 단색 떡·얼음·컨베이어·4조각 소멸판을 유지했다.
자동 후보 0개는 모든 곡선의 Jaggies·모든 색의 Doubles를 완벽하게 판정했다는 뜻이 아니다. 393개 프레임과 모든 스타일 조합을 사람이 한 장씩 승인한 결과도 아니다.

## 미실행 범위

ANIMOL Unity 저장소·C# 컴파일러·Unity Editor는 이 환경에서 사용할 수 없다. 순수 C# 선택기, UnityCrumbleVfx, 임시 플레이어 코드 7개, Editor 씬 생성기, NUnit 8개를 실제 Unity에서 컴파일·실행하지 않았다. 생성된 .unity 씬은 아직 없으며 MCP가 제공 생성기로 만들고 실제 물리 경로를 검사해야 한다.
현재 운영 플레이어 오류 원인은 실제 소스를 읽지 못해 확정하지 않았다. 그 진단과 적용은 MCP 명령에 구체적으로 포함했다. 운영 맵 마이그레이션·C09 삭제·C04 위험 owner·C05 이벤트 연결·Scene/Runtime·Undo·모바일 UI도 실제 프로젝트에서 확인해야 한다.
Chromium 실행 파일이 없어 실제 브라우저 레이아웃·다운로드 검사는 미실행이다. Native Canvas 실행을 브라우저 전체 검증이나 Unity 물리 검증으로 설명하지 않는다.
C05의 점진적 alpha 페이드는 요청한 런타임 연출이다. PNG 자산은 alpha 0/255를 유지하며 GIF의 불투명 비교판은 Sweetie16을 그대로 유지한다.
