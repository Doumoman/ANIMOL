현재 Unity 프로젝트의 AGENTS.md와 잔영 극장 M06 생성/카탈로그/렌더러/레일 배치 코드를 읽고 레일 카트 V01 수정 R2를 적용하라.

사용자 의도: 바퀴를 별도 자산으로 나누지 않는다. 바퀴까지 포함된 카트 한 장이 레일에 맞게 보이도록 한다.
이번 패키지는 아트와 표시 보조 소스다. 새 이동/밀침/복귀 게임 로직을 구현했다고 보고하지 않는다.

1. 기존 ANIMOL_ECHO_THEATER_RAIL_CART_V01 경로에 R2 파일을 교체한다.
   기존 파일의 .meta와 이미 생성된 카탈로그/클립의 GUID를 유지한다. 다른 V03 전체 폴더를 덮어쓰지 않는다.
   별도 복제 폴더에 같은 네임스페이스의 .cs를 중복 설치하지 않는다.
2. animation_catalog.json의 installationRevision=2, Sprite16개, Clip12개인지 확인한다.
   카트8개는 소품·차체·바퀴를 합친 PNG다. 카트당 SpriteRenderer 하나만 사용한다.
   바퀴 전용 SpriteRenderer/자식 오브젝트/리그를 새로 만들지 않는다.
3. PPU256, FullRect, Bilinear, 무압축, Mipmap Off, NPOT None을 적용한다.
   카트448×448, Pivot(.5,192/448). 레일 타일320×320, Pivot(.5,.5).
   재질512×64/받침320×96을 포함한 각 크기와 Pivot은 JSON을 따른다. 전체를 중앙 Pivot으로 덮어쓰지 않는다.
   rail/material은 Repeat, 나머지는 Clamp. rail/material은 SpriteAtlas 패킹에서 제외한다.
4. 컴파일 후 Tools > ANIMOL > Echo Rail Cart V01 > Build art catalog and clips에서 이번 animation_catalog.json을 고른다.
   _GeneratedRailCartV01/EchoRailCartCatalog.asset과12개 .anim을 생성 또는 갱신한다.
   JSON을 복사한 것만으로 생성 완료라고 보고하지 않는다.

선택적 CLI:
"<Unity Editor>" -batchmode -quit -projectPath "<project>" -executeMethod ANIMOL.Art.EchoRailCartV01.EchoRailCartBuilderV01.BuildFromCommandLine -echoRailCartCatalog "Assets/<path>/ANIMOL_ECHO_THEATER_RAIL_CART_V01/animation_catalog.json" -logFile "<log>"

5. 실제 M06 장치 등록 ID, 프리팹, 팩토리, 풀, 저장 로드를 확인한다. 새 공식 ID를 임의 부여하지 않는다.
   V03 전체 카탈로그의 고정 SHA 빌더에 이번 JSON을 넣지 않는다. 이번 빌더/카탈로그를 사용한다.
6. 전용 시각 자식에 EchoRailCartVisualV01을 연결하고 Configure(catalog, out error) 후 표시한다.
   ShowCart(heading, contact)를 쓴다. heading은 호스트가 확정한 north/east/south/west다.
   모서리에서 실제 진행방향이 바뀌면 새 진행방향의 카트로 전환한다.
   카트/Collider 전체를90도 회전시키지 않는다. Animator와 표시 컴포넌트가 같은 Renderer를 동시에 쓰지 않게 한다.
7. 카트의 논리 점유는1×1 기준이다. 기존2×1 무대를 그림만 보고 비균일 확대하지 않는다.
   1칸은256px/PPU256=1유닛이다. 프로젝트 cellSize가 다르면 카트 전체를 균일한 cellSize 배율로 맞춘다.
   448px PNG 전체 폭이나320px 레일 PNG 전체 폭으로 이웃 셀 간격을 잡지 않는다.
8. 레일 표시를 아래 두 방식 중 실제 프로젝트에 맞게 연결한다. 같은 경로를 중복으로 그리지 않는다.
   A) 기존 Tilemap: rail/ew, ns, ne, es, sw, wn을 rail_topology.json에 맞춰 논리 셀 간격으로 배치한다.
      두 선의 폭과 연결 위치가 일치한다. 직선 받침64px, 모서리 받침 약67.02px의 로컬 간격이다.
   B) 전체 경로 등간격: 바닥 전용 EchoRailTrackViewV02.Configure(catalog, orderedCells, closed, cellSize, out error)를 쓴다.
      orderedCells는 경로 순서의 상하좌우 인접 셀이다. 닫힌 루프의 첫 셀은 마지막에 중복하지 않는다.
      Examples/R2_CLOSED_LOOP.json을 참고한다. 실제 경로를 그대로 전달하고 오류를 확인한다.
      경로 전체 누적 길이로 받침을 배치해 마지막 연결부까지 간격을 맞춘다. 닫힌 루프는 약64px에서 균등 보정한다.
      이 컴포넌트는 레일 바닥만 만든다. 카트·바퀴·점유·충돌·턴을 제어하지 않는다.
      transform을 실제 보드 좌표계에 맞추고 sorting layer/order를 바닥<레일<카트 순서로 설정한다.
9. 원래 cart/<heading>/idle,move,contact 키를 보존했다. move는 정적 한 프레임이며 호스트가 좌표를 이동시킨다.
   연속 곡선 조향 애니메이션은 없다. 이것만으로 연속 곡선 주행이 구현됐다고 보고하지 않는다.
   접촉 연출은 카탈로그의 contact 클립 또는 ApplyContactProgress를 사용한다.
10. 기존 빈 이동 무대 Sprite/애니메이션/풀 기본값이 새 카트를 다시 덮어쓰는 경로를 찾아 최신 적재 카트로 연결한다.
    로드/Undo/Reset/풀 재사용 시 확정 셀·연결 형태·진행방향·상태를 다시 표시한다.
11. 게임 판정은 RULES_KO.txt의 입력→플레이어 이동→카트 한 칸→밀침/입력 전 P0 복귀 의도를 따른다.
    이 프로젝트에 해당 코드가 없다면 미구현이라고 명시한다. 연출 콜백으로 턴/코스트/충돌을 발생시키지 않는다.
12. 실제 검사:16 Sprite/12 .anim, 카트당 Renderer 하나, 별도 바퀴 자원 없음,
    가로/세로의 바퀴 접촉, 직선과 네 모서리의 두 레일 선 연결, 받침의 연결부 간격,
    같은 셀 크기/균일 배율, 소품 적재 모습, 기존 빈 무대 fallback 없음,
    씬·에디터·풀·로드·Undo·Reset에서 최신 그림 적용을 확인한다.
13. 실제 적용한 경로와 검사 결과를 보고한다. Unity를 실행하지 않았다면 컴파일/임포트/플레이를 NOT_RUN으로 구분한다.

전달 패키지의 오프라인 자원·기하·압축 검수와 실제 Unity 검수는 별개다.
이 전달 환경에서 Unity 컴파일/임포트/플레이는 NOT_RUN이다.
