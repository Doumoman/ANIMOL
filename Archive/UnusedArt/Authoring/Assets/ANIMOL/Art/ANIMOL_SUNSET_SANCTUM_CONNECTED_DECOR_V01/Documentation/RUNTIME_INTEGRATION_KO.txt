ANIMOL 낙일 성소 연결 장식 V01 — 실제 API 연결 안내

범위와 실행 상태
이 소스는 낙일 성소(서사 후 표시명: 천구 날조국)의 연결 장식 6종과 통짜 장식 20종을 위한 시각 전용 애드온이다. 실제 게임의 이동/빛/회전/장치/콜라이더/턴 규칙을 변경하지 않는다. 기존 G=sanctum_floor, W=wood_bridge, S=stone_bridge 의미와 공유 다리 난간/섬 밑마감을 유지한다.
Unity 프로젝트 및 Unity/C# 실행기가 이 작업 환경에 없으므로 컴파일, 실제 임포트, Prefab 생성 실행, NUnit 실행, Play, 실게임 어댑터 연결은 모두 NOT_RUN이다. 동봉 PNG 참고도는 오프라인 합성 이미지다.

설치할 폴더
Assets 아래 한 경로에 ANIMOL_SUNSET_SANCTUM_CONNECTED_DECOR_V01 루트를 그대로 둔다. Runtime/, Editor/에는19개 중16개 운영 소스가 있다. Tests~/의3개 소스는 자동 임포트 대상이 아니며 실제 프로젝트의 테스트 어셈블리에 명시적으로 복사해야 한다. 원본 이미지/참고도는 런타임 Sprite allowlist에 포함되지 않는다. 기존 Theater/Ranch 애드온은 이 이름공간과 공존한다.

ANIMOL.Art.SanctumConnectedDecorV01

초기 검사 보드 실제 생성

현재 manifest.json, Examples/stage_snapshot.json, Examples/all26_snapshot.json과 프로젝트에 실제 존재하는 Sorting Layer를 선택한다. optional scene 체크는 기본 false다.
실제 명령 진입점:
ANIMOL.Art.SanctumConnectedDecorV01.SanctumConnectedDecorV01BoardTools.BuildExamplesFromCommandLine
필수 인수:
-sanctumDecorManifest Assets/.../ANIMOL_SUNSET_SANCTUM_CONNECTED_DECOR_V01/manifest.json
-sanctumDecorStageSnapshot Assets/.../ANIMOL_SUNSET_SANCTUM_CONNECTED_DECOR_V01/Examples/stage_snapshot.json
-sanctumDecorAllSnapshot Assets/.../ANIMOL_SUNSET_SANCTUM_CONNECTED_DECOR_V01/Examples/all26_snapshot.json
-sanctumDecorSortingLayer 실제_존재하는_장식_SortingLayer명
선택 인수: -sanctumDecorCreateScenes true
...은 실제 설치 경로로 치환한다. 프로젝트 실행기 경로/projectPath 등은 해당 Unity 버전에 맞게 제공한다. 이 텍스트가 Unity 실행을 대신하지 않는다.
생성되는 실제 자산:
_Generated/SanctumConnectedDecorV01Catalog.asset
_Generated/InspectionBoards/Stage/SanctumDecorStageBoard.asset
_Generated/InspectionBoards/Stage/SanctumDecorStage.prefab
_Generated/InspectionBoards/All26/SanctumDecorAll26Board.asset

선택 시 같은 이름의 .unity 검사 씬도 생성된다. 현재 열려 있는 제작 씬은 변경하거나 닫지 않는다. 열려 있는 Prefab Stage/재생 중/컴파일 중/열린 대상 검사 씬/더티한 기존 소유 결과가 있으면 먼저 명시적 진단으로 중단한다. 생성기 성공 보고서의 generated GUID/실제 SpriteRenderer 상태를 확인한 뒤 Play에서 따로 검증한다.

실게임에서 반드시 필요한 실제 호출 경로
1. 현재 게임의 맵 로드/편집/삭제/재시작/Undo/Redo가 완료된 뒤 현재 전체 장식 데이터를 새 BoardSnapshot으로 만든다. Inspector에 Catalog만 넣거나 Controller만 붙이는 것으로는 배치되지 않는다.
2. 장식 루트의 같은 GameObject에 SanctumConnectedDecorV01Controller와 SanctumConnectedDecorV01Binding을 둔다. 실제 소스로 SanctumConnectedDecorV01PublishedSnapshotSource를 명시적으로 연결한다.
3. PublishSnapshot(snapshot, out error)로 권위 있는 데이터의 깊은 복사를 게시한다. snapshot.isExampleOnly=false, isWholeBoard=true여야 한다. 실제 게임이 계산한 허용 셀을 allowedDecorCells에 정확한 논리층/높이와 함께 담는다. 예시 보드의 화이트리스트를 실게임 승인으로 재사용하지 않는다.
4. binding.Bind(controller, catalog, SanctumConnectedDecorV01BoardSnapshot.ArtManifestSha256, actualSortingLayerName, source, out error)를 호출한다. allowExampleSource는 기본 false다. 이 Binding이 실제 Controller.Configure와 Controller.SetLayout을 호출한다.
5. 후속 PublishSnapshot 성공은 Changed 이벤트로 전체 시각 계획을 갱신한다. Update/카메라 영역/매 프레임 랜덤에 의존하지 않는다. 필요한 경우 RefreshNow(out error)를 명시적으로 호출한다.
6. 소스 비활성화/풀 반환 시 게시된 권위 데이터는 폐기된다. 재사용할 때 호스트가 새 스냅샷을 Publish해야 한다. AuthoredSnapshotSource는 정적인 BoardAsset을 위한 별도 소스로서, AssignBoard(board,out error)와 NotifyBoardChanged(out error)를 사용한다.
7. 장식 루트와 부모의 회전은 identity, XY 스케일은 양수여야 한다. 반전/회전 계층은 오류로 처리한다. 루트/부모 위치 변경 뒤 명시적 RefreshNow는 위치를 재계산한다.

스냅샷 필수 필드(16개)
schemaVersion=1
packageId=ANIMOL_SUNSET_SANCTUM_CONNECTED_DECOR_V01
sourceManifestSha256=동봉 manifest_sha256.txt의 정확한 값(코드 ArtManifestSha256과 일치)
boardId=실제 보드 식별 문자열
revision=0 이상 Int64 정수
isWholeBoard=true
isExampleOnly=실게임 false / 검사 예시 true
originX, originY, originZ=cell(0,0)의 왼쪽 아래 세계 좌표
cellSize=양수
seed=결정적 배치 시드
postSpacing=3 또는4
networkCells=[{x,y,logicalLayer,heightKey,sortingOrder,worldZ,family,connectionGroup},...]
groupPlacements=[{placementId,groupKey,anchorX,anchorY,logicalLayer,heightKey,sortingOrder,worldZ},...]
allowedDecorCells=[{x,y,logicalLayer,heightKey},...]
배열 세 개는 누락/null 금지다. 명시적 []는 정상적인 전체 비우기다. 허용 셀은 중복 없이 정확한 plane으로 제공한다. JSON에서 2차원/jagged 배열은 사용하지 않는다. 누락·중복·알 수 없는 필드, 잘못된 숫자 타입/범위는 엄격하게 거부한다.

좌표와 점유
+Y=N, +X=E. 연결 비트N1/E2/S4/W8. 동일 family+connectionGroup+logicalLayer+heightKey인 상하좌우 이웃만 연결한다. 같은 연속 구조에는 공통 connectionGroup을 쓰고 각 타일에 고유 그룹을 만들지 않는다.
group anchorX/Y는 전체 점유의 왼쪽 아래 셀이다. 3×2 제단은 한 placement/한 renderer, 총6셀을 승인받는다. 한 셀이라도 거부되거나 중복 점유하면 전체 교체 계획이 거부된다. 그림의 alpha bbox/캔버스 크기로 점유를 추측하거나 스프라이트를1칸에 맞춰 줄이지 않는다.
행이 아래로 증가하는 호스트에서는 Planner.FromRowDownCell(column,row)와 FromRowDownGroupBottomLeft(leftColumn,topRow,heightCells)를 사용한다. 보드 왼쪽 위 세계 위치는 Controller.RowDownTopLeftToWorldOrigin(boardTopLeft,cellSize)로 변환한다.
원본 PPU256/논리 바닥 중심 pivot을 유지한다. 각 sprite node의 세계 셀 스케일은 cellSize로 통일된다. 더 큰 장식에 footprint로 추가 나누기를 하지 않는다.
선택적 보강 기둥은 첫 두 난간류의 긴 직선에서만 시드와 세계 좌표를 기준으로3/4칸 간격을 정한다. 2·3·4칸의 짧은 구조나 모서리/T/십자에 반복 기둥을 붙이지 않는다.

실제 프로젝트 검증 후 기록할 항목
컴파일 결과, 예시 자산/Prefab/선택 씬의 실제 GUID, 임포트 PPU/pivot/FullRect/무압축/필터 설정, 장식 생성/삭제/연결/모서리/T/십자, 2·3·4칸과 긴 직선 기둥, 모든 크기 전체 점유 거부, 풀 재사용 최신 상태, 맵 로드/리셋/Undo/Redo 실제 호출, 26종 전체 보드 Play 확인, 기존 장치/광학/이동/다리/섬 마감 회귀 결과를 적는다.
레거시 정리는 실제 장식 생성 경로와 참조를 찾아 최신 Catalog allowlist로 전환한 뒤 범위 내 오래된 장식 renderer만 제거한다. 다른 테마나 기능 장치/원본 전체를 이름 패턴으로 일괄 삭제하지 않는다. 실제 프로젝트의 결과 없이 전체 레거시 제거 완료/실게임 적용 완료라고 기록하지 않는다.
