ANIMOL 별길 목장 V13 R4 — 병아리 둥지 귀환 애니메이션

1. 표현 목표
- 기존 빈 둥지의 흔들림/완료 표시만으로 끝나던 부분에 병아리가 직접 들어가 앉는 모습을 추가한다.
- 기존 병아리의 노란 몸/크림색 날개/주황 부리와 발/짙은 남색 외곽선을 유지한다.
- 남·동·북·서 네 방향은 별도 원화다. 뒷모습에 눈이나 부리를 그리지 않으며, 옆모습은 반대쪽 눈을 보이지 않는다.
- 실제 접근 경로 재생 → 도착 → 짧게 움츠림 → 폴짝 뛰기 → 부드러운 착지 → 날개를 접고 앉기 → 귀환 완료 표시 순서다.
- 도착 후 동작은 서로 다른6포즈를 8타임프레임으로 배치해 10fps/0.8초로 재생한다.
- 둥지 본체는 고정된다. 병아리의 몸 아래/발은 둥지 앞쪽 볏짚에 가려져 안에 들어갔다는 깊이감을 준다.
- 귀환 완료 후에는 병아리가 둥지 안에 앉아 있는 마지막 모습과 기존 계열의 작은 완료 표시를 유지한다.
- 눈이 보이는 방향은 마지막에 눈을 편안하게 감는다. 북쪽은 같은 뒷모습으로 앉는다.

2. 게임 판정과 연출 연결
- 귀환 조건/귀환 가능 둥지/수용 수/귀환한 병아리의 논리 상태는 원 프로젝트의 기존 판정이 소유한다.
- 귀환 성공을 한 번 확정한 뒤, 실제 경로를 따라오는 임시 시각과 도착 연출을 재생한다.
- 귀환 판정이 실패하거나 병아리가 도착하지 않았다면 성공 애니메이션을 먼저 재생하지 않는다.
- 게임플레이의 병아리를 추종 목록에서 분리하는 등 기존 귀환 결과는 논리 트랜잭션에서 처리한다.
- 애니메이션 완료에서 귀환 수/보상/코스트/장치 턴을 다시 변경하지 않는다. 별도 입력도 요구하지 않는다.
- 연출 자체의 추가 코스트/장치 턴은0이다. 최초 이동/바람 행동의 회계는 기존 게임 규칙을 따른다.
- 새로운 둥지 수용 규칙, 자동 귀환 경로, 방울/출구/보상 규칙을 추가하는 패치가 아니다.
- 수문 통과 후 정지/재추종/추가 침수 객체의 미확정 부분도 이 표현 수정으로 확정하지 않는다.

3. 표시 모드
- 권장: nest_return/<direction>/arrive 하나에 병아리와 둥지를 함께 표시하고, 끝나면 occupied로 전환한다.
- 이 모드에서는 도착한 병아리의 원래 렌더러/접근용 임시 렌더러를 숨겨 중복 병아리를 막는다.
- 기존 둥지 렌더러도 같은 합성 렌더러를 사용하거나 숨긴다. 빈 둥지와 합성 둥지를 겹쳐 그리지 않는다.
- chick_return/<direction>/hop은 분리 렌더링이 필요한 프로젝트용 병아리 단독 클립이다.
  권장 합성 모드와 동시에 병아리 단독 클립을 추가로 재생하지 않는다.
- nest/arrive 및 nest/settled는 정면(south) 귀환/앉기 클립의 호환 별칭이다. 신규 연결은 방향이 명시된 키를 사용한다.
- 접근 방향은 실제 경로의 마지막 유효 이동 벡터로 정한다. +Y=북쪽이며 배열 행 방향은 어댑터에서 변환한다.
- 귀환 상태를 로드했을 때는 도착 연출을 다시 보여 주지 않고 occupied 정지 상태를 즉시 적용한다.

4. 연결용 소스
- Runtime/RanchChickNestReturnVisualR4.cs를 둥지의 표현 소유자에 붙인다.
- 전용 자식 RanchDeviceVisualV13 하나를 Configure(catalog, child, out error)로 연결한다.
- 초기/로드/Undo/Reset/풀 재사용 시 SetResolvedState(occupied, settledDirection, out error)를 적용한다.
- 귀환 성공 후 접근 시각이 실제 둥지에 도착하면 PlayCommittedArrival(transactionId, arrivalDirection, out error)를 호출한다.
- transactionId는 스테이지/리셋 세대가 포함된 원 프로젝트의 고유 성공 이벤트 식별자다. 매 Update에서 새 ID를 만들지 않는다.
- 동일 이벤트의 중복 호출은 재시작 없이 성공한 no-op으로 처리한다. 다른 이벤트로 재생 중이면 false/진단을 반환해 호스트가 대기시킨다.
- ClearPresentation/비활성화는 표시만 취소한다. 게임의 귀환 결과를 취소하거나 병아리를 되살리지 않는다.
- 복원 후 권한 있는 실제 상태로 SetResolvedState를 다시 호출한다. 이 함수는 복원 시점에만 호출하고 매 프레임 호출하지 않는다.
- 표현기가 처리하는 중복 방지는 시각 중복 방지이며 보상 중복 방지의 권한 있는 게임 판정을 대신하지 않는다.

5. 파일 구성과 이전 버전
- R4 전체: PNG373개/클립170개. R3의 PNG325개는 모두 동일 바이트로 보존했다.
- 새 원화4장, 병아리 단독24 PNG, 둥지 합성24 PNG, 새12클립이 추가된다.
- PNG320×320, PPU256, Pivot(.5,.5), FullRect, Bilinear, 무압축, Mipmap Off다.
- 작은 CHICK_NEST_RETURN_R4_PATCH.zip은 기존 V13 R3 위에 병합하는 차이 파일이다. 단독 설치본이 아니다.
- PATCH_R3_TO_R4.json에 요구되는 R3 카탈로그 해시와 목표 R4 해시/파일 목록을 포함한다.
- 전체 V13 ZIP에는 R3 수문과 R2 양 수정까지 포함된다. 새 설치는 전체본, 기존 R3는 추가 패치를 사용한다.
- 원화·최종 프롬프트는 Authoring~/native 및 generation_prompts_r4.json, 등록값은 R4_CHICK_REGISTRATION.json이다.
  원화는 built-in imagegen으로 만들었으며 같은 둥지/앞 테두리와 합성했다.

6. 검증 범위
- 네 방향 PNG 디코드, 클립 연결, 마지막 arrive 프레임과 occupied 일치, 둥지 앞 테두리 고정, 압축/추출 무결성을 확인한다.
- 기존 장치 EditMode 검사31개 원본은 유지한다. 이 환경에서는 NUnit을 실행하지 않았다.
- 새 귀환의 중복 이벤트, 복원, 실제 접근 경로/추종 해제, 카메라 가림은 실제 프로젝트 적용 후 검증해야 한다.
- Unity C# 컴파일/NUnit/호스트 연결/플레이 검증은 NOT_RUN이다. 미리보기는 오프라인 스프라이트 재생이다.
