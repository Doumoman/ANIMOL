R4: 병아리 귀환 표현이 추가되었다. 실제 게임 판정은 기존 R3/원 프로젝트가 소유한다.

ANIMOL 별길 목장 장치 V13 R4 — 연결 수로 / 가로·세로 물 이동

이번 문서가 기존 수문 표현 설명보다 우선한다. 양의 R2 규칙은 유지한다.

1. 물이 이동하는 방식
- 두 개의 이웃 칸은 한 쌍이다. 한 칸은 물웅덩이, 다른 칸은 통행 가능한 마른 구덩이다.
- 두 칸의 경계에 낮은 흙 수로와 작은 목재 개폐 수문이 보인다. 별도의 레버나 조작 칸은 없다.
- 마른 구덩이에 선 플레이어가 짝 물웅덩이 쪽으로 입력하면 한 수를 판정한다.
- 물은 행동 전 물웅덩이에서 행동 전 마른 구덩이로 빠져나간다.
- 플레이어는 반대 방향으로 이동해, 물이 빠져 마른 구덩이가 된 칸에 도착한다.
- 출발 칸에 물이 차는 것, 도착 칸에서 물이 빠지는 것, 플레이어 이동을 한 번에 확정한다.
- 물의 출발지와 도착지를 플레이어 경로로 추정하지 않는다. result.waterRoute=[행동 전 Wet, 행동 전 Dry]다.
- 플레이어 경로 result.actualRoute=[행동 전 Dry, 행동 전 Wet]와 정확히 반대다.
- 원래부터 마른 두 칸 사이로 자유롭게 물을 보내거나 주변 물 전체를 토글하는 장치는 아니다.

2. 가로형과 세로형
- 가로형은 2×1: 서쪽/동쪽 한 칸씩. 물은 동→서 또는 서→동 모두 가능하다.
- 세로형은 1×2: 남쪽/북쪽 한 칸씩. 물은 북→남 또는 남→북 모두 가능하다.
- 위/아래는 게임 보드의 북/남을 뜻한다. 커널과 시각 키는 +Y=북쪽을 사용한다.
- 세로형은 별도 원화다. 가로 SpriteRenderer를 90도 돌리지 않는다.
- 쌍을 구성하는 A/B는 인스턴스 라벨이다. A가 항상 왼쪽/아래쪽이라고 가정하지 않는다.
- 가로 예시: 왼쪽 마름·오른쪽 물 → 플레이어 오른쪽 / 물 왼쪽.
- 세로 예시: 위쪽 물·아래쪽 마름 → 플레이어 위쪽 / 물 아래쪽.
- 반대 초기 위상에서는 물과 플레이어 방향이 모두 반대가 된다. 실제 높은 지형/낮은 지형 제약은 추가하지 않았다.

3. 직관적인 피드백
- 고정된 낮은 풀·흙 테두리, 두 구덩이를 연결하는 열린 수로, 작은 목재 수문이 한 장치로 보인다.
- 유효한 교환에만 작은 수문 열림 → 물줄기/물결의 출발지→도착지 이동 → 수위 이전 → 수문 닫힘을 재생한다.
- 물줄기는 항상 기존 물웅덩이에서 시작해 빈 구덩이에 닿는다. 도착지에 작은 물 튀김이 생긴다.
- 12프레임, 12fps, 총 1초다. 첫/마지막은 닫힘, 중간은 열림이며 마지막 그림은 확정된 새 상태와 일치한다.
- 물·수문·플레이어의 논리적 상태는 입력 판정에서 함께 확정된다. 애니메이션 종료에서 과금/타일 변경을 하지 않는다.
- 플레이어의 전용 시각 자식은 반대 방향 경로를 같은 연출 구간에 재생한다. 게임플레이 루트를 애니메이션으로 밀지 않는다.
- 오프라인 미리보기의 방향 화살표와 P 표시는 설명용이다. 실제 런타임 PNG에는 없고 물길·개폐·이동하는 물결이 들어 있다.
- 주변 바닥에서 물칸으로 들어가는 일반 이동은 특수 교환 조건이 아니다. 짝의 마른 칸에서 출발해야 한다.

4. 실패, 코스트, 복원
- 목적지 점유 등으로 실패하면 물, 플레이어, 수문 효과를 모두 변경하지 않는다. 코스트/장치 턴도 0이다.
- 떠나는 플레이어 자신을 출발 칸의 침수 장애물로 세지 않는다.
- 동행 병아리 등 추가 침수 객체 정책은 미확정이다. 기존 floodPolicyHolds 보호/진단을 유지한다.
- 성공한 직접 입력은 코스트 1, 장치 턴 1이다. 수문 열림/물 이동/닫힘에 각각 추가 턴을 주지 않는다.
- 입력 회계와 참조 커널의 costDelta/turnDelta를 중복 반영하지 않는다.
- Undo/Reset/Load는 쌍의 좌표/물 위상과 플레이어를 함께 복원하고, 진행 중 연출을 취소한 뒤 정지 상태를 재적용한다.

5. 양 — R2와 동일
- 직접 밀면 플레이어는 제자리, 양만 밀린 방향으로 한 칸 움직인다.
- 일반 바닥이면 양이 그 칸에 남는다. 풀이 있으면 그 풀과 양을 모두 제거하고 바닥을 남긴다.
- 물/벽/다른 차단 물체/양은 이동을 막으며, 새 연쇄 밀기는 추가하지 않는다.
- 양은 실제 유효 바람 범위의 끝 또는 장애물 직전까지 움직인다. 도중 처음 만난 풀을 먹으면 풀과 양이 사라진다.
- 바람 연쇄는 추가 코스트/턴 0이다. 양이 사라진 뒤 다음 풀을 계속 먹지 않는다.
- 물자리 수정으로 양 아트나 위 규칙을 바꾸지 않는다. 소멸을 방울·출구·보상으로 연결하지 않는다.

6. 포함 파일과 검증 범위
- 총 373개 PNG, 170개 애니메이션 정의. 기존 277개 PNG 경로는 유지하고 그중 가로 수문 6개를 교체했다.
- 새 가로/세로 × 양방향 × 12프레임 = 48개의 합성 PNG를 추가했다.
- Runtime/Rules/RanchDeviceRulesR2.cs에 waterRoute를 추가했다. 기존 교환 판정은 두 축을 모두 지원한다.
- Runtime/Rules/RanchPondPresentationR3.cs는 실제 좌표/물 위상으로 축과 물 흐름 키를 결정한다.
- Runtime/RanchPondSluiceVisualR3.cs는 확정된 물/플레이어 경로를 확인하고 합성 클립을 재생한다.
- Tests~/RulesR2에는 기존 21개 + 추가 10개 = 총 31개 EditMode 검사 케이스 원본이 있다.
- 원화와 최종 프롬프트는 Authoring~/native 및 generation_prompts_r3.json에 포함한다. built-in imagegen을 사용했다.
- 파일/카탈로그/PNG/압축 무결성을 검사한다. 실제 Unity C# 컴파일, NUnit, 원 프로젝트 연결, 플레이 검증은 NOT_RUN이다.
- 바람/컨베이어/제동판 순서와 병아리 동행/재추종의 미확정 부분은 이번 수정으로 임의 확정하지 않는다.


ANIMOL 별길 목장 V13 R4 — 병아리 둥지 귀환 애니메이션

1. 표현 목표
- 기존 빈 둥지의 흔들림/완료 표시만으로 끝나던 부분에 병아리가 직접 들어가 앉는 모습을 추가한다.
- 기존 병아리의 노란 몸/크림색 날개/주황 부리와 발/짙은 남색 외곽선을 유지한다.
- 남·동·북·서 네 방향은 별도 원화다. 뒷모습에 눈이나 부리를 그리지 않으며, 옆모습은 반대쪽 눈을 보이지 않는다.
- 실제 접근 경로 재생 → 도착 → 짧게 움츠림 → 폴짝 뛰기 → 부드러운 착지 → 날개를 접고 앉기 → 귀환 완료 표시 순서다.
- 도착 후 동작은 서로 다른6포즈를 8타임프레임으로 배치해 10fps/0.8초로 재생한다.
- 둥지 본체는 고정된다. 병아리의 몸 아래/발은 둥지 앞쪽 볏짚에 가려져 안에 들어갔다는 깊이감을 준다.
- 귀환 완료 후에는 병아리가 둥지 안에 앉아 있는 마지막 모습과 기존 계열의 작은 완료 표시를 유지한다.
- 눈이 보이는 방향은 마지막에 눈을 편안하게 감는다. 북쪽은 같은 뒷모습으로 앉는다.

2. 게임 판정과 연출 연결
- 귀환 조건/귀환 가능 둥지/수용 수/귀환한 병아리의 논리 상태는 원 프로젝트의 기존 판정이 소유한다.
- 귀환 성공을 한 번 확정한 뒤, 실제 경로를 따라오는 임시 시각과 도착 연출을 재생한다.
- 귀환 판정이 실패하거나 병아리가 도착하지 않았다면 성공 애니메이션을 먼저 재생하지 않는다.
- 게임플레이의 병아리를 추종 목록에서 분리하는 등 기존 귀환 결과는 논리 트랜잭션에서 처리한다.
- 애니메이션 완료에서 귀환 수/보상/코스트/장치 턴을 다시 변경하지 않는다. 별도 입력도 요구하지 않는다.
- 연출 자체의 추가 코스트/장치 턴은0이다. 최초 이동/바람 행동의 회계는 기존 게임 규칙을 따른다.
- 새로운 둥지 수용 규칙, 자동 귀환 경로, 방울/출구/보상 규칙을 추가하는 패치가 아니다.
- 수문 통과 후 정지/재추종/추가 침수 객체의 미확정 부분도 이 표현 수정으로 확정하지 않는다.

3. 표시 모드
- 권장: nest_return/<direction>/arrive 하나에 병아리와 둥지를 함께 표시하고, 끝나면 occupied로 전환한다.
- 이 모드에서는 도착한 병아리의 원래 렌더러/접근용 임시 렌더러를 숨겨 중복 병아리를 막는다.
- 기존 둥지 렌더러도 같은 합성 렌더러를 사용하거나 숨긴다. 빈 둥지와 합성 둥지를 겹쳐 그리지 않는다.
- chick_return/<direction>/hop은 분리 렌더링이 필요한 프로젝트용 병아리 단독 클립이다.
  권장 합성 모드와 동시에 병아리 단독 클립을 추가로 재생하지 않는다.
- nest/arrive 및 nest/settled는 정면(south) 귀환/앉기 클립의 호환 별칭이다. 신규 연결은 방향이 명시된 키를 사용한다.
- 접근 방향은 실제 경로의 마지막 유효 이동 벡터로 정한다. +Y=북쪽이며 배열 행 방향은 어댑터에서 변환한다.
- 귀환 상태를 로드했을 때는 도착 연출을 다시 보여 주지 않고 occupied 정지 상태를 즉시 적용한다.

4. 연결용 소스
- Runtime/RanchChickNestReturnVisualR4.cs를 둥지의 표현 소유자에 붙인다.
- 전용 자식 RanchDeviceVisualV13 하나를 Configure(catalog, child, out error)로 연결한다.
- 초기/로드/Undo/Reset/풀 재사용 시 SetResolvedState(occupied, settledDirection, out error)를 적용한다.
- 귀환 성공 후 접근 시각이 실제 둥지에 도착하면 PlayCommittedArrival(transactionId, arrivalDirection, out error)를 호출한다.
- transactionId는 스테이지/리셋 세대가 포함된 원 프로젝트의 고유 성공 이벤트 식별자다. 매 Update에서 새 ID를 만들지 않는다.
- 동일 이벤트의 중복 호출은 재시작 없이 성공한 no-op으로 처리한다. 다른 이벤트로 재생 중이면 false/진단을 반환해 호스트가 대기시킨다.
- ClearPresentation/비활성화는 표시만 취소한다. 게임의 귀환 결과를 취소하거나 병아리를 되살리지 않는다.
- 복원 후 권한 있는 실제 상태로 SetResolvedState를 다시 호출한다. 이 함수는 복원 시점에만 호출하고 매 프레임 호출하지 않는다.
- 표현기가 처리하는 중복 방지는 시각 중복 방지이며 보상 중복 방지의 권한 있는 게임 판정을 대신하지 않는다.

- R4 전체: PNG373개/클립170개. R3의 PNG325개는 모두 동일 바이트로 보존했다.
- 새 원화4장, 병아리 단독24 PNG, 둥지 합성24 PNG, 새12클립이 추가된다.
- PNG320×320, PPU256, Pivot(.5,.5), FullRect, Bilinear, 무압축, Mipmap Off다.

- PATCH_R3_TO_R4.json에 요구되는 R3 카탈로그 해시와 목표 R4 해시/파일 목록을 포함한다.
- 전체 V13 ZIP에는 R3 수문과 R2 양 수정까지 포함된다. 새 설치는 전체본, 기존 R3는 추가 패치를 사용한다.
