ANIMOL 별길 목장 V13 R4 — 병아리 둥지 귀환 적용 명령문

현재 Unity 프로젝트의 AGENTS.md, 병아리 추종/실제 이동 경로/둥지 귀환/저장/Undo/기존 장치 표현 코드를 읽고 다음을 적용하라.
목표는 귀환 판정이 성공했을 때 병아리가 둥지에 폴짝 들어가 앉고 그 상태로 남는 피드백을 추가하는 것이다.
최신 상세 기준은 UPDATE_R4_CHICK_RETURN_KO.txt다. R3 수로와 R2 양 규칙도 유지한다.

1. 설치 대상을 먼저 확인
- 기존 Assets 내 ANIMOL_STARWAY_RANCH_DEVICES_V13 설치 폴더를 찾아 같은 위치에 병합하고 .meta/GUID를 보존한다.
- 작은 R4_PATCH.zip을 받은 경우 V13 R3가 선행 설치되어야 한다. PATCH_R3_TO_R4.json의 expectedBaseCatalogSha256과 기존 카탈로그 해시를 확인한다.
- R3 해시가 다르면 임의로 강제 덮어쓰지 말고 설치본/사용자 수정 사항을 비교한다. 새 설치는 R4 전체본을 사용한다.
- 이미 targetCatalogSha256의 R4라면 중복 클래스를 새로 설치하지 않고 연결 상태만 확인한다.
- removedFiles에 명시된 구 패키지의 .tmp 임시 파일은 해시가 같은 경우에만 정리한다. 정상 PNG/.meta 또는 다른 사용자 파일은 삭제하지 않는다.
- animation_catalog.json, catalog_sha256.txt, RanchDevicesV13Pin.cs, 새48 PNG, Runtime/RanchChickNestReturnVisualR4.cs를 함께 갱신한다.
- Sprite373개 / 클립170개 / installationRevision4다. 새 Pin과 오래된 카탈로그를 혼용하지 않는다.
- PNG320×320 / PPU256 / 중앙 Pivot(.5,.5) / FullRect / Bilinear / 무압축 / Mipmap Off를 유지한다.
- Tools > ANIMOL > Ranch Devices V13 > Build catalog, clips and inspection prefab에서 이번 animation_catalog.json을 골라 .anim/카탈로그를 재생성한다.
- 생성된 _GeneratedV13/RanchDevicesV13Catalog.asset과 InspectionOnly_AllClips.prefab을 확인한다.

선택적 빌더 실행:
"<Unity Editor>" -batchmode -quit -projectPath "<project>" -executeMethod ANIMOL.Editor.RanchDevicesV13.RanchDevicesV13Builder.BuildFromCommandLine -ranchDeviceCatalog "Assets/<existing path>/ANIMOL_STARWAY_RANCH_DEVICES_V13/animation_catalog.json" -logFile "<log>"

2. 기존 귀환 성공 이벤트에 연결
- 원 프로젝트의 귀환 가능 판정과 트랜잭션을 먼저 찾는다. 새 프레젠테이션 코드 안에 두 번째 게임 판정 보드를 만들지 않는다.
- 기존 성공 판정에서 귀환한 병아리/둥지 상태, 추종 해제, 필요한 회계/저장을 한 번만 확정한다.
- 귀환 성공 이벤트 식별자(transactionId), 실제 접근 경로, 마지막 도착 방향, 둥지 식별자를 표현 단계로 전달한다.
- 병아리의 실제 접근 경로를 걷기/이동 연출로 먼저 재생한다. 벽을 통과하는 임의 직선 경로를 새로 만들지 않는다.
- 논리 병아리를 이미 반환 처리했다면 접근용 임시 시각을 사용한다. 연출을 기다리려고 충돌체/추종 상태를 유지하지 않는다.
- 접근 시각이 둥지에 도착한 시점에 아래 도착 애니메이션을 호출한다. 원래 병아리 렌더러와 임시 접근 렌더러는 그때 숨긴다.
- 실패/도착 전/단순 근접/일반 둥지 접촉만으로 귀환 완료 애니메이션을 먼저 재생하지 않는다.
- 애니메이션 끝에서 병아리를 다시 귀환 처리하거나 귀환 수/보상을 올리지 않는다. 추가 입력/추가 코스트/추가 장치 턴은0이다.

3. 권장 합성 표시 구성
- 둥지 논리 루트 아래 표현 소유자와 전용 자식 RanchDeviceVisualV13 하나를 둔다. 자식은 둥지의 실제 셀 중심에 놓고 스케일은 동일한 X/Y를 사용한다.
- 표현 소유자에 RanchChickNestReturnVisualR4를 붙인다. 논리 루트 자체를 스프라이트 애니메이션으로 이동시키지 않는다.
- Configure(currentCatalog, dedicatedChild, out error)로 연결한다. 현재 카탈로그가 없거나 다른 소유자의 렌더러라면 진단을 해결한다.
- 초기/로드/Undo/Reset/풀 재사용에서는 SetResolvedState(isOccupied, savedSettledDirection, out error)를 호출한다.
- 비어 있으면 nest/idle, 귀환 상태이면 nest_return/<direction>/occupied가 즉시 표시된다. 로드 시 귀환 연출을 재시작하지 않는다.
- 방향 저장이 없는 이전 저장본의 시각 마이그레이션은 south를 선택할 수 있지만 게임 상태/귀환 수는 바꾸지 않는다.
- 성공한 접근이 끝나면 PlayCommittedArrival(successEventId, arrivalDirection, out error)를 호출한다.
- arrivalDirection은 "south", "east", "north", "west" 중 하나이며 실제 경로의 마지막 유효 이동 벡터에서 계산한다.
- 커널/카탈로그는 +Y=북쪽이다. 배열 행 +1=아래인 프로젝트라면 방향을 어댑터에서 변환한다.
- 새 키는 nest_return/<direction>/arrive 및 occupied다. arrive는 8타임프레임/10fps, 총0.8초이며 끝나면 같은 마지막 그림의 occupied를 유지한다.
- 도착 연출에는 이미 병아리와 둥지가 함께 그려져 있다. 빈 둥지/원래 병아리/임시 접근 병아리/단독 hop을 동시에 중복 표시하지 않는다.
- 앞쪽 볏짚 가림이 합성 PNG에 들어 있다. 그 위에 별도 둥지 앞면을 다시 덮지 않는다.
- chick_return/<direction>/hop은 별도 병아리 렌더링이 필요한 프로젝트의 대안이다. 권장 합성 모드와 동시에 사용하지 않는다.
- 기존 nest/arrive와 nest/settled는 south 귀환/앉기 호환 별칭으로 갱신됐다. 기존 이벤트가 이 키를 쓰더라도 병아리 중복 표시를 반드시 정리한다.

4. 중복 이벤트, 취소, 복원
- transactionId는 보드/리셋 세대를 포함한 고유 성공 이벤트 ID를 사용한다. Update마다 새 ID를 생성하지 않는다.
- 같은 이벤트를 다시 전달하면 표현기는 재시작하지 않는다. 보상/귀환 수 중복 방지는 기존 권한 있는 게임 로직에서도 유지한다.
- 다른 귀환 이벤트가 연출 중 도착하면 표현기의 false/진단을 확인하고 기존 호스트 표현 큐에 넣는다. 이벤트를 버리거나 게임 귀환 판정을 취소하지 않는다.
- 다중 병아리 수용/귀환 경로/재추종 정책은 기존 기획이 소유한다. 시각 큐 처리 때문에 새 수용 수를 임의로1로 제한하지 않는다.
- Undo/Reset/Load/풀 반환 때 ClearPresentation으로 진행 중 표시를 취소하고, 다시 활성화할 때 현재 권한 상태를 SetResolvedState로 적용한다.
- SetResolvedState는 복원/초기화 시점에 사용하며 매 프레임 호출하지 않는다. 이 함수는 시각 이벤트 중복 기록을 새 세대로 초기화한다.
- 취소된 오래된 접근 완료 콜백도 호스트 세대 검사로 무시한다. Reset 이후 과거 콜백이 새 귀환 연출을 재생하지 못하게 한다.
- 시각 취소만으로 귀환한 병아리를 되살리거나 추종 상태를 복원하지 않는다. 실제 Undo 트랜잭션이 반환 상태와 추종 상태를 함께 복원한다.

5. 실제 프로젝트 검증
- Unity 컴파일 후 빌더를 실행하고 Sprite373개/.anim170개/현재 Pin을 확인한다.
- 기존 Tests~/RulesR2의31개 EditMode 검사 원본은 유지하고 프로젝트 환경에서 실행한다.
- 남·동·북·서에서 실제 경로를 따라 도착하는 병아리를 각각 확인한다. 옆모습 반대 눈/뒷모습 얼굴이 새로 나타나지 않아야 한다.
- 움츠림→도약→착지→앉기의 순서, 둥지 앞 볏짚이 발/몸 아래를 가리는지, 마지막 앉은 상태가 유지되는지 실제 카메라 배율로 확인한다.
- 귀환 시 원래 병아리와 합성 병아리가 두 마리로 겹치지 않고, 귀환한 병아리가 다시 플레이어를 따라오지 않는지 확인한다.
- 동일 성공 이벤트2회 전달에도 애니메이션이 재시작되거나 귀환 수/보상/코스트가 증가하지 않는지 확인한다.
- 실패한 귀환/도착 전/미완료 접근에서는 성공 표시가 뜨지 않는지 확인한다.
- 도약 중 Undo/Reset/Load/풀 반환 후 재진입에서도 잔상/옛 콜백/빈 둥지 오표시가 없는지 확인한다.
- 추가 코스트/장치 턴이 발생하지 않고 R3의 가로·세로 수문, R2의 양 밀기/풀과 양 제거/바람 동작이 유지되는지 확인한다.
- 변경한 실제 프로젝트 파일, 연결된 성공 이벤트, 수행한 검사와 미실행 항목을 보고한다.

전달 환경에서 완료한 것은 파일/원화/카탈로그/오프라인 미리보기/압축 검수다. 실제 Unity C# 컴파일/NUnit/원 프로젝트 연결/플레이는 NOT_RUN이다.

2. 수문 배치 데이터 — 가로/세로
- 인스턴스별 두 셀 A/B 좌표와 wetA를 저장한다. 두 셀은 상하 또는 좌우로 정확히 한 칸 이웃해야 한다.
- A/B의 순서를 새로 강제하거나 저장된 물 위상을 좌표 정렬만으로 뒤집지 않는다.
- 가로는 점유2×1, 세로는 점유1×2다. 연결 수로는 두 칸 안에 포함되고 별도 세 번째 칸을 차지하지 않는다.
- 커널 좌표는 +Y=북이다. 프로젝트가 배열 행 +1=아래를 사용하면 어댑터에서 북/남 부호를 변환한다.
- 기존 배치 도구가 수평만 허용한다면 두 인접 셀 또는 horizontal/vertical 선택을 지원하도록 확장한다.
- 수평 검사로 dy==0만 통과시키던 호스트 코드를 찾아 상하 인접도 허용한다. 대각선과 두 칸 간격은 거절한다.
- 수문/양의 공식 정의 ID는 기존 프로젝트 정의를 사용하며 패키지에서 새 번호를 임의로 붙이지 않는다.

3. 이동 판정과 물 방향
- 플레이어가 짝의 마른 칸에서 짝 물칸으로 입력할 때 TryCrossPond를 일반 물칸 거절보다 먼저 검사한다.
- 기본 교환은 출발 칸 물참 + 도착 칸 물빠짐 + 플레이어 도착 이동의 원자적 성공이다.
- 목적지 점유/추가 침수 객체 정책을 먼저 확인한다. 실패는 상태/코스트/턴/물 흐름 효과 모두 0이다.
- 출발 플레이어는 떠나는 객체이므로 침수 차단으로 세지 않는다. 도착 칸은 같은 교환으로 말라지므로 기존 물 차단만으로 거절하지 않는다.
- result.actualRoute는 플레이어 [행동 전 Dry, 행동 전 Wet]다.
- 새 result.waterRoute는 물 [행동 전 Wet, 행동 전 Dry]다. 물 이동에는 actualRoute를 그대로 사용하지 않는다.
- 수평 예: 서쪽마름·동쪽물 → 플레이어동쪽 / 물서쪽.
- 수직 예: 남쪽마름·북쪽물 → 플레이어북쪽 / 물남쪽.
- 반대 초기 위상은 반대로 작동한다. 위로 이동하는 물도 퍼즐의 동일한 교환 규칙으로 허용한다.
- NotApplicable은 기존 일반 판정으로 보낸다. 외부 바닥에서 물칸으로 들어가는 입력을 무조건 교환으로 처리하지 않는다.
- 원 프로젝트의 권한 있는 상태/Undo/회계에서 한 번만 확정한다. 참조 BoardR2를 별도 실시간 보드로 운영하지 않는다.
- 코스트 1/장치 턴 1을 입력 회계 또는 커널 delta 중 한 경로로만 적용한다. 애니메이션에서는 과금하지 않는다.

4. 새 수로 표현 연결
- 기본 표현은 Runtime/RanchPondSluiceVisualR3.cs와 전용 자식 RanchDeviceVisualV13 하나다.
- 자식 렌더러는 쌍의 월드 중심에 둔다. X/Y 스케일을 동일하게 적용하고 회전은 0이다. 논리 루트/콜라이더를 애니메이션으로 이동하지 않는다.
- Configure(catalog, dedicatedChild, pairSnapshot, out error)로 구성한다. RulesR2 어셈블리와 새 RanchPondPresentationR3.cs도 함께 포함한다.
- 정지 상태는 SetResolvedState(authoritativePairSnapshot)로 표시한다.
- 교환 성공 후 PlayCommittedTransfer(beforePairSnapshot, afterPairSnapshot, committedResult, out error)를 호출한다.
- before는 변경 전 별도 스냅샷이어야 한다. after와 같은 변형된 객체를 넘기지 않는다. pair.Copy() 등을 사용한다.
- 표현기는 물 경로/플레이어 경로가 반대인지, 실제 성공 이벤트인지 검사한다. 실패 이벤트로 물을 흘리지 않는다.
- 현재 물칸→마른 칸 방향은 RanchPondPresentationR3.TryCue(before, ...)가 좌표로 결정한다. A가 언제나 서쪽/남쪽이라고 가정하지 않는다.
- 가로 클립: pond_pair/horizontal/west_wet, east_wet, water_west, water_east.
- 세로 클립: pond_pair/vertical/north_wet, south_wet, water_north, water_south.
- 물 수문 클립은 열림→수로 흐름→수위 이전→닫힘, 12프레임/12fps다. 마지막 그림을 새 정지 키로 바꾼다.
- 같은 1초 구간에 플레이어 전용 시각 자식을 result.actualRoute로 반대 방향 이동시킨다. 기존 연출 속도 체계에 맞추되 물/플레이어의 방향은 유지한다.
- 기존 RanchCommittedMotionV13을 쓰면 실제 경로의 월드 중심과 1칸당 1초를 전달하고, 게임플레이 루트를 먼저 확정된 목적지에 둔다.
- 렌더러 하나에 2칸 합성 그림을 표시한다. R2 RanchPondPairVisualR2의 두 셀 렌더러와 기존 물 오버레이는 해당 인스턴스에서 비활성화해 중복 표시를 막는다.
- R2의 셀별 표현은 호환용이다. 이번 수로 피드백을 사용하려면 R3 합성 표현으로 연결해야 한다.
- 옛 pond_pair/cross_a_to_b 등 키는 수평 호환 별칭이다. 그 이름은 플레이어 이동이며 물은 반대다. 새 연결은 축/물 방향이 명시된 R3 키를 사용한다.
- 세로 그림을 회전한 가로 그림으로 대체하지 않는다. 오프라인 미리보기의 화살표/P 문자를 런타임 장치에 추가하지 않는다.
- OnDisable/Undo/Reset/Load/오브젝트 풀 복귀에서는 Clear로 연출을 취소하고, 다시 켤 때 권한 있는 현재 물 위상을 SetResolvedState로 적용한다.
- 빠른 재입력/연쇄의 연출 대기는 기존 호스트 방식을 따른다. 클립 완료에서 다음 장치 턴을 자동 발생시키지 않는다.

5. 양과 나머지 장치 유지
- 직접 양 밀기는 플레이어 제자리, 양만 한 칸 이동한다. 기존 공용 PushHandler의 플레이어 전진을 이 장치에서 억제한다.
- 풀에 닿으면 그 풀과 양을 모두 제거하고 바닥을 남긴다. 양은 바람 영향을 받고 처음 만난 풀에서 먹고 사라진다.
- 유효한 직접 입력 1회 비용, 바람 자동 연쇄 추가0, 실패0 규칙을 유지한다.
- 참조 TryPushSheep/TryWindSheep와 RanchSheepConsumptionVisualR2를 기존 실제 맵/엔티티에 연결한 상태를 유지한다.
- 먹기/풀/털 효과는 논리 제거 후 임시 시각으로만 재생하고 끝나면 숨긴다. Collider를 남기지 않는다.
- 병아리 등 추가 침수 객체는 floodPolicyHolds 진단을 유지한다. 동행/재추종 및 바람·컨베이어·제동판 순서의 미확정 사항을 임의 확정하지 않는다.

6. 실제 프로젝트 검증과 결과 보고
- C# 컴파일 후 빌더 실행, Sprite373개/클립170개/최신 Pin을 확인한다.
- Unity Test Framework가 준비된 프로젝트에서 Tests~/RulesR2의 두 .cs와 테스트 asmdef를 실제 Editor 테스트 폴더로 복사한다.
- 제공 총31개 검사 케이스를 실행한다. 새 검사는 양축/네 방향/A·B 역순/실제 물 경로·플레이어 경로/차단 시 효과 없음까지 확인한다.
- 실제 맵에 수평2×1과 수직1×2를 놓고 각각 양방향 이동, 물의 실제 출발지와 도착지, 플레이어 반대 이동을 확인한다.
- 수문 열림과 흐르는 물줄기가 설명 화살표 없이도 보이는지, 원래 웅덩이가 비고 빈 구덩이에 물이 차는지 실제 게임 배율로 확인한다.

- 변경 경로, 등록된 장치 정의, 실제 테스트 결과와 미실행 항목을 보고한다.
