공통4범주(무빙워크·일방향 문·튕김 모서리·제동판)와 성소5범주(초승달 도약·빛 장치·자석·짝 포털·유리벽)의 최신 원화를 같은 칸 테두리 위에서 검토한다. 방향이 필요한 장치는 네 방향, 제동판은 두 이동 축, 튕김 모서리는 네 코너를 보인다. 광원·거울·감지기·연결 문은 같은 카드에 묶는다.

이 파일은 실제 Unity 스크린샷이나 실행 영상이 아니다. 소스 규칙을 설명하는 셀 테두리, 도약3칸 점선, 반사 광선, 금속 견인 경로, 포털 출구 한 칸 예시는 미리보기용 정밀 도형/원화 합성이다. 실제 프로젝트의 프리팹·장치 ID·점유·시뮬레이션·셰이더가 연결됐다는 증거로 사용하지 않는다. 상자 견인과 포털 출력 예시는 입력 도감의 확정 규칙에 맞춘 설명용 재생이며, 영상 반복 시 초기 예시 상태로 돌아간다.

원화 픽셀은 각 담당 그룹의 최신 PNG를 읽어 균일 크기 조절/합성만 했다. 새 production RGB를 코드로 그리거나 기존 원화를 재도색하지 않았다. GIF는 전체 구간에 하나의256색 팔레트와 Dither.NONE을 사용한다. GIF 표시용 양자화와 무관하게 실제 PNG 원화와 고해상도 검수 PNG는 원래의 색·알파를 유지한다.

특히 확인할 부분
- 일방향 문은 한 칸, 잘못된 방향에는 닫힌 봉과 X.
- 무빙워크의 실제 진행 축과 화살표가 일치, 제동판은 이동 축에 수직인 정지봉.
- 도약판은 출발칸과 세 칸 떨어진 별도 착지 표식. 미확정 착지/중간 장치 반응은 실제 host에 위임.
- 자석 U입구 바깥쪽으로 밀지 않고 금속만 자석 쪽으로 견인. 목재는 그대로.
- 포털은 A/B에 같은 pair glyph를 사용하고 실제 world 방향과 walk/slide 상태 보존. 출구 바깥 한 칸이 막히면 입구 전 정지.
- 유리는 온전할 때 빛만 통과. crack 프레임으로 새 다중 피격 규칙을 만들지 않고 기존 폭탄/석상 파괴 때 open으로 전환.

재현 스크립트 build_device_previews.py는 다른 그룹의 runtime PNG를 수정하지 않는다. 실제 Unity import/C#·shader compile/Play Mode는 NOT_RUN이다.

거울 전환 검수: canonical endpoint pose0에서만 E→N, pose4에서만 E→S 광선을 표시한다. 중간 native yaw pose1/2/3에서는 반사 광선을 숨기고 TRANSITION을 표시해 전환 그림의 면과 광선 방향이 충돌하지 않게 했다. 센서/연결 문의 짧은 상태 피드백은 유지한다. 실제 광선은 host의 확정된 endpoint 상태를 따른다.
