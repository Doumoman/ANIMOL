별길 목장 — 연결 울타리·낮은 돌담 V01

신규 built-in imagegen 원화에서 제작한 장식 연결 스프라이트다. 기존 V12 장식의 크기·그림체를 참조했으며 기존 PNG를 재색칠하거나 다리 rail을 재사용하지 않았다. cream_fence와 meadow_stone_wall 각각16 이웃 마스크와 직선 구간의 선택적 기둥1개, 총34 PNG다. 실제 생성 프롬프트는 generation_prompts.json, 최종 원화는 sources/에 있다. 돌담의 첫 시도도 편집 근거로만 보관하며 인게임 선택 대상이 아니다.

N=+gridY, E=+gridX이다. 마스크는 N1 E2 S4 W8이며 같은 family/connectionGroup/layer/height의 연결 장식만 이웃으로 판정한다. 단지 잔디 바닥이 옆에 있다는 이유로 울타리를 연장하지 않는다. 현재 지도 좌표가 행 아래 방향이면 y를 명시적으로 변환한다.

기본 캔버스320×320, 논리 지면[32,32,256,256],PPU256,pivot[0.5,0.5]다. 논리1칸은world1이며 투명 여백을 포함해 PNG 전체를1칸으로 축소하면 안 된다. 연결부는 논리 칸의 경계에 닿고, 인접 칸도 같은 단면을 가진다. 비연결 방향의 팔은 그리지 않는다.

직선 n05(N+S)와 n10(E+W)는 중간 기둥이 없다. 끝·코너·T·교차 지점에는 해당 칸이 가진 중앙 기둥 하나만 그려진다. periodic_post.png는 직선에서만, host가 정한 전역좌표 기준3~4칸 간격으로 배치하는 선택적 부품이다. 진행 축의 양옆 이웃도 같은 직선 마스크인 후보만 허용하여, 끝·코너·갈림길 옆1칸에 기둥이 연달아 서지 않게 한다. 양쪽 끝 기둥이 달린 패널을 매 칸 반복하지 않는다. 지도/카메라 이동이나 프레임마다 난수를 다시 뽑아 기둥 위치를 바꾸지 않는다.

반투명 접합 픽셀의 소유권은 [32,288)×[32,288)의 반열린 논리 영역이다. 연결 방향에는 같은 native RGB의 완전 불투명(alpha255) 코어만4px 연장하여, 작은 화면에서 Bilinear/LANCZOS가 투명 여백을 읽고 내부에 얇은 선을 만드는 것을 방지한다. 반투명 AA 픽셀은 여백으로 연장하지 않아 중복 블렌딩하지 않는다. 두 PNG의64px 캔버스 중첩 영역 전체 RGBA가 같을 필요는 없으며, 동시에 그려지는 부분이 같은 RGB/alpha255인지 검사한다. rails_qa.json은 256개 반대 방향 포트 조합의 RGBA 차이0, 실제3칸 연속 합성,64/80/100px 축소에서 코어 alpha 손실 최대2/255 이하, 전체34 PNG decode/SHA 일치를 기록한다.

장식 네트워크는 실제 게임의 통행/Collider/장치 ID를 새로 정의하지 않는다. 접합 판단용 장식 셀과 기존 게임 점유 판정을 분리한다. 다리 외곽의 기존 V12 bridge_decor rail/post 선택기는 별개다. 새 장식 울타리를 다리 경계 위에 자동 중복 배치하지 않는다.

production/build_rails.py는 원화 crop, alpha 정리/near-opaque core alpha 정규화, 균일 비율 등록, native 단면의 기계적 연장과 합성만 수행한다. PNG RGB를 코드로 그리거나 재색칠하지 않는다. inspection/의 배경·격자·설명 글씨는 검수용이며 인게임 스프라이트가 아니다.

이 결과는 오프라인 파일·픽셀·원화·접합 검수다. 원본 Unity 프로젝트가 없으므로 실제 Import/C# Compile/Prefab 연결/Play Mode/실제 장식 배치 검증은 모두 NOT_RUN이다.
