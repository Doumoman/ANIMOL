ANIMOL 별길 목장 — 연결 장식·여러 칸 장식 V01

이 패키지는 별길 목장의 장식 배치만 보강하는 추가 교체본이다. 이어 붙이는 울타리·낮은 돌담·입체 화단과, 여러 칸을 한 번에 채우는 큰 장식을 제공한다. 굵은 남색 외곽선, 크림색 목재와 에메랄드 마감, 민트·세이지 잎, 노란 건초·꽃, 경계가 선명한 평면 그림자를 기존 목장 그림체에 맞췄다.

기존 V12에도 2×1 울타리·벤치·여물통, 2×2 나무, 3×2 헛간이 있었다. 이번 작업은 모든 옛 PNG가 한 칸이었다는 전제에서 출발하지 않는다. 실제 프로젝트의 크기 강제 맞춤·앵커 처리·큰 장식 중복 생성·이웃별 연결 선택도 함께 확인해야 한다. 현재 원본 Unity 프로젝트가 없으므로 그 원인을 실제 코드에서 확인하거나 수정했다고 주장하지 않는다.

설치 범위

ANIMOL_STARWAY_RANCH_CONNECTED_DECOR_V01 폴더를 Assets 아래의 새 경로에 설치한다. 이 장식 추가본을 적용하려고 옛 V12 전체 팩을 다시 설치하지 않는다. 최신 바람개비·바람·일방향 문·병아리 패치, 다른 테마, 캐릭터, UI, 장치 동작, 기본 바닥과 배경은 유지한다. 기존 bridge_decor의 다리 경계 난간 선택기와 이 장식의 울타리를 같은 위치에 중복 생성하지 않는다.

정확한 파일·크기·피벗·원화·검수 수치는 manifest.json 및 개별 family manifest가 기준이다. 편집 원화와 Sources/Authoring/Inspection 이미지는 인게임 Sprite 선택 후보가 아니다. 원화 선택 파일을 설치하지 않아도 필수 runtime PNG와 코드가 모두 있으면 장식 사용이 가능하다.

장식 종류

cream_fence: 같은 연결 그룹의 크림색 목재 울타리. N1 E2 S4 W8의 16가지 이웃 상태를 사용한다.
meadow_stone_wall: 같은 연결 그룹의 낮은 목장 돌담. 울타리와 별도의 16가지 이웃 상태를 사용한다.
raised_flower_meadow: 연속해서 자라는 입체 잔디·화단. N1 NE2 E4 SE8 S16 SW32 W64 NW128의 256가지 이웃 상태로 바깥 모서리와 안쪽 구멍을 처리한다. 기본 바닥에 풀 무늬를 그려 넣는 방식이 아니라 별도의 올라온 장식이다.
hay_store_2x1: 2×1 건초 보관 장식.
feeding_corner_3x1: 3×1 긴 여물통과 목장 소품 장식.
tree_flower_corner_2x2: 2×2 나무·화단 장식.
barnyard_3x2: 3×2 헛간과 이어진 작은 마당 장식.

연결과 크기

연결은 실제 장식 맵의 family·connectionGroup·논리 장식 logicalLayer·정수 heightKey가 모두 같은 이웃끼리만 판정한다. 아래에 같은 풀 바닥이 있다고 연결하지 않는다. 서로 다른 그룹이나 높이의 장식은 맞닿아 있어도 임의로 연결하지 않는다. 직선의 매 칸마다 끝기둥을 붙이지 않고, 실제 끝·꺾임·분기와 안정된 좌표 간격의 기둥만 사용한다.

같은 띠나 화단 영역으로 이어질 셀들은 같은 connectionGroup을 공유한다. 매 셀의 고유 instanceId나 placementId를 connectionGroup으로 넣으면 모든 셀이 서로 다른 그룹이 되어 끝 타일로 분리되므로 그렇게 지정하지 않는다. 큰 장식의 placementId는 반대로 장식 그룹 하나마다 유일하게 유지한다.

새 장식은 PPU256이며 논리 256px가 world1칸이다. 일반 연결 장식의 320×320 캔버스에서 [32,32,256,256]이 지면 한 칸이고 나머지는 시각적 여유다. 여러 칸 장식은 각 파일의 logicalRect와 footprintCells, 별도 pivot을 사용한다. 그림 전체를 한 타일 크기로 줄이거나 alpha bounds를 지면 크기로 간주하지 않는다. 풀 끝·지붕·수관의 위쪽 돌출은 별도 시각 영역이다.

큰 장식은 기준 앵커 하나, 그 크기 전체의 장식 셀 예약, SpriteRenderer 하나로 배치한다. 3×2 장식을 여섯 칸의 루프에서 여섯 번 생성하지 않는다. 재배치·삭제·풀 재사용 때 그 장식이 소유한 모든 예약 셀과 시각을 함께 정리한다.

이 장식용 셀 예약은 기존 게임의 통행·충돌 점유와 구분한다. 실제 host가 장식 배치를 허용한 셀만 사용하며 그림의 alpha나 크기로 Collider·Blocker·새 보행 종류를 자동 생성하지 않는다. 원래 막는 장식과 통과 가능한 장식의 동작은 기존 프로젝트 계약을 따른다.

Unity 적용

UNITY_CLI_KO.txt를 실제 Unity 프로젝트를 다루는 CLI에게 전달한다. 새 namespace는 ANIMOL.Art.RanchConnectedDecorV01이다. manifest.json의 실제 SHA256과 manifest_sha256.txt를 대조하고, 해당 핀으로 생성한 최신 catalog만 연결한다. 전체 원본 이미지의 축소율 대신 선언된 PPU·logicalRect·pivot을 적용한다.

장식 맵의 배치·삭제·로드·undo·청크 갱신 이벤트에서 연결 상태를 다시 계산한다. 화면에 보이는 청크만 이웃으로 삼지 말고 실제 전체 장식 맵을 조회한다. 수평·수직·대각 이웃 변경이 영향을 주는 셀도 함께 갱신한다. 매 프레임 임의 난수로 화초·기둥을 다시 뽑지 않는다.

잘못된 layout을 SetLayout에 전달하면 이 component가 소유한 이전 시각까지 지우고 오류를 표시한다. 기존의 유효한 시각을 유지한 채 실패를 무시하는 정책이 아니다. host가 무효 이동을 확정하지 않아 SetLayout 호출 자체를 생략하는 경우와 구분한다. 오류 후에는 실제로 유효한 최신 전체 장식 맵으로 다시 전달한다.

오프라인 파일 검수

패키지 루트를 작업 디렉터리로 두고 실행한다. Python과 Pillow가 필요하다. INGAME만 설치했다면 선택 원화가 없는 상태를 허용하도록 다음 명령을 사용한다.
python QA/verify_addon.py --package "<패키지 루트>" --runtime-only

선택 원화까지 합친 전체판에서는 다음과 같이 --runtime-only를 생략해 원화 파일도 확인한다.
python QA/verify_addon.py --package "<패키지 루트>"

이 스크립트는 파일·PNG·해시·크기·피벗·목록 및 소스의 일부 구조를 확인한다. Unity Editor, C# 컴파일러, 실제 Scene이나 Play Mode를 실행하지 않는다.

검수 상태

PNG·메타데이터·원화·접합·오프라인 배치 그림의 검수와 실제 Unity 검증은 별개다. 실제 import, C# 컴파일, 원본 Prefab/Scene 바인딩, Play Mode, 현재 생성기의 강제 축소 제거, 실제 레거시 장식 참조 0은 아직 NOT_RUN이다. 미리보기는 조립된 장식 예시이며 실제 Unity 스크린샷이나 플레이 검증이 아니다.
