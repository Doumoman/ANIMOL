ANIMOL hole_finish_v5 — 기존 Unity 맵 에디터 적용 명령

이 패키지의 실제 아틀라스와 문양을 ANIMOL 자유형 지형 편집기의 artVersion=5로 설치해라. 수정 대상은 T01_A의 내부 구멍에서 산호색 마감·그림자 조각이 튀어나오던 연결부다. 기존 명암, 벽돌 무늬, 둥글고 뭉툭한 모서리를 유지해라. 다른 19스타일은 v4와 같은 아트다. 이번 작업에서 테마·팔레트·승인 디자인을 새로 만들지 마라.

이 패키지는 Unity 프로젝트에서 실행한 패치가 아니다. 아래 Unity 검사는 적용 프로젝트에서 수행하고 실행하지 않은 검사는 미실행으로 기록해라. v4 이하 문서·검사·비교판은 과거 버전 이력이며 v5 PASS로 재사용하지 마라.

1. 실제 프로젝트와 소스 확인
AGENTS.md, 현재 Git 변경, 기존 자유형 지형 데이터·Registry·Builder·Renderer·Undo/Validate/Commit 구현을 먼저 읽어라. 별도 에디터를 새로 만들지 말고 실제 Scene 편집기의 기존 흐름을 확장해라.
패키지를 Tools/ArtSources/ANIMOL_FreeShape_Sprites_hole_finish_v5 등 프로젝트 규칙에 맞는 소스 경로에 보관해라. PACKAGE_MANIFEST.json의 모든 파일 목록·크기·SHA256을 검사해라.
Data/sprite_lookup.json, source_rects.json, topology_catalog.json, style_catalog.json, Data/hole_native_layout_v5.json, Tools/build_hole_native_sources_v5.mjs, terrain_topology.mjs, terrain_composition.mjs, terrain_preview_model.mjs를 읽어라. npm run validate:hole, validate:art, validate:topology, validate:gallery를 실행해라. validate:joint는 v5 검사 별칭이며 Tools/validate_joint_finish_v4.mjs는 과거 검사다.
장식 provenance는 native 제작 코드가 실제 선언한 면·윤곽을 그리면서 만드는 영역 정보다. 같은 산호색/보라색이라도 몸체 명암을 내곽 장식으로 재분류해 덮지 마라. 내곽 받침 두께와 기둥 연결 위치는 v5 등록 좌표를 사용해라. 몸체·외곽 프레임·몸체 명암·둥근 돌 모서리는 v4 원본을 유지한다.
Previews/T01_A_hole_finish_v5_comparison.png는 실제 아틀라스의 셀 조립 결과다. 썸네일이나 과거 Sampling 이미지를 Runtime Sprite로 사용하지 마라. 색을 지우는 후처리, Runtime 픽셀 수정, 임의 테두리, Shader로 원본 마감을 대체하지 마라.

2. 아트 버전과 기존 계약 유지
contractId/artContract=ANIMOL_FREE_SHAPE_BLOB47_V1과 자유형 lookup/FreeShapeLayer schemaVersion=1을 유지하고 artVersion만 5로 설치해라. 기존 terrainPlacements schemaVersion=3 같은 다른 데이터 버전과 혼동하지 마라.
기존 20 styleId, 32×32px/PPU32, canonical mask 47종, raw mask 256종, v0~v3 네 전역 위상을 유지해라. v0~v3는 아트 버전이 아니라 같은 버전 안의 네 반복 위상이다.
별도 V5 레지스트리를 설치해라. 예: Assets/ANIMOL/TerrainFreeShape/Art/V5. 기존 V1~V4 에셋·meta·GUID·GlobalObjectId·사용자 맵을 보존하고 각 버전의 맵은 해당 레지스트리를 계속 참조하게 해라. 알 수 없는 계약/schema/버전이나 미설치 버전은 기존 규칙대로 거부하고 다른 버전으로 임의 fallback하지 마라.
V5에는 셀 Sprite 3,760개, 아틀라스 80장, 문양 20개의 참조가 완전해야 한다. 다른 19스타일은 SHA256이 동일한 기존 에셋이 설치된 경우만 참조를 명시적으로 공유해도 된다. 그렇지 않으면 이 패키지의 파일을 임포트해라.
Runtime은 lookup이 지정하는 아틀라스와 문양을 사용해라. 개별 셀 PNG·원화·Sampling·Samples·비교판·HTML을 중복 Runtime 설치하지 마라.

3. 임포트와 Sprite 참조 갱신
아틀라스는 Multiple, 32×32 rect, 중앙 pivot, FullRect, PPU32다. JSON rect는 왼쪽 위 원점이므로 Unity y=atlasHeight-y-height로 변환해라. 문양은 bottom-left pivot, PPU32, 시각 크기 4×4셀, 추가 점유/Collider 0이다.
Point, 압축 None, mipmap Off, 프로젝트의 정상 sRGB 설정을 적용해라. 알파 0/255와 T01_A 기존 5색을 유지해라.
기존 아트 버전의 캐시가 남지 않게 V5 Registry에서 styleId/mask/variant에 대응하는 모든 32×32 Sprite와 80개 아틀라스 참조를 lookup으로 등록해라. 썸네일만 바꾸거나 일부 mask/위상만 재바인딩하지 마라. 선택 맵이 V5로 전환될 때 Renderer·Tilemap·분면/셀 캐시가 새 Registry에서 다시 해석되어야 한다.

4. 선택한 맵만 아트 버전 전환
현재 맵의 artVersion을 표시하고, 사용자가 선택한 개발 맵 범위만 기존 Undo/Validate/Commit 경로로 artVersion=5에 전환해라. 설치·창 열기·리로드·초기화가 모든 맵을 자동 전환하거나 저장하면 안 된다.
전환 전후의 좌표·점유·styleId·seed·객체·스탬프·셀 크기·물리 소유자는 동일해야 한다. 기존 규칙대로 artVersion을 hash에 반영하고 revision은 한 번 증가시켜라. 점유를 이미지에서 다시 추정하거나 구멍을 외접 사각형으로 채우지 마라.
Undo/Redo가 버전과 파생 아트 참조·캐시를 함께 복원하게 해라. Validate·Commit·저장 실패는 정본·디스크·Scene 프리뷰·Registry 선택을 기존 트랜잭션 규칙으로 롤백해라. Ready·보상·스테이지 배정 검증을 우회하지 마라.

5. 전역 연결·위상·물리 보존
N1/NE2/E4/SE8/S16/SW32/W64/NW128, 대각선 게이팅, rawToCanonical/rawToIndex를 그대로 사용해라. 이웃은 청크 내부가 아니라 전역 점유에서 판정해라.
위상은 resolveVariant와 정확히 같아야 한다:
floorMod(globalX+(seed&1),2)+2*floorMod(-globalY+((seed>>1)&1),2).
음수 좌표에서도 양의 floorMod를 사용하고 16셀 청크 소유자는 Math.floor(global/16)과 같은 floor division을 사용해라. 지형의 좌상단이나 청크 원점에서 위상을 재시작하지 마라.
문양은 동일 스타일 4×4셀과 사방 1셀 여유의 점유 지지가 있을 때 기존 hash/support 규칙으로 표시해라. 문양·줄눈·받침·내곽 장식이 별도 점유나 Collider를 만들지 않아야 한다.
기존 고체 충돌 소유자, 객체 footprint/swept path, one-way 동작을 보존해라. 아트 Tilemap에 새 Collider를 추가하지 마라. 내부 빈 셀은 시각적으로도 물리적으로도 비어 있어야 한다.

6. 대상 프로젝트 검증과 결과 보고
먼저 맵 복사본에서 가운데 1×1 구멍(3×3 점유), 2×2 구멍(4×4 점유), 더 큰 구멍, 1셀 두께 벽·천장·바닥, 계단, 열린 U자 구덩이, T분기와 음수 청크 경계를 검사해라. 구멍을 만들기 전→생성→확대→다시 채우기의 마감 갱신도 확인해라.
3×3/가운데1×1 구멍은 seed=0의 origin(0,0),(1,0),(0,1),(1,1) 네 위상을 모두 검사하고 음수 시작 좌표와 고정 seed에서도 반복해라. T01_A의 47mask×4위상 전체와 다른 19스타일의 기존 참조가 유효한지 확인해라.
Scene/Runtime을 원배율 1×와 정수 최근접 8×로 캡처하고 패키지 실제 PNG와 비교해라. 구멍 모서리의 산호색 받침·흰 명암·보라 기둥 연결, 돌의 둥근 코너, 몸체 반복 줄눈을 확인해라. 모든 둥근 코너의 의도된 2×2 잉크까지 오류로 간주해 없애지 마라.
V4/V5 선택→저장→재열기→플레이, 전환 Undo/Redo, hash/revision, 실패 롤백, 문양 지지 제거/복원, 빈 구멍 통과·착지·one-way·객체 배치 보존을 검사해라. 실제 Unity 컴파일과 변경 경로의 기존 테스트도 실행해라.
Docs/ANIMOL_HOLE_FINISH_V5_PATCH_RESULT.md에 변경 경로·버전별 참조·manifest 검증·다른19스타일 보존·선택 맵·임포트 설정·실제 Unity 결과·검수 캡처·미실행 항목을 기록해라. 이 패키지의 Node 검사 결과와 대상 프로젝트의 Unity 실행 결과를 구분해라. 일부 모양의 검수를 모든 가능한 맵의 미관이나 다른19스타일의 신규 수정으로 확대해 보고하지 마라.
