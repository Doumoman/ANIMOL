ANIMOL 별길 목장 V12 — 최신 스프라이트·방향·애니메이션 교체 명령

목표
이번 작업 범위는 별길 목장과 별길 목장에 나타나는 공통 장치다. 실제 게임에서 생성되는 장치,
병아리, 풍차가 V12의 방향별 원화와 애니메이션을 사용하게 만들고, 이 테마에서 접근 가능한
레거시 시각 참조를 제거하라. 파일을 가져오거나 예시 씬 한 곳을 바꾸는 것으로 완료하지 말라.
잔영 극장·낙일 성소·별너울 해안의 원화, 공용 로직, 저장 ID와 기존 진행 상태는 보존하라.

전달물의 경계
이 패키지는 실제 PNG 프레임, 프레임/방향 카탈로그, 시각 재생기, Unity Editor 생성기,
지형·배경 런타임과 검수 자료다. 원 프로젝트의 Scene/Prefab/GUID/Addressables 주소/장치 이벤트를
이 환경에서 확인한 결과물이 아니다. 따라서 아래의 실제 프로젝트 연결과 실행 검증까지 수행하라.
동봉 합성 영상은 프레임 검토 자료이며 Unity Play Mode 녹화가 아니다.
이 문서는 V11의 '정적 상태 18장', '부족한 방향은 기존 표현 유지', 'front 한 장' 적용 지시를 대체한다.

먼저 읽을 파일
README_KO.txt, manifest.json, animation_catalog.json, required_visual_contract.json,
sprite_import_settings.json, device_bindings_template.json, visual_overrides.json,
inspection/atlas_logic_audit.json, required_gameplay_checks.json, legacy_migration_policy.json,
Runtime/StarwayRanchV12VisualCatalog.cs, Runtime/StarwayRanchV12AnimatedVisual.cs,
Editor/StarwayRanchV12AnimationBuilder.cs, Editor/StarwayRanchV12SpriteImporter.cs.
지형·배경은 terrain_manifest.json, span_manifest.json, bridge_tops_manifest.json,
bridge_decor_manifest.json, props_manifest.json, turf_manifest.json, background_manifest.json,
background_scene_layout.json 및 해당 Runtime을 추가로 읽어라.

1. 실제 참조 경로를 조사하고 대응표부터 작성하라.
별길 목장의 실제 테마 ID, 시작 씬, 캠페인·대전 진입, 레벨 에디터 미리보기, 재시작·씬 재진입,
런타임 맵 생성기, 프리팹 팩토리, 풀의 등록·재사용 경로를 먼저 찾는다. starway_meadow는 전달물의
참고 키일 뿐 검증된 프로젝트 키가 아니므로 이름만으로 새 enum/저장 키를 만들지 않는다.

장치별 실제 클래스·저장 ID·방향 필드·상태 enum·유효 행동 이벤트·SpriteRenderer 경로와
Animator/OverrideController·프리팹·SO·리소스 주소를 대응시킨다. device_bindings_template.json의
null/verified=false를 실제 소스 위치와 증거로 채우고 PROJECT_BINDING_REPORT.md로 제출한다.
도감 번호는 문서의 원문 번호이며 런타임 enum 숫자로 강제하지 않는다.

검사 범위에는 다음을 모두 포함한다.
- 비활성 오브젝트와 Prefab Variant/Nested Prefab/추가 컴포넌트를 포함한 모든 별길 목장 씬·프리팹.
- ScriptableObject의 테마 카탈로그·장치 표·레벨 데이터·외형 레지스트리·기본 인스펙터 참조.
- Resources.Load/LoadAll, Addressables 주소·AssetReferenceSprite·서브오브젝트, AssetBundle,
  문자열 경로·키와 switch/default, 직렬화된 기본 배열, 에디터 스포너·맵 미리보기.
- SpriteAtlas 원본과 Variant, packing 대상, .anim의 Sprite 키프레임, AnimatorController와
  AnimatorOverrideController의 원본/오버라이드, Playable·Timeline이 쓰는 해당 외형.
- Instantiate 팩토리, 풀의 프리웜·반납·OnEnable 재설정, DontDestroyOnLoad 캐시와 싱글턴,
  Addressables/Resources 로드 후 적용 코드, 원격/번들 콘텐츠 매니페스트와 배포된 카탈로그.
- LateUpdate/코루틴/상태 진입에서 sprite나 scale/rotation을 다시 쓰는 이전 시각 컴포넌트.

폴더명에 V12가 있다고 최신이라고 판단하지 않는다. animation_catalog.json과 manifest.json의
상대 경로·PNG SHA256 및 Unity의 GUID+subasset fileID를 함께 확인한다. 실제 생성 인스턴스의
Renderer가 참조한 sprite도 같은 최신 집합이어야 한다.

2. 원래 게임 동작을 유지하고 도감의 동작을 대조하라.
공통 07 무빙워크 / 09 단방향 문 / 18 튕김 모서리 / 19 제동판.
별길 목장 01 별돌 끼움홈 / 02 누름판·덩굴 다리 / 20 바람 통로 / 24 따라오는 병아리.
별돌과 홈, 누름판과 다리는 각각 같은 문서 ID의 두 외형 계열이다. 병아리를 장식 prop 한 장으로
누락하지 않는다. 장식 props/ranch_gate와 실제 단방향 문, 장식 풍차와 실제 바람 통로를 구분한다.

유효 스와이프·밀기 한 번은 코스트1이고, 처음부터 막힌 무효 입력은 코스트0이며 장치 위상도
진행하지 않는다. 하나의 자동 이동 연쇄에 추가 코스트를 부과하지 않는다. 실시간 경과나
애니메이션 완료 콜백으로 턴/강제 이동/다리 충돌/목표를 진행시키지 않는다.
기존 동작이 도감과 다르면 차이와 근거를 보고하고, 외형 교체 과정에서 몰래 새 규칙을 만들지 않는다.
도감의 옛 테마 이름은 현재 표시 이름과 대응하되 기존 ID를 보존한다. 픽셀·16색 제약은 적용하지 않는다.
도감 p8 별돌의 역방향 보조 화살표와 p7 제동판 그림의 축 혼동은 복제하지 않는다.

3. 방향은 실제 이동 벡터 한 곳에서 결정하라.
프로젝트의 격자 좌표/월드 좌표 변환을 확인하고, 실제 확정된 이동 벡터를 카탈로그의 east/north/
west/south로 변환한다. 화면 스와이프 y나 raw grid row 부호를 그대로 사용하지 않는다.
east는 예컨대 실제 동쪽 이동+동쪽을 가리키는 화살표+동쪽으로 열린 출력구가 함께 일치해야 한다.
수평/수직 구조는 각각 제작된 원화를 사용한다. 2.5D 전체 그림이나 그림자·캐릭터를 90도 돌려
세로 버전을 흉내 내지 않는다. 게임플레이 루트/Collider/격자 배치/저장 방향을 아트 때문에 돌리지 않는다.
방향이 없거나 0인 입력에는 임의 south/east fallback을 쓰지 말고 마지막 유효 방향·현재 상태를 유지한다.
필요한 키가 없으면 검수 실패와 진단을 내고 이전 모델·기본 프레임으로 조용히 돌아가지 않는다.

4. 각 장치의 최신 방향·상태·중간 프레임을 실제 이벤트에 연결하라.
07 무빙워크: 네 방향 구조·반복 화살표·벨트/판자 이동 위상이 같은 축/부호를 향하게 한다.
진입 후 인쇄된 방향으로 기존 연쇄 이동을 이어가고 끝/막힌 칸 직전 정지는 기존 판정이 담당한다.
시각 루프는 기존 작동 상태에서만 재생하며, 루프 한 바퀴가 이동 한 칸이라는 새 로직을 만들지 않는다.

09 단방향 문: 허용 이동 벡터에 맞는 기둥 배치와 열리는 문을 선택한다. 통로가 동서일 때의
기둥/개구부와 남북일 때의 기둥/개구부를 구분한다. 닫힘→중간→열림과 역방향 닫힘을 재생한다.
반대쪽 진입이나 반대편 막힘이 무효면 열기/코스트/턴을 실행하지 않는다. 열림 그림을 투명하게
숨기는 것으로 대체하지 않으며 Collider의 허용 판정은 기존 로직에 맡긴다.

18 튕김 모서리: 얇은 ㄴ자 가장자리와 작은45도 작동면, 중앙에 넓게 열린 통행 공간을 사용한다.
커다란 건초 상자/막힌 큐브/튀어나온 끝마개를 쓰지 않는다. ne/nw/se/sw 원화는 모서리 외형 방향
표기이며 실제 반사 입출력은 기존45도 면 규칙에 맞춰 대응시킨다. 강제 이동체가 닿을 때90도
꺾여 같은 연쇄가 이어진다. 좌우180도 반전 스프링으로 바꾸지 않는다. 다음 칸이 막히면 기존
안전 정지 규칙을 유지한다. 접촉 압축→반동→복귀를 재생하되 새 밀침 힘·코스트를 추가하지 않는다.

19 제동판: H/V는 진입 진행 축을 뜻한다. 두 개의 정지선은 그 진행 축을 가로막도록 수직으로
놓이며 운반 화살표를 쓰지 않는다. 눌림/멈춤 프레임과 이동 잔상의 종료를 같은 칸에서 보여준다.
이 장치는 기존 강제 이동을 그 칸에서 종료하며 반대 방향 이동/반발/한 칸 추가 이동을 만들지 않는다.

01 별돌/끼움홈: 돌 전체가 크림·회색 오각별인 최신 원화만 사용한다. 바위 원형 테두리나
노란 별이 박힌 바위로 돌아가지 않는다. 밀기의 월드 위치는 기존 확정된 밀기 tween이 담당하고
스프라이트 push는 접촉 피드백만 담당한다. 동일 문양 홈에는 seating 중간 프레임을 재생하고,
완료 상태는 바닥과 낮게 맞물린 통행 가능한 별 바닥으로 읽히게 한다. 돌이 실제로 움직이지
못한 입력에 seating/승리/소모가 발생하지 않아야 한다. 다른 문양의 처리는 기존 규칙을 유지한다.

02 누름판/덩굴 다리: 점유→누름판 하강과 연결된 다리 전개, 비점유→해제와 수축을 같은
권위 상태에서 표시한다. 가로2×1/세로1×2 원화를 구분하고 논리 점유는 실제 프로젝트와 대조한다.
시작·끝 두 지지대와 펼쳐지는 중간 구간이 단계별로 보이게 한다. 끝 상태 PNG 두 장만 바꾸지 않는다.
애니메이션이 늦거나 중단되어도 실제 통행 판정은 기존 상태를 따른다. 수축 시 위에 대상이 있을 때의
보호 규칙은 도감에서 미확정이므로 외형 작업으로 임의 낙하·압사·텔레포트를 추가하지 않는다.

20 바람 통로: 네 방향의 출력구·바람 리본·범위/타깃 표시가 실제 힘 방향과 일치해야 한다.
유효 행동이 끝난 뒤 범위 안 플레이어/가벼운 나무 상자를 한 칸 밀고, 금속 상자는 밀리지 않으며
뒤의 바람도 차단된다. 막힌 목적지에서는 그대로 정지한다. 바람 리본도 금속 뒤에서 끊기도록
기존 계산된 영향 칸을 시각화한다. 별도 state=flow_effect의 바람 전용16프레임은 몸체 없는 범위
오버레이다. 각 영향 칸의 별도 Renderer에서만 재생하며 emitter 몸체 Renderer를 flow_effect로
교체하지 않는다. 금속 뒤에는 이 오버레이도 표시하지 않는다. active는 통풍구 본체, flow_effect는
계산된 범위의 리본으로 구분하라. gust 루프는 해당 행동의 표현일 뿐 실시간 밀기 타이머가 아니다.
active/flow_effect는 loop=true이므로 시작 호출만 연결하지 말라. 해당 행동의 기존 시각 phase/tween이
끝나면 emitter를 같은 방향 idle로 SnapToState하고, 범위 오버레이는 Cancel 후 Renderer를 숨긴다.
Cancel만 호출하면 마지막 바람 이미지가 남으므로 범위 해제도 반드시 수행한다. 이 종료 처리는
기존 시뮬레이션 또는 시각 phase의 결과를 따르며 다음 턴/힘/코스트를 발생시키지 않는다.

24 병아리: north/east/south/west의 idle 및 실제 walk 프레임을 사용한다. north는 뒤통수/등이며
정면 눈을 붙이지 않는다. 눈이 보이는 방향에는 작은 흰 광채를 유지한다. 실제 확정된 경로의
각 구간을 따라가며 방향이 꺾일 때 그 구간 방향으로 바뀌고, 멈추면 마지막 방향 idle을 유지한다.
여러 칸 자동 이동은 최종 위치만 보고 직선 보간하지 말고 원래 실제 경로를 따른다. 무효 입력에는
따라오기/발자국을 추가하지 않는다. 길을 막거나 일반 누름판을 누르지 않으며 자체 코스트가 없다.
포털/도약/배/둥지 판정은 기존 동작을 유지하고 미확정 처리를 새로 만들지 않는다.

풍차/바람개비: 새 고정 몸체와 중심이 정확한 대칭4날개 로터를 별도 visual 자식으로 둔다.
로터 피벗에서 로터만 회전시킨다. 통합 풍차 그림이나 뒷 배경 섬 전체를 빙글빙글 돌리지 않는다.
장식용 회전은 timeScale/기존 Pause/reduced-motion을 따르며 실제 바람의 턴/힘을 발생시키지 않는다.

5. 실제 클립을 만들고 재생 책임을 한 곳으로 모아라.
동봉 Editor 생성기로 실제 .asset 카탈로그와 SpriteRenderer PPtr 키프레임 .anim을 생성한다.
메뉴 Tools/ANIMOL/Starway Ranch V12/Build selected animation_catalog.json에서 선택한 명세를
생성하거나, 아래 명령의 실제 Editor/프로젝트/Assets 경로를 대입해 실행한다.
"<UNITY_EDITOR_PATH>" -batchmode -projectPath "<PROJECT_PATH>" -executeMethod ANIMOL.Art.V12.StarwayRanchV12AnimationBuilder.BuildFromCommandLine -ranchV12Manifest "Assets/<실제설치경로>/ANIMOL_STARWAY_RANCH_CARTOON_V12/animation_catalog.json" -quit -logFile "<PROJECT_PATH>/Logs/ranch-v12-catalog-build.log"
이 명령은 자산 생성기만 실행한다. 실제 게임 이벤트 연결·레거시 이관·Play Mode 검증은 별도로
이 문서의 전 과정을 수행해야 한다. 실패를 무시하거나 코드0으로 바꾸지 않는다. 생성기 성공 로그와
_Generated 아래 파일 목록을 남기며, JSON 복사만으로 클립이 만들어졌다고 보고하지 않는다.
생성된 카탈로그의 SourceManifestSha256과 animation_catalog_sha256.txt를 대조하고, 시각 재생기의
expectedManifestSha256을 이 새 값으로 고정해 Configure/SnapToState한다. 예전 프리팹의 hash나
빈 값을 남기지 말라. Runtime catalog에는 프레임·부품만 직접 참조하며 정적 지형 전체를 메모리에
끌어들이지 않는다. 정적 지형/소품은 manifest.json의 최신 집합으로 별도 검증한다.
각 clip의 frames/fps/loop와 이미지 크기·PPU·pivot·SHA256를 대조한다. 원화 sources/를 Sprite로
잘라 쓰거나 아틀라스 전체를 프레임으로 지정하지 않는다. Atlas rotation/tight packing은 끈다.

시각 재생기는 프레임을 바꾸며 코스트·위치·충돌·장치 턴을 결정하지 않는다. 실제 이동/전환의
duration 또는 normalized progress에 동기화한다. Pause는 현재 프레임/경과를 고정하고 복귀 때
몰아서 건너뛰지 않는다. 반복 호출로 매 프레임0을 다시 시작하지 말고 상태/행동 ID가 바뀔 때만
전환한다. 중단/풀 반납/재사용/씬 복귀 때는 현재 권위 상태와 방향으로 초기화한다.
짧은 비루프 애니메이션이 끝나면 마지막 권위 상태를 유지하고, 종료 콜백으로 다음 턴을 호출하지 않는다.
Animator를 사용하는 프로젝트는 동일 카탈로그로 해당 시각 레이어의 키프레임/Override만 이관한다.
동일 Renderer를 Animator와 새 재생기가 동시에 덮어쓰지 않게 한다. 게임 로직을 포함한 전체
Animator/컴포넌트를 무조건 삭제하지 말고 sprite 쓰기 책임만 분리한다.

6. 레거시 시각 참조를 안전하게 끊어라.
교체 전 old asset GUID+subasset fileID+원본 경로+실제 사용처를 기록한다. 새 파일을 넣었다는
이유로 .meta를 전부 지우거나 GUID를 무작위 재생성하지 않는다. 같은 논리 자산의 안전한 원화
교체는 .meta를 유지하고, 다른 새 자산으로 옮기면 모든 구 참조를 새 GUID/fileID로 명시적으로 치환한다.
SpriteSheet slicing이 바뀌면 GUID만 같아도 fileID가 다를 수 있으므로 모든 PPtr을 따로 검증한다.

V12 폴더의 endpoint aliases는 V12 프레임의 복사본이며 과거 원화가 아니다. 실제 방향/작동은
animation_catalog.json의 정확한 키로 선택한다. V10/V11/old/default/Resources/임시 원본을
찾는 체인, 없는 방향에서 front만 재사용하는 체인, SetSprite(null) 후 옛 기본 이미지를 복구하는
체인, 캐시된 old Sprite/Animator를 되살리는 코드를 목장 범위에서 제거한다.
전역 기본값이 다른 테마와 공유되면 목장용 레지스트리/Prefab Variant를 분리해 다른 테마를 보존한다.

정적 직렬화 참조, 코드의 문자열 로딩, 원격 카탈로그, 런타임 로딩/풀 재사용을 모두 검사한 뒤
목장에 한정해 참조0인 레거시 시각 자산만 제거한다. 삭제 전 dry-run 목록과 의존성 보고서를
남긴다. 프로젝트 전체의 Old/Legacy 폴더, 다른 테마 공유 원본, 실제 게임 로직은 일괄 삭제하지 않는다.
유일한 최신 키가 없거나 바인딩 미완이면 Editor/빌드 검수를 실패시키고 원인을 보고한다.
프레임 누락을 숨기기 위해 구버전 모델이나 임시 기본 프레임으로 계속 실행시키지 않는다.

7. 크기·정렬·기존 지형과 배경을 보존하라.
PPU256과 파일별 canvas/pivot/logical rect를 그대로 임포트한다. 장치의 여백을 footprint로 삼거나
2칸 아트를 한 칸으로 재축소하지 않는다. 세로 다리 원화의1×2 슬롯은 기존 실제 점유 방향과 대조한다.
병아리의 .62는 visual 자식에 정확히 한 번만 적용하고 루트/충돌/추종 거리에는 적용하지 않는다.
기존 접지 anchor 방식과 기존 pivot 방식 중 한 가지만 사용한다. 모든 병아리 프레임은 동일
canvas/pivot/contact 계약을 쓰며 프레임마다 임의 접지 보정이나 bounds 기반 배율을 계산하지 않는다.

G=잔디/W=목재 다리/S=석재 다리이며 S를 G로 정규화하지 않는다. 기존 organic256의8이웃,
합쳐진1~4칸 하부, 긴 구간의 고정 seed 군집, 얕은 연결띠, 다리/난간 연결 규칙을 유지한다.
입체 잔디는 독립 오버레이이고 동서쪽 풀을90도 돌리지 않는다. 승인된 차분한 잔디 상면은
이미 최신 집합의 일부이므로 단순히 예전 바이트와 같다는 이유로 다시 만들지 않는다.
거의 고정된 별은 구름 뒤에 두며 달/행성은 없다. 구름과 섬의 독립 깊이/움직임 및 기존 카메라,
Z·Sorting Layer·연결된 하부의 그리기 순서를 보존한다. 게임플레이 루트 아래 새 카메라를 만들지 않는다.
