ANIMOL 잔영 극장 V03

잔영 극장의 공통 장치4종과 전용 장치7종을 방향별 원화와 실제 중간 프레임으로 교체하는 패키지다.
회전 책장은 고정 중앙 핀을 기준으로 지면에서 가로↔세로90도 회전한다. 주사위는6면 전체의
24가지 방향과96개의 유효 굴림 전환을 구분한다. 이전의 정적 상태 PNG만 있는 V02 지시를 대체한다.
별길 목장 V12와 다른 테마의 원화는 이번 작업에서 변경하지 않는다.

그림체
굵고 각진 남색 외곽선, 넓은 단색 면, 명확한 다각형 셀 음영을 사용한다. 버건디·자주색 벨벳,
무광 금색 도장 목재·크림색으로 극장 소품과 어울리게 한다. 픽셀/16색 제약은 적용하지 않는다.

최신 집합
manifest.json이 승인된 지형·배경·소품과 모든 런타임 프레임의 전체 목록이다.
animation_catalog.json은 장치별 방향·상태·시퀀스의 유일한 시각 목록이다. 정적 지형 전체를
애니메이션 카탈로그에 참조하지 않는다. 같은 경로의 endpoint alias도 새 프레임으로 덮었다.
별도 옛 폴더/default/front 이미지로 돌아가는 fallback은 허용하지 않는다.
기존 승인된 극장 지형·배경·소품은 V03 최신 집합에 유지한다. 바이트가 같다는 이유로 삭제하지 않는다.

장치
04 교대 셔터: 가로/세로 구조와 열림 중간 단계, 역순 닫힘.
06 행동 연동 이동 무대: 기본2×1 무대가 네 방향으로 움직이는 그림. 이동 방향과 점유 형태를
혼동하지 않는다. 선택적1×2 원화는 실제 프로젝트가 그 점유 형태를 지원할 때만 연결한다.
08 회전 책장: 중앙 핀 고정, H2×1↔V1×2, 대각 중간 원화. 회전 합집합 캔버스는 새 충돌2×2가 아니다.
13 도미노 벽: 방향별 패널의 순차 넘어짐과 낮은 통행 바닥. H704×448/V448×704는 판의 높이
표현을 위한 여백이며 바닥 아트 슬롯2×1/1×2를 늘리지 않는다. 복구 동작을 새 게임 규칙으로 만들지 않는다.
17 돌진 석상: 네 방향 대기·경고·돌진·충돌·복귀 표현. 월드 이동은 기존 확정된 경로가 담당한다.
22 주사위 블록:24개 안정 방향과96개 방향 전환. 실제6면 배치가 권위 상태다. 굴림 중에는 극장
덮개가 숫자를 가리며, 시작/종료면은 정확한 실제 방향이다. 원화로 만든 숫자 부품을 면에 합성한다.
23 겁쟁이 인형: 네 방향 시선과 동작. 플레이어를 보는 방향과 도망 이동 방향은 서로 반대다.
07/09/18/19 공통: 축에 맞는 무빙워크·단방향 문, 넓게 열린 얇은 ㄴ자, 진행 축을 가로막는 제동선.

Unity 연결
PPU256, 파일별 canvas/pivot/logical rect를 유지한다. 책장 union/sweep와 실제 점유를 구분한다.
같은 SpriteRenderer에 Animator와 새 재생기가 동시에 쓰지 않게 한다. 실제 행동·전환 시간에
프레임 재생을 동기화하고, 시각 콜백으로 코스트·턴·좌표·충돌·목표를 진행시키지 않는다.
Editor 생성기는 실제 프로젝트에서 .asset 카탈로그와 .anim을 생성한다. 동봉 C#은 연결용 소스다.
실제 테마 ID·장치 enum·이벤트·프리팹 경로는 추측하지 않았다. device_bindings_template.json의
미확인 항목을 실제 소스 증거로 채운다. 상세 작업은 UNITY_APPLY_PROMPT_KO.txt를 따른다.

보존할 배경과 지형
G=stage_floor, W=wood_catwalk, S=velvet_carpet. 극장의 S는 지지대 선택에서 G로 정규화한다.
목장의 S=stone_bridge 규칙을 여기로 복사하지 않는다.8이웃 타일·연결된 하부·목재 통로와 난간,
독립 소품·별·구름·섬의 깊이와 움직임은 유지한다. 별은 모든 구름 뒤에서 거의 고정되며 달/행성은 없다.

검증 범위
동봉 영상과 GIF는 제공 PNG를 재생한 합성 검토 자료이며 실제 게임 녹화가 아니다.
파일/SHA/프레임 차이/방향/메타데이터/주사위 수학/합성 화면을 오프라인에서 검사한다.
원 Unity 프로젝트가 없어 import/compile/Play Mode/실제 씬 연결·레거시 참조0은 NOT_RUN이다.
required_gameplay_checks.json의 미실행 항목을 실제 프로젝트에서 실행하고 증거를 남겨야 한다.
