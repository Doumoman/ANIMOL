ANIMOL 별길 목장 — 연결 장식·여러 칸 장식 V01 실제 적용 지시

목표는 새 콘텐츠나 게임 규칙의 추가가 아니라, 목장 장식이 한 칸마다 끊겨 보이거나 큰 PNG가 한 칸에 축소되는 문제를 해결하는 것이다. 제공된 새 장식 PNG와 연결·배치 코드를 실제 프로젝트에 설치하고 기존 장식 생성기의 사용 경로에 연결하라. 원화를 다시 생성하라는 지시가 아니다.

실행한 작업만 PASS, 실행하지 않은 항목은 NOT_RUN으로 보고하라. 지금 제공본은 실제 Unity 프로젝트가 없는 환경에서 제작되었다. 파일 검수·그림·소스 읽기 결과를 import/컴파일/Play Mode 성공으로 바꾸지 마라.

1. 실제 장식 배치 경로를 조사하라.

별길 목장의 실제 theme key, 장식 ID, 배치 데이터/SO/Prefab/Scene, 맵 생성기, 청크 renderer, Resources/Addressables, 풀과 undo/load 경로를 조사해 표로 남겨라. 연결용 장식 맵과 게임 통행·충돌 맵을 구분하라. 기존 V12의 props_manifest에는 이미 2×1 울타리·벤치·여물통, 2×2 나무와 3×2 헛간이 있으므로 모든 원본 이미지가 1칸이라고 단정하지 마라.

특히 다음을 실제 코드에서 찾아 확인하라.
- Sprite bounds를 기준으로 모든 그림을 같은 타일 폭·높이에 맞추는 fitToCell/autoScale/alphaBounds 보정.
- 2×1·3×2 크기를 무시하고 앵커를 한 셀로 저장하는 데이터 변환.
- 큰 장식의 예약된 각 셀에서 같은 Prefab을 다시 만드는 반복문.
- 울타리·돌담·화단을 이웃과 무관하게 같은 단독 PNG로 고르는 selector.
- 현재 청크 밖 이웃을 빈칸으로 처리해 청크 경계에 끝기둥을 만드는 조회.
- 기존 bridge_decor가 그린 다리 경계 난간과 새 울타리가 겹쳐지는 경로.

이 목록은 조사 대상이지 현재 코드에 그 결함이 있다고 확인한 보고서가 아니다. 발견한 실제 경로·파일·재현 장면을 근거로 수정하라.

2. 새 장식 추가본만 설치하라.

ANIMOL_STARWAY_RANCH_CONNECTED_DECOR_V01 폴더를 Assets 아래의 새 경로에 넣는다. 기존 V12 전체 파일을 재설치해서 최신 장치 패치를 되돌리지 마라. 바람개비/바람 영역/일방향 문/병아리, 실제 플레이어와 장치 동작, 테마 ID, 맵·세이브·해금·통행 규칙, UI·다른 테마·바닥·배경을 유지하라. 이름에 old/legacy가 있다는 이유로 폴더를 통째 삭제하지 마라.

기존 장식의 실제 ID에서 새 visual family/group key로 가는 명시적인 매핑을 만들어라. 잘못된 전역 문자열/GUID/.meta 치환으로 장치나 다른 테마를 바꾸지 않는다. 같은 새 장식 추가본을 갱신할 때는 그 파일의 .meta를 보존한다. 실제 ID가 확인되지 않은 필드는 임의로 채우지 마라.

원본 파일명 기준의 시각 매핑 후보는 다음과 같다. 이 파일명을 실제 gameplay ID로 간주하지 말고 현재 데이터에서 대응 관계를 확인하라.
- fence_horizontal/fence_picket_horizontal의 2×1 장식은 같은 그룹의 cream_fence 두 셀로, fence_vertical의 1×2 장식은 세로 두 셀로 구성할 수 있다.
- stone_wall의 2×1 장식은 meadow_stone_wall 두 셀로 구성할 수 있다.
- yellow_flowers/clover_flowers 등 연속 화단으로 쓰던 셀은 raised_flower_meadow와 명시적 연결 그룹으로 구성할 수 있다. 바닥에 같은 풀 색이 있다는 이유로 전체 바닥을 화단으로 등록하지 않는다.
- hay_pair 2×1, clover_tree 2×2, ranch_barn 3×2는 각각 새 hay_store_2x1/tree_flower_corner_2x2/barnyard_3x2 후보와 지면 크기를 대조한다.
- water_trough 2×1을 feeding_corner_3x1로 바꾸려면 추가 한 칸까지 실제로 허용되는 배치 위치를 확보해야 한다. 자리가 없다고 새 그림을 2×1 또는 1×1로 줄이거나 길을 새로 막지 마라.
- ranch_gate, windmill, chick처럼 실제 장치·문·추종자와 연결될 수 있는 항목은 일반 울타리 매핑에 섞지 않는다. 현재 프로젝트에서 기능을 확인하고 기존 최신 시각 경로를 유지한다.

새 namespace: ANIMOL.Art.RanchConnectedDecorV01
manifest: ANIMOL_STARWAY_RANCH_CONNECTED_DECOR_V01/manifest.json
pin: ANIMOL_STARWAY_RANCH_CONNECTED_DECOR_V01/manifest_sha256.txt

현재 제공 CatalogBuilder의 무인자 명령 진입점:
"<UNITY_EDITOR>" -batchmode -quit -projectPath "<UNITY_PROJECT>" -executeMethod ANIMOL.Art.RanchConnectedDecorV01.RanchConnectedDecorV01CatalogBuilder.BuildFromCommandLine -ranchDecorManifest "Assets/<실제부모>/ANIMOL_STARWAY_RANCH_CONNECTED_DECOR_V01/manifest.json" -logFile "<LOG_DIR>/RanchConnectedDecorV01_Catalog.log"

설치한 최종 소스의 클래스명·flag와 이 명령이 같은지 확인한다. 이 명령문을 제공했다는 사실은 컴파일 성공의 근거가 아니다. 성공 후 _Generated/RanchConnectedDecorV01Catalog.asset과 실제 빌드 보고서를 확인하고 catalog/pin을 함께 연결한다. 실패 시 옛 Sprite로 대체하거나 SHA/GUID/fileID 검증을 끄지 마라.

3. Sprite의 지면 크기와 피벗을 그대로 사용하라.

새 PNG는 Sprite Single/FullRect, 선언된 PPU256·pivot, Bilinear, Clamp, 무압축, mipmap 없음으로 임포트한다. Sources/Authoring/Inspection 및 원화 아틀라스를 장식 Sprite 후보에 넣지 않는다.

논리 256px는 world1칸이다. 연결 셀의 일반 320×320/[32,32,256,256] 계약을 기존 모든 PNG에 일괄 적용하지 마라. 옛 장식에는 8~10px 여백과 다른 커스텀 pivot도 있다. 새 추가본의 각 logicalRect/footprintCells/pivot만 정확히 적용한다.

큰 그림 전체를 한 타일 폭으로 맞추지 마라. native artwork의 지면은 footprintCells만큼 유지하고 위로 튀어나온 수관·지붕·풀 끝은 그대로 허용한다. logicalRect는 지면 정보이며 PNG를 그 사각형으로 잘라서 돌출을 없애라는 뜻이 아니다.

큰 장식은 아래 key를 그대로 사용한다.
- hay_store_2x1: 지면 2×1
- feeding_corner_3x1: 지면 3×1
- tree_flower_corner_2x2: 지면 2×2
- barnyard_3x2: 지면 3×2

각 placementId는 앵커 하나와 전체 footprint를 가진다. 모든 후보 셀을 host의 실제 장식 허용 조건으로 먼저 검사하고, 한 칸이라도 불가능하면 전체 배치를 거절한다. 일부 셀만 예약하거나 그림을 작은 크기로 몰래 줄이지 마라. 성공 시 전체 장식 셀을 한 placement의 소유로 예약하되 renderer는 하나만 생성한다. 삭제·undo·재배치·풀 반환에서는 그 placement의 모든 장식 예약과 renderer를 함께 정리한다.

hostAllowDecorCell은 부작용 없는 검사 함수로 구현하라. 검사 콜백 안에서 실제 맵이나 예약 목록을 먼저 수정하면 전체 계획이 거절될 때 부분 점유가 남을 수 있다. 모든 검사와 새 계획의 성공을 확인한 뒤 host의 단일 확정 경로에서 필요한 장식 예약만 함께 반영하라.

장식 예약이 게임 충돌 점유를 자동 변경해서는 안 된다. 제공 JSON의 actualGameplayFootprintCells:null은 미검증을 뜻한다. 기존 호스트가 장식을 실제로 막는지/통과시키는지 조사하고 보존한다. Sprite alpha로 Collider/Blocker를 만들거나 플레이어 경로를 새로 막지 마라.

4. 실제 이웃에 따라 연결 그림을 고르라.

한 이웃의 family·connectionGroup·논리 장식 logicalLayer·정수 heightKey가 모두 같을 때만 연결한다. 논리 장식 logicalLayer는 Unity Sorting Layer 이름과 구분하라. 격자 좌표와 높이는 명시적인 데이터를 사용하고, float worldZ의 근사 비교로 연결 그룹을 정하지 마라.

같은 울타리 띠·돌담 띠·화단 영역으로 이어질 모든 셀은 같은 connectionGroup을 공유해야 한다. 각 셀의 고유 instanceId나 placementId를 connectionGroup에 넣지 마라. 그러면 셀마다 다른 그룹이 되어 이웃이 모두 끊기고 끝 타일로 선택된다. 서로 분리할 영역에만 다른 connectionGroup을 주고, 큰 장식의 placementId는 장식 그룹 하나당 유일하게 유지한다.

cream_fence와 meadow_stone_wall의 비트는 N1 E2 S4 W8이다. n00은 단독, n05는 남북 직선, n10은 동서 직선, n03/n06/n12/n09는 네 꺾임, n07/n14/n13/n11은 네 T, n15는 십자다. 경로는 decor/connected/<family>/n00..n15.png이다. 같은 family라도 다른 연결 그룹/높이면 실제 경계를 닫고 서로 다른 skin을 임의로 잇지 않는다.

raised_flower_meadow는 N1 NE2 E4 SE8 S16 SW32 W64 NW128의 raw8비트다. 경로는 decor/connected/raised_flower_meadow/n000..n255.png이다. 연결된 내부 셀 사이에 테두리를 그리지 않고, 실제 빈칸과 안쪽 구멍에만 해당 native 마감을 남긴다. 대각만 있는 경우를 cardinal 연결로 추측하지 마라. 모서리/구멍/투명 여유의 알파 소유 규칙은 제공 family metadata와 검수 예시를 따른다.

끝기둥·모서리·분기의 기둥은 정확히 한 번만 둔다. 직선의 각 타일 양끝마다 기둥을 다시 만들지 않는다. 긴 직선의 보강 기둥·희소 꽃은 월드 격자 좌표와 고정 seed로 안정적으로 선택한다. 매 프레임 난수, 화면 밖 재진입, 카메라 청크 원점을 기준으로 모양이 바뀌게 하지 마라.

실제 전체 장식 맵에서 이웃을 조회한다. 현재 renderer가 가진 청크만 검사해서 가짜 끝부분을 만들지 마라. 배치·삭제·그룹/높이 변경·undo/load 후에는 본인 셀뿐 아니라 영향받는 직교·대각 이웃과 긴 직선 보강 기둥도 일관되게 갱신한다. 지금 제공 controller의 전체 layout 갱신을 연결했다면 host의 확정된 맵 이벤트에서 그 경로를 호출하라. 프레임마다 새로운 맵을 생성하는 방식은 쓰지 않는다.

위에서 아래로 row가 증가하는 host라면 RanchConnectedDecorV01Planner.FromRowDownCell(column,row)와 FromRowDownGroupBottomLeft(leftColumn,topRow,heightCells)를 구분해 사용한다. 큰 장식의 왼쪽 위 앵커에 y부호만 바꾸어 왼쪽 아래 앵커라고 전달하지 마라. host가 셀 중심을 origin으로 쓰는지 지면 경계를 origin으로 쓰는지 대조하여 worldOrigin과 반 칸 오프셋을 한 번만 맞춘다.

제공 helper에서 셀 변환은 (column,-row), 큰 그룹의 왼쪽 아래 변환은 (leftColumn,-topRow-heightCells+1)이다. Controller의 worldOrigin은 격자 셀(0,0)의 왼쪽 아래 경계다. host가 보드의 왼쪽 위 경계를 origin으로 갖는다면 RanchConnectedDecorV01Controller.RowDownTopLeftToWorldOrigin(boardTopLeft,cellSize)로 y에서 한 칸을 뺀 경계 원점을 구해 전달한다. 같은 보정을 두 번 적용하거나 row0 전체를 한 칸 잘못 내리지 않도록 첫 셀과 3×2 그룹의 전체 지면을 동시에 확인하라.

5. 새 장식 시각의 소유자를 하나로 정하라.

새 controller에 최신 catalog와 manifest SHA 핀을 연결하고, 실제 host가 확정한 연결 셀·큰 장식 placement·world grid origin/cellSize·장식 허용 조건을 전달한다. 최종 제공 소스의 Configure/SetLayout API 및 데이터형과 맞춰 연결하라. 기존 코드를 추정한 가짜 event명이나 실제로 없는 ID를 추가하지 마라.

제공된 RanchConnectedDecorV01Controller의 명시적 연결 API는 다음과 같다. 변수 값은 실제 프로젝트에서 조사한 catalog·핀·정렬층·전체 장식 맵과 좌표를 전달한다.
Configure(RanchConnectedDecorV01Catalog latest, string pinnedManifestSha256, string actualSortingLayerName)
SetLayout(IList<RanchDecorNetworkCell> networkCells, IList<RanchDecorGroupPlacement> groupPlacements, Vector3 worldOrigin, float cellSize, Func<RanchDecorClaim,bool> hostAllowDecorCell, int seed=0, int postSpacing=4)

두 메서드의 bool 결과와 LastDiagnostic을 확인한다. CurrentPlan의 claims는 시각 장식 예약 정보이며 게임 점유에 자동 등록된 결과가 아니다. 큰 장식의 anchorX/anchorY는 왼쪽 아래 셀 인덱스이고, 배치 중심은 anchor+(width/2,height/2)다. Network cell은 해당 셀의 (x+0.5,y+0.5)에 놓인다. worldOrigin은 이 인덱스 공간의 지면 경계 원점과 맞춘다.

연결 데이터는 RanchDecorNetworkCell의 x/y/family/connectionGroup/logicalLayer/heightKey와 필요 시 실제 sortingOrder/worldZ를 사용한다. 큰 장식은 RanchDecorGroupPlacement의 유일한 placementId/groupKey/anchorX/anchorY/logicalLayer/heightKey를 사용한다. 논리 연결 판정용 heightKey와 시각 깊이 worldZ를 같은 의미로 취급하지 마라. 장식 셀 입력과 큰 그룹은 같은 logicalLayer/heightKey에서 겹치지 않아야 한다. 의도적으로 층을 겹치는 경우도 host의 명시적 허용 조건을 거쳐라.

postSpacing은 3 또는 4만 사용한다. ClearLayout()은 이 component가 소유한 시각과 현재 계획만 비운다. OnDisable 후 재활성에서는 옛 layout을 자동 부활시키지 않으므로 실제 host의 현재 데이터로 Configure 후 SetLayout을 다시 전달하라.

SetLayout에 잘못된 snapshot을 전달하면 새 계획을 적용하지 않고 이 component가 소유한 이전 시각까지 지우는 fail-closed 정책이다. 이전 유효 시각을 계속 유지한다고 가정하지 마라. 실제 host가 무효 이동을 커밋하지 않아 SetLayout 호출을 생략하는 경우에는 기존 시각이 남는 것이 정상이며, 이 두 경우를 구분해 시험하라. 거절된 snapshot 이후에는 LastDiagnostic을 확인하고 유효한 최신 전체 snapshot을 다시 전달한다.

기존 장식 생성기·풀·Animator·Addressables가 같은 장식을 동시에 그리지 않도록 소유자를 정한다. 현재 목장의 대상 장식 시각 경로만 새 controller로 넘기고, 다른 시각이나 게임 로직의 소유권을 빼앗지 않는다. 새 renderer를 한 번 표시했더라도 OnEnable/Start/풀에서 옛 단독 Sprite로 덮어쓰는 경로를 확인하라.

맵 갱신 때 삭제된 renderer를 Destroy 지연 시간 동안 그대로 보여 겹치지 않도록 즉시 숨긴 뒤 정리한다. 빈 layout, 잘못된 manifest/pin/파일, 잘못된 footprint, pool disable/재사용, undo/load 뒤의 이전 시각·예약 잔류를 확인한다. 누락된 새 파일을 옛 단독 Sprite로 대체하지 마라.

6. 실제 화면과 로그로 마무리하라.

Unity를 실행하기 전에 제공된 오프라인 파일 검사도 수행하라. 패키지 루트에서 실행하며 Python과 Pillow가 필요하다. INGAME 설치본은 선택 원화를 요구하지 않는 다음 명령을 사용한다.
python QA/verify_addon.py --package "<패키지 루트>" --runtime-only

원화까지 합친 전체판은 다음 명령을 사용한다.
python QA/verify_addon.py --package "<패키지 루트>"

제작 환경의 전체 조립본은 runtime PNG 298개와 native 원화 11개에 대해 이 파일 검사를 PASS_OFFLINE으로 통과했다. 이는 PNG·목록·메타데이터·해시 및 일부 정적 소스 검수 결과이며 Unity import/컴파일/실제 배치/Play Mode 결과가 아니다. 실제 설치한 바이트로 다시 실행한 결과와 뒤의 Unity 검증 결과를 분리해 보고하라.

별길 목장의 기존 생성 결과 및 수동 검수 맵에서 다음을 확인하라.
- 한 칸 단독, 가로·세로 2/3/4칸, 네 꺾임, 네 T, 십자, 긴 직선.
- 화단의 2×2 연결, 한 칸 구멍, 대각만 붙은 모양, 얇은 목과 오목한 부분.
- 연결 그룹·family·layer·높이가 다른 셀이 닿은 경우와 음수 좌표·청크 경계.
- 2×1/3×1/2×2/3×2 그룹마다 전체 footprint 예약과 정확히 renderer 하나.
- 일부 셀이 허용되지 않는 큰 장식의 원자적 거절, 중복 placementId, 예약 누수.
- 배치·삭제·undo/load·풀 반환·비활성 후 재활성·빠른 연속 수정에서 이전 시각 잔류 없음.
- Bilinear 확대/축소에서 틈, 내부 끝기둥, 겹친 AA 선, 잘린 입체 풀 끝과 지붕 없음.
- 기존 bridge_decor 난간과 새 울타리 중복 없음, 기존 병아리/문/바람/장치 동작과 비용 유지.

수동 아트 예시가 아닌 실제 게임 Scene의 전체 화면, 그리드 표시 화면, 긴 연결부 확대, 모든 큰 장식의 footprint 화면을 남겨라. 변경 파일·기존 ID→새 visual 매핑·catalog/pin·실제 import/컴파일/Play 로그를 보고한다. 실제 현재 사용 참조를 검사한 근거가 있어야 '대상 장식의 옛 시각 참조 0'이라고 쓴다. 실행하지 못한 검증은 NOT_RUN, 실제 host 정책이 없어 진행할 수 없는 부분은 BLOCKED_PRECONDITION으로 남기되 확정된 나머지 적용은 계속하라.
