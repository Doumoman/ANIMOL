ANIMOL 별길 목장 장치 V13 R3 적용 명령문

현재 Unity 프로젝트의 AGENTS.md와 기존 입력/이동/맵/장치/Undo/수문 표현 코드를 읽고 아래 수정본을 적용하라.
이번 범위는 수로 피드백 개선, 물웅덩이→구덩이 물 이동, 가로·세로 배치 지원이다. 양의 R2 수정도 유지하라.
최신 규칙은 DEVICE_RULES_KO.txt / UPDATE_R3_RULES_KO.txt다.

1. 패키지 교체와 카탈로그 재생성
- 기존 Assets 내 ANIMOL_STARWAY_RANCH_DEVICES_V13 폴더에 이번 파일을 병합하고 기존 .meta/GUID를 보존한다.
- 새 폴더를 다른 위치에 하나 더 설치해 같은 클래스/장치가 중복되지 않도록 기존 설치 위치부터 찾는다.
- animation_catalog.json, catalog_sha256.txt, Runtime, Editor, 새 Sprites/pond_transfer, 기존 가로 수문 6개를 함께 갱신한다.
- Sprite 325개 / 클립 정의 158개, installationRevision 3이다. 최신 Pin과 카탈로그를 혼용하지 않는다.
- PPU256, 중앙 Pivot(.5,.5), FullRect, Bilinear, 무압축, Mipmap Off다.
- 1×1 PNG320×320, 가로2×1 PNG576×320, 세로1×2 PNG320×576을 그대로 가져온다.
- 기존 V13 빌더는 footprint 기반으로 1×2도 수용한다. 이미지 크기를 576×320으로 강제하지 않는다.
- Tools > ANIMOL > Ranch Devices V13 > Build catalog, clips and inspection prefab에서 이번 animation_catalog.json을 선택한다.
- _GeneratedV13/RanchDevicesV13Catalog.asset과 InspectionOnly_AllClips.prefab을 재생성한다.
- 무관한 다른 에셋을 삭제하지 않는다. 옛 InspectionOnly_All137Clips.prefab을 최신 검사 보드로 사용하지 않는다.

선택적 빌더 실행:
"<Unity Editor>" -batchmode -quit -projectPath "<project>" -executeMethod ANIMOL.Editor.RanchDevicesV13.RanchDevicesV13Builder.BuildFromCommandLine -ranchDeviceCatalog "Assets/<existing path>/ANIMOL_STARWAY_RANCH_DEVICES_V13/animation_catalog.json" -logFile "<log>"

2. 수문 배치 데이터 — 가로/세로
- 인스턴스별 두 셀 A/B 좌표와 wetA를 저장한다. 두 셀은 상하 또는 좌우로 정확히 한 칸 이웃해야 한다.
- A/B의 순서를 새로 강제하거나 저장된 물 위상을 좌표 정렬만으로 뒤집지 않는다.
- 가로는 점유2×1, 세로는 점유1×2다. 연결 수로는 두 칸 안에 포함되고 별도 세 번째 칸을 차지하지 않는다.
- 커널 좌표는 +Y=북이다. 프로젝트가 배열 행 +1=아래를 사용하면 어댑터에서 북/남 부호를 변환한다.
- 기존 배치 도구가 수평만 허용한다면 두 인접 셀 또는 horizontal/vertical 선택을 지원하도록 확장한다.
- 수평 검사로 dy==0만 통과시키던 호스트 코드를 찾아 상하 인접도 허용한다. 대각선과 두 칸 간격은 거절한다.
- 수문/양의 공식 정의 ID는 기존 프로젝트 정의를 사용하며 패키지에서 새 번호를 임의로 붙이지 않는다.

3. 이동 판정과 물 방향
- 플레이어가 짝의 마른 칸에서 짝 물칸으로 입력할 때 TryCrossPond를 일반 물칸 거절보다 먼저 검사한다.
- 기본 교환은 출발 칸 물참 + 도착 칸 물빠짐 + 플레이어 도착 이동의 원자적 성공이다.
- 목적지 점유/추가 침수 객체 정책을 먼저 확인한다. 실패는 상태/코스트/턴/물 흐름 효과 모두 0이다.
- 출발 플레이어는 떠나는 객체이므로 침수 차단으로 세지 않는다. 도착 칸은 같은 교환으로 말라지므로 기존 물 차단만으로 거절하지 않는다.
- result.actualRoute는 플레이어 [행동 전 Dry, 행동 전 Wet]다.
- 새 result.waterRoute는 물 [행동 전 Wet, 행동 전 Dry]다. 물 이동에는 actualRoute를 그대로 사용하지 않는다.
- 수평 예: 서쪽마름·동쪽물 → 플레이어동쪽 / 물서쪽.
- 수직 예: 남쪽마름·북쪽물 → 플레이어북쪽 / 물남쪽.
- 반대 초기 위상은 반대로 작동한다. 위로 이동하는 물도 퍼즐의 동일한 교환 규칙으로 허용한다.
- NotApplicable은 기존 일반 판정으로 보낸다. 외부 바닥에서 물칸으로 들어가는 입력을 무조건 교환으로 처리하지 않는다.
- 원 프로젝트의 권한 있는 상태/Undo/회계에서 한 번만 확정한다. 참조 BoardR2를 별도 실시간 보드로 운영하지 않는다.
- 코스트 1/장치 턴 1을 입력 회계 또는 커널 delta 중 한 경로로만 적용한다. 애니메이션에서는 과금하지 않는다.

4. 새 수로 표현 연결
- 기본 표현은 Runtime/RanchPondSluiceVisualR3.cs와 전용 자식 RanchDeviceVisualV13 하나다.
- 자식 렌더러는 쌍의 월드 중심에 둔다. X/Y 스케일을 동일하게 적용하고 회전은 0이다. 논리 루트/콜라이더를 애니메이션으로 이동하지 않는다.
- Configure(catalog, dedicatedChild, pairSnapshot, out error)로 구성한다. RulesR2 어셈블리와 새 RanchPondPresentationR3.cs도 함께 포함한다.
- 정지 상태는 SetResolvedState(authoritativePairSnapshot)로 표시한다.
- 교환 성공 후 PlayCommittedTransfer(beforePairSnapshot, afterPairSnapshot, committedResult, out error)를 호출한다.
- before는 변경 전 별도 스냅샷이어야 한다. after와 같은 변형된 객체를 넘기지 않는다. pair.Copy() 등을 사용한다.
- 표현기는 물 경로/플레이어 경로가 반대인지, 실제 성공 이벤트인지 검사한다. 실패 이벤트로 물을 흘리지 않는다.
- 현재 물칸→마른 칸 방향은 RanchPondPresentationR3.TryCue(before, ...)가 좌표로 결정한다. A가 언제나 서쪽/남쪽이라고 가정하지 않는다.
- 가로 클립: pond_pair/horizontal/west_wet, east_wet, water_west, water_east.
- 세로 클립: pond_pair/vertical/north_wet, south_wet, water_north, water_south.
- 물 수문 클립은 열림→수로 흐름→수위 이전→닫힘, 12프레임/12fps다. 마지막 그림을 새 정지 키로 바꾼다.
- 같은 1초 구간에 플레이어 전용 시각 자식을 result.actualRoute로 반대 방향 이동시킨다. 기존 연출 속도 체계에 맞추되 물/플레이어의 방향은 유지한다.
- 기존 RanchCommittedMotionV13을 쓰면 실제 경로의 월드 중심과 1칸당 1초를 전달하고, 게임플레이 루트를 먼저 확정된 목적지에 둔다.
- 렌더러 하나에 2칸 합성 그림을 표시한다. R2 RanchPondPairVisualR2의 두 셀 렌더러와 기존 물 오버레이는 해당 인스턴스에서 비활성화해 중복 표시를 막는다.
- R2의 셀별 표현은 호환용이다. 이번 수로 피드백을 사용하려면 R3 합성 표현으로 연결해야 한다.
- 옛 pond_pair/cross_a_to_b 등 키는 수평 호환 별칭이다. 그 이름은 플레이어 이동이며 물은 반대다. 새 연결은 축/물 방향이 명시된 R3 키를 사용한다.
- 세로 그림을 회전한 가로 그림으로 대체하지 않는다. 오프라인 미리보기의 화살표/P 문자를 런타임 장치에 추가하지 않는다.
- OnDisable/Undo/Reset/Load/오브젝트 풀 복귀에서는 Clear로 연출을 취소하고, 다시 켤 때 권한 있는 현재 물 위상을 SetResolvedState로 적용한다.
- 빠른 재입력/연쇄의 연출 대기는 기존 호스트 방식을 따른다. 클립 완료에서 다음 장치 턴을 자동 발생시키지 않는다.

5. 양과 나머지 장치 유지
- 직접 양 밀기는 플레이어 제자리, 양만 한 칸 이동한다. 기존 공용 PushHandler의 플레이어 전진을 이 장치에서 억제한다.
- 풀에 닿으면 그 풀과 양을 모두 제거하고 바닥을 남긴다. 양은 바람 영향을 받고 처음 만난 풀에서 먹고 사라진다.
- 유효한 직접 입력 1회 비용, 바람 자동 연쇄 추가0, 실패0 규칙을 유지한다.
- 참조 TryPushSheep/TryWindSheep와 RanchSheepConsumptionVisualR2를 기존 실제 맵/엔티티에 연결한 상태를 유지한다.
- 먹기/풀/털 효과는 논리 제거 후 임시 시각으로만 재생하고 끝나면 숨긴다. Collider를 남기지 않는다.
- 병아리 등 추가 침수 객체는 floodPolicyHolds 진단을 유지한다. 동행/재추종 및 바람·컨베이어·제동판 순서의 미확정 사항을 임의 확정하지 않는다.

- 수평/수직 중간 및 끝 프레임에서 콜라이더/플레이어 앞뒤 가림/수로 접지를 확인한다.
- 변경 경로, 등록된 장치 정의, 실제 테스트 결과와 미실행 항목을 보고한다.
