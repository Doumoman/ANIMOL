ANIMOL 별길 목장 장치 V13 R2 적용 명령문

현재 Unity 프로젝트의 AGENTS.md와 기존 행동/맵/장치 코드부터 읽고, 아래 변경을 실제 프로젝트에 적용하라.
최신 요구는 DEVICE_RULES_KO.txt다. 이전 레버식 수문과 '양 밀면 플레이어도 전진' 처리를 이번 두 장치에 사용하지 마라.

1. 패키지 갱신
- 기존 ANIMOL_STARWAY_RANCH_DEVICES_V13 폴더에 이 개정본을 반영하고 .meta/GUID를 보존한다.
- Runtime/Editor/animation_catalog.json/catalog_sha256.txt를 함께 갱신한다.
- Runtime/Rules의 독립 순수 규칙 어셈블리도 포함한다.
- 실사용 Sprite 277개, 애니메이션 정의 150개. 기존 스프라이트 경로 267개를 유지했다.
- 1×1 PNG 320×320, 2×1 PNG 576×320, PPU 256, 중앙 Pivot, FullRect, Bilinear, 무압축, Mipmap Off.
- Tools > ANIMOL > Ranch Devices V13 > Build catalog, clips and inspection prefab에서 현재 animation_catalog.json을 선택한다.
- 생성된 최신 RanchDevicesV13Catalog.asset과 InspectionOnly_AllClips.prefab을 확인한다.
- 옛 InspectionOnly_All137Clips.prefab은 최신 검사 보드가 아니다. 다른 에셋을 지우지 말고 참조를 새 검사 보드로 바꾼다.

선택적 CLI 형식:
"<Unity Editor>" -batchmode -quit -projectPath "<project>" -executeMethod ANIMOL.Editor.RanchDevicesV13.RanchDevicesV13Builder.BuildFromCommandLine -ranchDeviceCatalog "Assets/<existing path>/ANIMOL_STARWAY_RANCH_DEVICES_V13/animation_catalog.json" -logFile "<log>"

2. 새 수문 등록/판정
- 기본은 수평 2×1의 두 이웃 칸 A/B. 딱 한 칸이 물칸이다. 둘의 원래 좌표를 저장한다.
- 마른 짝 칸에 선 플레이어가 다른 짝 물칸으로 입력할 때만 교환 이동을 시도한다.
- 원 프로젝트의 일반 물칸 진입 거절보다 먼저 이 특수한 짝 교환 조건을 검사한다.
- RanchDeviceRulesR2.TryCrossPond를 참조해 A 물/마름 전환 + B 반대 전환 + 플레이어 도착 이동을 하나의 트랜잭션으로 확정한다.
- 출발 플레이어를 침수 장애물로 세지 않는다. 목적지는 같은 동작에서 마른 바닥이 되므로 물칸이라는 이유만으로 거절하지 않는다.
- 조건 불일치 NotApplicable은 기존 일반 이동 판정으로 돌린다. 실제 물칸 진입을 무조건 허용하는 fallback을 만들지 않는다.
- 도착 점유 검사와 추가 침수 객체 정책 검사를 마친 뒤에만 전체 변경을 적용한다.
- 병아리 등 추가 객체의 정책 미지정은 floodPolicyHolds/진단으로 표시한다. 플레이어만 건너가는 기본 동작은 구현한다.
- 레버, 댐, 손잡이 일반 밀기, 외부 A/B 수로 일괄 토글이라는 옛 해석을 제거한다.

3. 새 양 판정
- 양 바로 뒤에서 입력하면 플레이어는 제자리, 양만 입력 방향으로 한 칸 움직인다.
- 기존 공용 PushHandler가 플레이어를 양 이전 칸으로 이동시키면 이 장치에서는 그 후속 이동을 억제한다.
- 도착이 바닥이면 양 위치만 갱신한다. 키 큰 풀이면 그 풀을 바닥으로 변경하고 양 엔티티도 제거한다.
- 이번 적용값은 양과 풀이 모두 사라지는 것이다. 먹고도 양이 남는 이전 로직을 사용하지 않는다.
- TryPushSheep/TryWindSheep의 실제 경로와 SheepAteAndRemoved/SheepWindAteAndRemoved 결과를 기존 엔티티/타일 시스템에 연결한다.
- 바람은 호스트가 계산한 실제 0/3/6/9 범위/금속 차단 결과를 전달한다. 물/벽/다른 차단체 직전에서 멈춘다.
- 바람 중 처음 만난 풀도 먹고 사라지며, 다음 풀을 계속 소비하지 않는다.

4. 행동 회계와 저장/복구
- 입력 전 스냅샷으로 판정하고 성공한 한 수의 코스트/턴을 기존 권한 시스템에서 딱 한 번만 반영한다.
- 커널 result.costDelta/turnDelta와 기존 입력 이벤트를 둘 다 과금하지 않는다.
- 바람 자동 단계는 추가 코스트/턴 0이다. 실패/거절은 상태 변경과 과금 모두 0이다.
- 양의 원래 좌표/존재 여부, 풀 상태, 물자리 쌍 위상, 플레이어 좌표를 같은 Undo/Reset/저장 단위에 넣는다.
- 제공 BoardR2는 연결용 참조 DTO다. 실제 맵을 두 개 운영하거나 렌더링에서 별도 판정을 만들지 않는다.
- 순수 커널은 성공 시 복사 상태를 반환하는 작은 보드 참조 구현이다. 기존 프로젝트가 delta/command 기반이면 동일 변경만 기존 트랜잭션으로 이식한다.

5. 아트/애니메이션 연결
- 수문은 pond_pair/a_dry_b_wet, a_wet_b_dry, cross_a_to_b, cross_b_to_a를 사용한다.
- 셀별 렌더링은 pond_cell/dry, wet, fill, drain과 RanchPondPairVisualR2를 쓴다. 기존 2×1 합성 렌더링과 동시에 그리지 않는다.
- 기존 sluice/horizontal 키는 경로 호환 별칭이며 그림은 새 구덩이/물웅덩이로 바뀌었다. 키 이름 때문에 댐 로직을 다시 적용하지 않는다.
- 물과 플레이어 이동은 같은 확정 결과를 표현한다. 마지막 프레임에서 타일/물/코스트를 커밋하지 않는다.
- 양 경로 재생 뒤 sheep/<direction>/eat_and_disappear를 재생하고 반드시 시각을 Clear한다.
- RanchSheepConsumptionVisualR2는 임시 VFX 오브젝트에 사용한다. 게임 양은 논리적으로 이미 제거된 상태다.
- 풀의 eaten 프레임도 임시 효과로만 재생하고 끝나면 숨긴다. Collider나 풀 차단을 애니메이션 끝까지 남기지 않는다.
- 로드/Undo/풀 재사용 때 물자리 위상과 양 존재 여부로 표시를 재설정하고 진행 중 임시 효과를 취소한다.

6. 실제 검증
- 에디터 컴파일 후 빌더를 실행하고 277 Sprite/150 .anim을 확인한다.
- Unity Test Framework가 설치된 프로젝트에서 Tests~/RulesR2 내용을 Editor 전용 테스트 폴더로 복사해 제공 검사를 실행한다.
- 기본 건너가기, 역방향 복귀, 출발 플레이어 예외, 목적지 차단, 양 밀기 시 플레이어 정지, 풀/양 동시 제거,
  바람 끝 이동, 첫 풀에서 소멸, 직접 밀기+바람 연쇄 한 번 과금, Undo/Reset을 실제 맵에서도 확인한다.
- 캐릭터 앞뒤 가림과 구덩이 접지는 실제 카메라 배율로 확인한다.
- 실제 장치 ID/배치 에디터 등록과 호스트 연결 경로, 수행한 검사 및 미실행 검사를 결과로 남긴다.

제공본은 파일/카탈로그/압축 검수를 수행했지만, 원 Unity 프로젝트가 없어 실제 C# 컴파일/NUnit/호스트 연결/플레이는 NOT_RUN이다.
