ANIMOL 별길 목장 장치 V13 — Unity MCP / CLI 적용 명령문

아래 내용을 원 Unity 프로젝트를 제어하는 에이전트에게 전달하라.

최신 별길 목장 장치 V13을 실제 프로젝트에 적용하라. 먼저 AGENTS.md와 현재 씬/스크립트/장치 데이터/테마 바인딩을 읽고 기존 구조에 맞춰 작업하라.
본 ZIP은 스프라이트·프레젠테이션 코드·에디터 빌더다. JSON만 복사하거나 검사 프리팹만 만든 것을 게임 연결 완료로 보고하지 말라.

1. 가져오기
- ANIMOL_STARWAY_RANCH_DEVICES_V13 폴더 전체를 Assets/ANIMOL/Art/ 아래에 배치한다.
- 기존 별길 목장 V12 배경·지형·연결 잔디·연결 장식 V02를 유지한다. 이번 패키지는 장치 그림/표현을 갱신한다.
- 기존 장치 GameObject의 ID·컴포넌트·저장/로드 참조·콜라이더·논리 루트를 통째로 삭제하거나 중복 생성하지 않는다.
- Authoring~는 제작 원화/프롬프트 보관용이며 게임에 넣을 별도 스프라이트 폴더가 아니다.
- 압축 내 SHA256SUMS.txt를 대조하고 누락/손상이 있으면 새 자산 생성으로 조용히 메우지 말고 보고한다.

2. 임포트와 생성
- Sprites/ 아래 실사용 PNG는 267개. PPU 256, Single Sprite, FullRect, 중앙 Pivot, Bilinear, 무압축, Mipmap Off, Clamp.
- 1×1 캔버스는 320×320이지만 논리 칸은 가운데 256×256이다. 320을 1칸으로 맞추려고 PPU를 320으로 바꾸지 않는다.
- 수문은 576×320 캔버스, 가운데 512×256의 2×1 논리 점유. 전 프레임 scale=1,1,1 유지.
- Tools > ANIMOL > Ranch Devices V13 > Build catalog, clips and inspection prefab 실행 후 이 폴더의 animation_catalog.json 선택.
- 빌더는 체크섬을 확인하고 카탈로그 asset, 실제 .anim 137개, InspectionOnly_All137Clips.prefab을 _GeneratedV13 아래에 생성한다.
- 기존 프로젝트 Animator를 쓰면 생성 .anim을 연결한다. RanchDeviceVisualV13을 쓰면 같은 SpriteRenderer에 Animator를 동시에 작동시키지 않는다.
- 검사 프리팹은 모든 클립 열람용이다. 이동·충돌·수집이 구현된 게임 씬이 아니다.

선택적 배치 명령 형식(설치된 Unity Editor 실제 경로와 프로젝트 경로를 사용):
"<Unity Editor executable>" -batchmode -quit -projectPath "<project>" -executeMethod ANIMOL.Editor.RanchDevicesV13.RanchDevicesV13Builder.BuildFromCommandLine -ranchDeviceCatalog "Assets/ANIMOL/Art/ANIMOL_STARWAY_RANCH_DEVICES_V13/animation_catalog.json" -logFile "<log path>"

3. 실제 프로젝트 연결
- DEVICE_RULES_KO.txt를 우선 규칙으로 읽는다. 옛 덩굴 다리를 다시 도입하지 않는다.
- 수문/별양/둥지의 문자열 family key는 아트 키이며 새 공식 장치 ID를 부여하지 않는다.
- 기존 장치의 전용 Visual 자식에 새 SpriteRenderer 또는 기존 렌더러 바인딩을 연결한다. 게임 판정 루트를 Tween하지 않는다.
- 카탈로그 Configure 후 확정 상태의 키를 SetState로 전달한다. 프레임 완료 콜백에서 코스트·턴·콜라이더를 변경하지 않는다.
- 나무상자 직접 밀기 한 칸, 바람 운반은 끝/장애물 직전까지. 별양 직접 밀기 한 칸 + 앞 풀 한 칸만 먹기.
- 바람은 플레이어/나무상자/별양/병아리를 실제 이동 가능한 마지막 칸까지 운반하고 금속 상자 뒤를 차단한다.
- 바람개비 본체는 고정하고 off/3/6/9 상태의 같은 방향 클립을 연결한다.
- RanchResolvedWindVisualV13.SetResolvedPath에 실제 바람 영향 칸, 현재 0/3/6/9 최대 범위, 셀 크기, Sorting 정보를 보낸다.
- 마지막 실제 바람 칸에만 terminal을 표시한다. 끈 뒤 이전 화살표·끝 표시가 남지 않게 한다.
- RanchCommittedMotionV13은 이미 논리 루트가 최종 위치로 확정된 뒤 실제 타일 중심 경로를 받는다.
- 시각 전용 자식의 초기 localPosition을 보존하고 이 자식에 RanchDeviceVisualV13을 배치한다. 경로 마지막 중심은 최종 루트+해당 오프셋과 일치해야 한다.
- 꺾인 경로는 perSegmentMoveClips 오버로드로 각 구간 방향의 walk/wind 클립을 전달한다. 포털/도약/배의 미확정 추종 경로를 임의로 생성하지 않는다.
- 병아리는 경로를 생략하지 않고 따라오며 둥지 도착 시 chick/<direction>/sit, 수문 통과 후 실제 정지 위치에서 waiting_at_sluice를 표시한다.
- 병아리와 둥지를 방울·별점·출구 열쇠로 연결하지 않는다. 병아리는 비차단·일반 누름판 비작동.
- 수로 A/B 상태 교환 후 RanchWaterCellVisualV13.Apply에 해당 칸의 wet와 같은 상태 이웃 8비트 마스크를 전달한다.
- 마스크 순서는 N1 NE2 E4 SE8 S16 SW32 W64 NW128. 변경 칸과 주변 8칸을 함께 갱신한다.
- 레벨 로드/리셋/되돌리기/풀 재사용/비활성화 후 재활성화 때 논리 상태로 다시 Configure/SetState/Apply한다. 잔상·경로·이전 클립을 재사용하지 않는다.
- 셀 크기가 1이 아니면 시각 전용 계층에 동일 비율을 적용한다. 시각 부모는 양수의 균일 스케일, 회전 0을 사용한다.

4. 예외 보존
- 다른 문양 별돌의 홈 진입은 거절하고 코스트·턴 0. 일치할 때만 통행 가능한 별 바닥으로 전환.
- 수로 점유 중 전환, 수문 정지 후 병아리 재추종, 바람 속 양의 풀 먹기, 여러 이동 장치 경합의 미확정 처리를 새로 확정하지 말라.
- 기존에 같은 예외의 확정 로직이 있는지 찾아 근거와 차이를 보고한다. 없다면 미확정 목록을 남기고 해당 조합을 기획 완료로 표시하지 않는다.

5. 실제 검증과 결과 보고
- 우선 에디터 컴파일 오류 0을 확인하고 빌더를 실행한다. 생성된 267 Sprite/137 .anim/검사 프리팹을 확인한다.
- 네 방향 양·병아리 걷기, 양 먹기, 둥지 앉기, 수문 2×1 좌↔우, 문양 일치/거절, 바람 off/3/6/9를 재생한다.
- 수문은 2칸 루트 하나만 존재해야 한다. 두 수로를 동시에 마른/젖은 상태로 잘못 적용하지 않는지 확인한다.
- 바람으로 막힘 직전까지 가는 플레이어/상자/양/병아리와 금속 뒤 차단을 실제 맵에서 확인한다.
- 양이 풀 한 칸만 먹는지, 먹힌 풀의 통행 상태가 Undo/Reset 때 기존 규칙대로 복구되는지 확인한다.
- 병아리 수문 통과 정지, 자기 둥지 도착, 비차단, 누름판 비작동, 추가 코스트 0을 확인한다.
- 무변화 입력의 코스트/턴 0과 자동 이동 연쇄의 추가 코스트 0을 실제 계측한다.
- 카메라 추적·맵 크기 변경·장치 주변 점유·화면 밖 복귀·풀 재사용을 점검한다.
- 기존 책장/도미노/다른 테마 장치 및 목장 장식 애니메이션이 갱신 때문에 덮이지 않았는지 확인한다.
- 실행한 검사와 미실행 검사를 나누고 바인딩한 씬/프리팹/스크립트 경로를 결과 파일로 남겨라.

이 제공본을 만든 환경에는 원 Unity 프로젝트와 Unity Editor가 없었다.
따라서 원본 제공본의 실제 Unity 임포트·C# 컴파일·프로젝트 연결·PlayMode는 NOT_RUN이다.
이번 적용 작업에서 실제 실행한 결과로 이 항목을 갱신하라.
