ANIMOL 별길 목장 장치 R2 — 최신 수정사항

이번 규칙이 이전 V13의 수문/양 설명보다 우선한다.

1. 수문: 구덩이·물웅덩이 교환형
- 기본 크기 2×1. 이웃한 두 칸 A/B가 한 쌍이며, 한 칸은 마른 구덩이, 다른 칸은 물웅덩이다.
- 마른 구덩이는 통행 가능하고, 물이 찬 칸은 보통 이동으로 통과하지 못한다.
- 플레이어가 마른 A에 서서 짝 물칸 B 쪽으로 스와이프하면 유효 행동 1회다.
- A에 물이 차고 B가 마른 구덩이가 되며 플레이어가 B로 이동한다. 세 변경을 함께 확정한다.
- 역방향도 동일하다. 마른 B에서 물칸 A 쪽으로 이동하면 다시 상태가 교환된다.
- 입력 후 손잡이/댐 본체를 밀거나 별도의 레버를 작동시키지 않는다.
- 외부 바닥에서 물칸으로 들어가는 입력은 이 교환 조건이 아니다. 반드시 짝의 마른 칸에서 출발한다.
- 출발 칸의 플레이어는 같은 트랜잭션에서 떠나므로 침수 점유 장애물로 세지 않는다.
- 도착 칸이 다른 차단 물체로 막혔다면 이동/물 교환/코스트를 모두 적용하지 않는다.
- 동행 병아리 등 추가 객체가 함께 침수될 때의 구체 정책은 별도 미확정이다.
  참조 커널은 host가 floodPolicyHolds에 명시한 칸에서 진단을 반환하고 전체 변경을 보류한다.
  이 보호 처리를 별도의 기획 확정으로 취급하지 않는다.

2. 별양
- 직접 밀 때 플레이어는 현재 칸에 그대로 있고 양만 입력 방향으로 한 칸 움직인다.
- 앞칸이 일반 바닥이면 그 칸으로 이동한 뒤 남아 있다.
- 도착 칸에 키 큰 풀이 있으면 그 풀 한 칸을 먹고 양이 사라진다.
- 이번 전달본은 '풀을 먹고 사라짐'을 풀과 양이 모두 제거되는 것으로 해석해 반영했다.
- 먹힌 풀 칸은 통행 가능한 바닥으로 남는다. 양의 이전 칸으로 플레이어가 자동 진입하지 않는다.
- 벽/물칸/다른 차단 물체/다른 양 때문에 이동할 수 없으면 아무 상태도 바꾸지 않는다.
- 양은 바람 영향을 받는다. 현재 유효 바람 범위의 끝 또는 막힌 칸 직전까지 이동한다.
- 바람으로 풀에 도착해도 동일하게 첫 풀 한 칸을 먹고 사라진다. 사라진 뒤 다음 풀을 연속으로 먹지 않는다.
- 양의 소멸을 방울 획득·출구 개방·별점으로 연결하지 않는다.

3. 코스트와 장치 턴
- 유효한 물자리 교환 이동 또는 직접 양 밀기: 코스트 1, 장치 턴 1회.
- 막혀 아무 상태 변화가 없으면 코스트 0, 장치 턴 0회.
- 바람에 의한 양의 자동 이동·섭취·소멸은 추가 코스트 0, 추가 장치 턴 0회.
- 직접 밀기 뒤 바람이 연쇄되어도 처음 한 행동에 대해 한 번만 계산한다.
- 참조 커널의 costSpent/deviceTurns와 원 프로젝트의 행동 회계를 이중 적용하지 않는다.

4. 표현
- 원화는 낮은 풀/흙 테두리, 마른 흙 바닥, 청록 물로 구성된다. 댐·기계·레버는 제거했다.
- 물자리 두 칸은 1×1 셀 두 개 또는 2×1 합성 스프라이트 하나로 표시할 수 있다. 둘을 동시에 중복 표시하지 않는다.
- 물 차오름/빠짐 중에도 흙 테두리의 모양과 위치는 고정된다.
- 양은 실제 이동 경로를 재생한 뒤 먹기→작은 털 퍼프→완전 숨김으로 마친다.
- 게임 논리에서는 양과 풀의 제거를 먼저 확정하고 임시 시각 효과가 동작을 마저 보여 준다.
- 양 Collider를 애니메이션 완료까지 남겨 두거나 마지막 퍼프 프레임을 영구 유지하지 않는다.

5. 그 밖의 규칙
- 나무상자, 바람개비 0/3/6/9, 별돌 문양, 둥지 및 공통 장치 규칙은 기존 최신 기획을 따른다.
- 병아리의 '수문 통과 후 정지' 요구는 유지하되, 새 물자리 교환에 동행하는 세부 판정은 별도 미확정이다.
- 여러 바람/컨베이어/제동판의 처리 우선순위는 기존 호스트가 소유한다.
- 수문/별양의 공식 장치 ID는 임의로 부여하지 않았다. 코드의 instanceId는 배치 인스턴스 식별자다.

6. 코드 제공 범위와 검증 상태
- Runtime/Rules/RanchDeviceRulesR2.cs: 물자리 교환, 정지한 플레이어의 양 밀기, 풀/양 제거, 바람 이동의 순수 참조 판정 코드.
- 성공 시 원본을 보존한 새 상태와 실제 경로·이벤트·코스트 차이를 반환한다. 실패 시 원본과 코스트 0을 반환한다.
- 실제 프로젝트 맵/엔티티/Undo에 연결하는 어댑터는 원 프로젝트에서 작성해야 한다. 독립 보드를 두 개 운용하지 않는다.
- Tests~/RulesR2에 EditMode 검사 원본을 포함한다. 제공 환경에서는 C# 컴파일과 NUnit 실행이 미실행이다.
- Python 파일 검수와 Unity/NUnit 실행 결과를 혼동하지 않는다.
