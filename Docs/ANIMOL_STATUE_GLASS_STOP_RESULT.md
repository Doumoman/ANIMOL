# 잔영 극장 석상: 유리 파괴 시 현재 돌진 종료

잔영 극장(`memory_theater`)의 석상은 유리를 부수되 유리가 있던 칸으로 들어가지 않고 바로 앞 칸에서 이번 돌진을 끝낸다. 예를 들어 오른쪽으로 돌진해 `(5,4)`의 유리를 부수면 석상은 `(4,4)`에 멈춘다. 유리 칸으로 진입하는 이동 이벤트도 발생하지 않아 표시 위치와 판정이 일치한다. 이후 유효 행동에서 플레이어를 발견하면 기존처럼 다시 조준하고, 그다음 유효 행동에 재돌진할 수 있다.

잔영 극장의 유리 충돌은 정지 옵션과 무관하게 파괴 직후, 유리 칸으로 이동하기 전에 돌진을 끝낸다. 이미 유리 바로 옆에 있으면 이동 없이 유리만 부순다. 금 간 벽과 다른 테마의 유리 파괴는 기존 옵션을 따른다. 영구 정지 상태나 새로운 저장 필드는 추가하지 않았다.

실제 판정 변경은 `Assets/ANIMOL/Scripts/Runtime/PuzzleDeviceSession.cs`의 `Statue` 종료 조건이다. 유리 파괴 이벤트, 회복 표현, 플레이어 접촉 실패, 고체 충돌, 입력 차단 여부와 시간 배율은 유지한다. 맵·시나리오·씬·프리팹은 수정하지 않았다. 특히 SW00 원본 및 GUID는 변경하지 않았다.

Unity 6000.3.8f1에서 최종 코드를 컴파일하고 다음을 실제 실행했다.

- EditMode `Statue` 필터: **19/19 통과**. 네 방향 × 정지 옵션 참/거짓, 유리 직전 칸 정지 후 재조준·재돌진, 네 방향에서 인접 유리 파괴 시 이동 없음, 유리 칸 진입 이동 이벤트 없음, 최초 유리만 파괴, 되돌리기·재시작, 플레이어 접촉 실패, 금 간 벽·다른 테마의 기존 옵션 보존을 검사했다.
- PlayMode `StatueStopsBeforeBrokenGlassThenCanChargeAgainAndUndoRestoresBoth`: **1/1 통과**. 실제 `PuzzlePrototypeController`와 ET-05의 석상·유리 아트 정의를 사용한 메모리 검수 보드에서 석상 표시 위치가 유리 바로 앞 칸에 정지한 뒤 다시 돌진하는 것과 Undo/재시작 복구를 검사했다. 실제 ET-05 맵 전체 경로를 완주한 검증은 아니다.
- 기존 석상 장치 예제 `DeviceRoomClearsThroughItsAuthoredRoute(17)`: **1/1 통과**. 위치 변경 후에도 작성된 예제 해답으로 클리어된다.
- `git diff --check` 통과. 상태 스키마와 탐색 스냅샷 코드는 작업 전 원본과 동일하다.
- 작업 전 수정 상태였던 추적 파일의 바이트를 보관하고 검증 후 비교했다. 기존 사용자 변경에는 추가 차이가 없으며 맵과 기존 한글 폰트는 이번 커밋에 포함하지 않는다.

새 피드백 사건은 추가하지 않았다. `CommercialPolishPolicyTests`는 레거시에 격리되어 실행하지 않았으며 위의 현재 판정·PlayMode 테스트 결과와 구분한다. 실기기 GPU 및 기존 전체 맵 해답 재검증은 실행하지 않았다.

실행 근거: `Docs/Validation/StatueGlassStop/EditMode.json`, `PlayMode.json`, `StatueRoomRoute.json`.
