## 편집기 사용

`ANIMOL > 맵 제작기`에서 맵을 선택하면 설정 패널의 **별길 목장 최단 경로**에 순서, 최단 입력 수, 복사 가능한 경로와 탐색 상태 수가 표시된다. 개별 맵 또는 `SW00`~`SW19` 전체 탐색을 실행할 수 있다. Edit Mode의 저장된 맵에서만 계산한다.

탐색 상한을 조절해 더 큰 계산을 실행할 수 있다. 전체 탐색은 같은 원본·규칙에서 이미 확인한 상한 이하의 미확정 계산을 반복하지 않는다. 완료된 확정 기록도 재사용한다. 결과 JSON은 임시 파일을 완성한 뒤 교체해 이전 기록을 보존한다.

경로는 `↑=위`, `→=오른쪽`, `↓=아래`, `←=왼쪽`으로 기록한다. 연속 화살표는 이동 중 다음 입력을 예약하는 순서다. `○`는 바람 자동 이동 한 번을 기다리며 코스트는 0이다. 화살표 한 개는 유효 입력 코스트 1이다.

## 탐색과 검증

실제 `PuzzleDeviceSession`의 네 방향 이동을 모두 검사하는 정확 탐색을 사용한다. 지원하는 보드에서는 안전한 하한을 이용한 A*를, 지원하지 않는 장치가 있는 보드에서는 기존 0-1 BFS를 사용한다. 막힌 입력과 실패 상태는 버리고, 방향 입력은 비용 1, 선택적인 `AdvanceWind()`는 비용 0으로 확장한다. 런타임 `Load()`의 첫 바람 이동도 반영한다. 예약 입력이 `ContinueWind()`보다 먼저 처리되는 순서를 포함한다.

플레이어·물체·장치·방울·목표 방문·둥지·양·연못·풀 상태를 비교한다. 판정에 사용하지 않는 표시 방향은 비교에서 제외한다. 개별 목표나 연결이 없는 동일 금속 상자는 위치 순서만 다른 중복 상태를 합친다. 바람이 없는 맵에서는 같은 위치를 차지하는 양의 ID 순서만 다른 상태도 합친다. 바람 맵은 양의 처리 우선순위가 영향을 줄 수 있으므로 원래 ID별 자리를 유지한다. 고정 ID 자리를 사용해 반복 GUID 문자열 저장량도 줄인다.

A*의 하한은 물체·양·풀·둥지·연못 통행 제한을 제거한 완화 보드에서 방울 수를 채우고 출구에 도달하는 최소 비용이다. 가능한 바람·반사 직선 위에서는 그 직선 방향의 0비용 이동을, 장치 원점·컨베이어에서는 모든 방향을 허용한다. 범위·차단 조건은 완화하며 소켓이 공개할 수 있는 방울도 포함한다. 실제 후속 상태는 항상 원래 판정으로 생성한다. 지원하지 않는 순간이동·장치 조합은 하한 0과 0-1 BFS로 되돌아간다.

실제 상태의 입력 비용 `g`와 과대평가하지 않는 하한 `h`의 합이 가장 작은 상태부터 조사한다. 같은 상태를 더 낮은 비용으로 발견하면 다시 연다. 이 순서로 꺼낸 클리어만 최단으로 확정한다. 임의의 추정 거리나 첫 발견만으로 최단 표시를 하지 않는다. 기존 상태 비교·이동 규칙은 그대로이므로 규칙 버전 4의 기존 증거를 유지한다. 탐색 순서 변경은 실제 API 경로 재생과 별도 하한 검증으로 확인한다.

저장 전 실제 공개 `Apply()` / `AdvanceWind()` API로 전체 경로를 다시 실행하여 클리어와 비용을 확인한다. 원본 SHA-256과 탐색 규칙 버전이 다르거나 미저장 편집이 있으면 이전 결과를 현재 최단 경로로 표시하지 않는다.

계산은 별도의 메모리 세션에서 실행하며 플레이어의 실제 클리어·재화 기록에 반영하지 않는다.

`limit`은 탐색 상한까지 답이 확정되지 않았다는 뜻이다. `unreachable`은 도달 가능한 전체 상태를 모두 검사한 경우에만 기록한다. 취소·상한 도달을 클리어나 도달 불가로 취급하지 않는다.

## 2026-11-07 최종 탐색

마지막 미확정이던 **18번(SW17)의 최단 경로는 64입력**이다. 원래 판정 코드로 네 방향을 모두 확장하는 A*에서 477,514개 상태를 발견하고 368,235개를 꺼내 조사했다. 전이 1,472,936개가 빠른 구현과도 모두 일치했으며, Unity 공개 API로 방울 3개 수집·클리어·비용 64를 재생 확인했다.

```text
→ ↑ ↑ → → → ← ← ↓ → → ↓ ← ← ↑ ↑ ↓ ↓ ↓ ↑ → → → ↑ ↑ ↑ → → → → ↑ ↑ → → ↓ ← ← ← ← ← ↑ ← ← ← ← ↑ ↑ ↑ ↓ ↓ ↓ ↓ ↓ ↓ ↓ ↓ ↓ ↑ ↑ ↑ → → → →
```

이 맵은 방울이 있는 풀 두 곳을 양 두 마리가 각각 먹어야 한다. 풀을 먹은 양은 사라지므로 다른 풀에 양을 소모한 분기는 완주할 수 없다. 정적 바닥만 남긴 양 밀기 경로에서 필요한 풀마다 서로 다른 양을 배정하는 최소 비용을 구했다. 실제 경로보다 자유로운 완화이므로 밀기 수를 과대평가하지 않으며, 배정이 불가능한 분기만 제외한다.

이 범위의 양·상자 밀기는 플레이어가 제자리에 있고 병아리 경로도 진행하지 않는다. 기존 하한은 이동 입력 수를, 새 하한은 별도의 양 밀기 수를 세므로 합산할 수 있다. 실제 판정 전이는 바꾸지 않았고, 더 낮은 비용을 발견하면 상태를 다시 연다. 제한 규칙·작은 상태 표현·검증 방법은 [계산 도구](../Tools/Puzzle/ExactSearch/README.md)에 정리했다.

검증에는 기존 전이 7,000개, SW02/SW17 전이 200,000개와 세션 복원, 작은 보드 전이 8,000개, 두 보드의 완전 BFS/A* 비교를 사용했다. SW02의 기존 77입력 경로와 상태 수까지 재현했다. 최종 원래 판정 탐색과 빠른 탐색도 거리·경로·상태 수가 같았다. 상한·원본 변경·선택적 방울의 처리도 검사했다.

주 증거의 계산 시간은 13.32초(.NET)다. 적용한 상한은 10,000,000개 상태·추가 관리 메모리 2,048 MiB이며, 두 상한에 도달하지 않고 해결했다. [최단 경로 증거](Validation/StarwayShortestPathsFinal/SW17.json), [소스 커밋·해시 대조](Validation/StarwayShortestPathsFinal/provenance.json).

## 화살표 기록과 최단 코스트 적용

확정된 19개 맵의 시작 코스트를 최단 입력 수에 맞췄다. 메인 로비에서 입장할 때와 맵 제작기의 플레이 미리보기에서 같은 `StarwayShortestPaths.json`을 연결한다. 실행 시 MapData와 시나리오를 복사하여 그 복사본의 `costLimit`만 설정하므로 원본 맵·메타·작성된 검수 경로는 보존된다.

기존 HUD는 설정된 제한에서 실제 사용 코스트를 빼서 표시한다. 유효한 방향 입력은 1을 소비하고, 막힌 입력과 `○` 바람 대기는 소비하지 않는다. 정확한 최단 경로로 완주하면 남은 코스트가 0인 상태에서 클리어된다. Reset은 같은 시작 코스트로 돌아간다. 경로가 없는 7번(SW06)에는 최단값을 적용하지 않고 기존 설정을 유지한다.

맵 제작기의 표시·복사, 현재 경로 JSON과 새 계산기 출력은 화살표를 사용한다. 이전 계산 증거와 원본의 작성 검수 경로는 보관한다. 원본 해시나 규칙 버전이 달라진 증거는 Editor에서 예산으로 사용하지 않는다.
