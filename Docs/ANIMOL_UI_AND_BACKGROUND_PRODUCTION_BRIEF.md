# ANIMOL UI·게임 배경 제작 목록 및 전달 명세

작성일: 2026-10-02

우선 범위: **강화 UI, 캠페인 진입 전 UI, 해당 화면에 필요한 공통 부품과 배경**

용도: 기획·UI 디자인·픽셀 아트 제작·Unity 구현 담당자가 함께 사용하는 단일 전달 문서.

## 1. 이번 제작의 기준과 범위

메인 로비는 현재 승인된 **v7 판타지 배경**을 유지한다. 이전 배경을 복원하거나 새 로비 배경으로 교체하지 않는다. 신규 화면은 v7의 다섯 테마와 현재 버튼·패널의 시각적 분위기에 맞춘다.

이번 1차 작업 단위는 **기존 로비 진입점 보강 1개 + 화면 7개 + 공통 모달·상태 UI**다. 화면 7개는 테마 선택, 스테이지 선택, 스테이지 상세, 진입 로딩, 강화 허브, 계정 강화, 동물 강화다. 동물 상세는 우선 동물 강화 화면 내부 패널로 구성하며 별도 전체 화면을 추가하지 않는다.

게임플레이용 배경은 별도 제작 목록으로 구분한다. 로비의 고정 발판·토끼 애니메이션을 게임 맵이나 게임 플레이어에 그대로 적용하지 않는다. 화면 디자인 작업을 이유로 수동 편집 맵·물리·입력·보상 규칙을 바꾸지 않는다.

문서에서 사용하는 상태 구분:

| 표기 | 의미 |
|---|---|
| 기존 | 현재 파일·코드·데이터 구조가 존재함. 완성된 운영 기능이라는 뜻은 아님 |
| 보강 | 기존 화면·흐름에 표현이나 연결을 추가해야 함 |
| 제안 | 이번 전달 문서의 제작·배치 제안. 구현 완료 또는 기획 확정으로 간주하지 않음 |
| 미확정 | 가격·효과·종류·운영 연결 등이 정해지지 않음. 아트에 고정값을 넣지 않음 |

## 2. 현재 프로젝트에서 확인한 사항

| 항목 | 현재 상태 | 제작에 반영할 내용 |
|---|---|---|
| 메인 로비 배경 | v7 배경 20개와 토끼 시트 2개 적용 | 유지·재사용. 신규 로비 배경 제작 제외 |
| 로비 버튼 | 캠페인·경쟁·협동·상점·설정·광고 및 뒤로 가기 | 현재 승인된 외형과 동작 유지 |
| 강화 진입 | 기존 Meta UI에 `UpgradeButton` 처리와 강화 화면은 존재하지만, 현재 Portrait 로비에는 직접 진입 버튼이 없음 | **노출되는 강화 진입점과 실제 연결이 필요** |
| 캠페인 흐름 | 테마 선택 → 스테이지 선택 → 상세 → 스테이지 실행 코드 존재 | 기존 화면을 재디자인·보강하며 경로 보존 |
| 캠페인 동물 | 스테이지 데이터가 허용 동물과 시작 동물을 지정 | 선택·편성창이 아닌 읽기 전용 정보로 표시 |
| 캠페인 규모 | 5테마 × 테마당 20스테이지 구조 | 카드·노드 템플릿을 재사용. 스테이지 100개마다 별도 UI 그림을 만들 필요 없음 |
| 계정 공통 강화 | 최대 스테미나·재생 속도·소비량 감소의 3트랙, Lv.0~10 초안 존재 | 현재/다음 레벨과 효과 비교 영역 필요. 수치는 프로토타입이며 최종 밸런스 아님 |
| 동물별 강화 | 액티브·패시브 각 Lv.0~5의 성장 계약 존재 | 2트랙 표현 필요. 효과·가격·숙련도 획득 정책은 미확정 |
| 동물 명단 | 성장 데이터의 일부 항목은 DEV 식별자이고 CharacterUpgrade 정의는 비어 있음. 캠페인에서 확인된 실명 정의는 토끼 | DEV 명칭을 출시용 동물명으로 사용하지 않음. 최종 명단 없이 여러 동물 원화를 확정하지 않음 |
| 계정·재화 | 운영 계정/구매 연결 미완료 상태를 표시 | 잔액 미조회, 요청 불가, 재연결 상태 디자인 필요 |
| 로딩 화면 | `SC09_MapLoading` 프리팹은 있지만 현재 캠페인 실행은 씬을 직접 로드 | 새 로딩 디자인과 별도로 **캠페인 실행 경로 연결 작업** 필요 |

## 3. 필요한 화면 흐름

```text
현재 시작 화면 → 현재 v7 로비
  ├─ 캠페인 → 테마 선택 → 스테이지 선택 → 스테이지 상세
  │                                           ├─ 게임 시작 → 진입 로딩 → 실제 게임
  │                                           └─ 강화 보기 [보강 제안]
  └─ 강화 [로비 진입점 보강] → 강화 허브
                              ├─ 계정 공통 강화
                              └─ 동물별 강화 → 같은 화면의 동물 상세 패널

강화에서 뒤로 가기 → 진입했던 로비 또는 스테이지 상세로 복귀
모달이 열린 상태의 뒤로 가기 → 모달만 닫기
```

스테이지 상세에서 강화로 이동했다면 선택 테마·스테이지·스크롤 위치를 복귀 시 유지하는 구성을 제안한다. 강화가 캠페인 입장의 필수 절차가 되어서는 안 된다. 입장 전에 강제 동물 선택이나 필수 튜토리얼 팝업을 추가하지 않는다.

## 4. 캠페인 진입 전 UI 상세

### C0. 로비의 진입점 보강

기존 `SC01_Lobby`를 사용한다. 캠페인 카드는 유지하며 강화 진입 버튼 1개를 추가하는 것이 필요하다. 버튼은 의미를 알 수 있는 성장 아이콘과 `강화` 라벨을 함께 사용한다. 보조 메뉴 영역 또는 작은 성장 메뉴를 사용하는 배치를 제안하되, 확정 배치는 기존 버튼·토끼 통로·Safe Area를 함께 검토한다.

스테이지 상세의 `강화 보기`는 편의를 위한 추가 진입점이다. 서버 미연결이어도 강화 정보 열람은 가능하게 하고 실제 구매·적용만 상태에 따라 비활성화하는 구성을 제안한다.

### C1. 테마 선택 — `SC02_ThemeSelect`

| 필수 요소 | 내용 |
|---|---|
| 상단 영역 | 뒤로 가기, `캠페인` 제목, 현재 진행 요약 |
| 테마 카드 | 정확히 5개. 테마 대표 그림, 이름, 진행 `완료 수/20`, 상태 배지 |
| 해금 정보 | 열림·잠김·클리어·제작 중을 구분하고 해금 조건 표시 |
| 현재 목표 | 다음 진행 가능한 테마 또는 최근 플레이 테마 강조 |
| 목록 조작 | 세로 스크롤을 기본 제안. 터치 영역과 선택 피드백 확보 |
| 예외 상태 | 데이터 로딩, 데이터 없음, 불러오기 실패, 재시도 |

**필요 아트:** 테마 대표 이미지 5종, 공용 카드 프레임 1종, 진행 바 1세트, 잠금/완료/진행 중/제작 중 배지. 상태별로 대표 그림을 새로 그리지 않고 배지·테두리·명도 처리를 재사용한다.

### C2. 스테이지 선택 — `SC03_StageSelect`

| 필수 요소 | 내용 |
|---|---|
| 상단 영역 | 뒤로 가기, 선택 테마명, 테마 진행 `x/20` |
| 스테이지 목록 | 20개 노드 또는 카드. 번호는 런타임 텍스트 |
| 노드 상태 | 잠김, 입장 가능, 선택됨, 클리어, 제작 중 |
| 선택 정보 | 선택 스테이지 이름·번호, 최고 기록 유무, 상세 보기 |
| 해금 설명 | 선행 스테이지 등 실제 데이터의 조건 |
| 진행 표시 | 다음 플레이 위치 강조, 목록 복귀 시 위치 유지 |

노드형 길 또는 카드형 그리드는 미확정이다. **먼저 20개가 들어가는 공용 목록 구조 1종을 제작**하고 다섯 테마의 배경·장식만 교체하는 것을 제안한다. 시각적 경로를 그리더라도 기존 스테이지 해금 규칙을 새로 만들지 않는다.

**필요 아트:** 공용 노드/카드 프레임, 상태 표시, 연결선 또는 구간 장식, 테마별 선택 화면 배경 5종. 별·등급·보상 상자는 현재 검증된 규칙이 없으므로 필수 요소로 넣지 않는다.

### C3. 스테이지 상세 — `SC04_StageDetail`

| 필수 요소 | 내용 |
|---|---|
| 제목 | 테마명, 스테이지 번호·이름 |
| 미리보기 | 해당 테마 또는 실제 맵의 대표 이미지 |
| 기본 목표 | 방울 3개 수집 → 출구 개방 → 실제 출구 도착 |
| 사용 동물 | 스테이지가 정한 고정 동물 목록과 시작 동물 표시. 선택 조작 없음 |
| 플레이 규칙 | 실제 데이터가 제공하는 제한시간, 출구 개방 후 시간, 체크포인트·선택 목표 |
| 기록 | 클리어 여부, 개인 최고 시간, 기록 없음 상태 |
| 보상 | 확정 데이터가 있을 때만 종류·수량 표시. 미설정은 안내로 구분 |
| 주요 조작 | `게임 시작`, 뒤로 가기, 선택적으로 `강화 보기` |
| 입장 불가 | 잠금·콘텐츠 제작 중·데이터 오류 등 원인과 해결 가능한 행동 |

**필요 아트:** 상세 패널 1종, 목표/방울/출구/시간/체크포인트/기록 아이콘, 동물 초상 프레임, 시작 버튼, 작은 보상 슬롯. 맵 미리보기 100장을 먼저 수작업 제작하지 않는다. 초기에는 테마 대표 이미지 5종을 재사용하고 필요 시 실제 맵 캡처로 확장한다.

### C4. 진입 로딩 — `SC09_MapLoading`

- 선택한 테마·스테이지 이름과 실제 준비 상태.
- 고정 사용 동물의 읽기 전용 표시.
- 실제 진행률을 받을 수 있을 때만 퍼센트/진행 바를 표시. 그렇지 않으면 준비 중 표시.
- 중복 시작 방지, 로딩 실패·재시도·돌아가기 상태.
- 취소 가능한 단계에만 취소 버튼 표시.
- 선택적인 짧은 조작 팁 1줄. 강제 학습이나 긴 시퀀스는 추가하지 않음.

**필요 아트:** 공용 로딩 패널 1종, 테마 대표 이미지 재사용, 작은 로딩 애니메이션 1종. 별도의 로딩 전용 배경 5장을 우선 제작할 필요는 없다.

## 5. 강화 UI 상세

### U1. 강화 허브 — `SC10_UpgradeHub`

| 필수 요소 | 내용 |
|---|---|
| 상단 영역 | 뒤로 가기, `강화` 제목, 조회 가능한 실제 보유 코인 |
| 계정 공통 강화 카드 | 모든 동물에 적용되는 공통 성장임을 설명, 세 트랙 요약 |
| 동물별 강화 카드 | 선택 동물의 액티브·패시브 성장으로 이동 |
| 진행 요약 | 현재 레벨·최대 레벨·최대 성장 여부. 조회하지 못한 값은 `--` |
| 계정 상태 | 게스트/서버 연결/조회 불가를 간결하게 안내 |
| 도움말 | 공통 성장과 동물별 성장의 차이, 모드별 적용 규칙 열람 |

**필요 아트:** 두 분류 카드, 계정 성장 아이콘, 동물 성장 아이콘, 공통 코인 표시, 성장 요약 게이지. 강화 허브를 다른 화면과 분리한 새 전체 씬으로 만들 필요는 없다.

### U2. 계정 공통 강화 — `SC10A_AccountUpgrade`

기존 세 트랙을 유지한다. 아래 레벨 상한은 **현재 데이터 초안 기준**이며 모든 수치는 런타임 데이터에서 표시한다.

| 트랙 | 필요한 표현 | 아이콘 방향 제안 |
|---|---|---|
| 최대 스테미나 | 현재 최대치 → 다음 최대치, 현재 레벨/상한 | 스테미나 용량·그릇 |
| 재생 속도 | 현재 회복 효과 → 다음 회복 효과 | 회복·순환 |
| 소비량 감소 | 현재 소비 효과 → 다음 소비 효과 | 절약·보호 |

세 트랙 각각에 필요한 요소:

- 트랙명과 효과 설명, 현재 레벨, 다음 레벨, 공용 레벨 진행 표시.
- 현재 효과와 다음 효과를 나란히 읽을 수 있는 비교 영역.
- 다음 레벨 비용, 보유 코인, 부족분 표시.
- 강화 버튼과 적용 가능/불가 이유.
- Lv.0, 중간 레벨, 최대 레벨의 레이아웃. 현재 초안 상한은 10.
- `강화 가능`, `코인 부족`, `MAX`, `조회 불가`, `처리 중`, `실패` 상태.
- 성공 시 서버가 확정한 새 레벨·잔액만 반영. 성공 연출은 짧은 강조로 제한.

**필요 아트:** 강화 항목 카드 1종을 3개에 재사용, 트랙 아이콘 3종, 10단계까지 대응 가능한 공용 게이지, 비용 영역, MAX 배지. 레벨별 카드 그림 30장을 제작하지 않는다.

### U3. 동물별 강화 — `SC10B_CharacterUpgrade`

| 영역 | 필수 요소 |
|---|---|
| 동물 목록 | 초상, 이름, 해금/잠김, 선택 상태, 성장 요약 |
| 선택 동물 정보 | 큰 초상 또는 짧은 대기 모션, 이름, 간단한 특성 설명 |
| 액티브 성장 | 현재/다음 레벨, 효과 설명, 레벨 표시, 강화 비용 |
| 패시브 성장 | 현재/다음 레벨, 효과 설명, 레벨 표시, 강화 비용 |
| 재료 | 공용 코인과 해당 동물의 숙련도 각각의 보유량·필요량 |
| 잠금 안내 | 실제 해금 조건, 콘텐츠 준비 여부 |
| 적용 범위 | 캠페인·일반·랭크 등 실제 확정된 적용 규칙만 표시 |
| 주요 조작 | 강화, 트랙 상세/도움말, 뒤로 가기 |

현재 성장 계약은 액티브·패시브 각 Lv.0~5를 표현하지만 **실제 기술·패시브 효과·가격·숙련도 획득량은 미확정**이다. 임의의 점프력·이동속도 증가나 새 능력 효과를 확정해서 그리지 않는다.

동물 해금과 강화는 별개다. 강화 버튼으로 캠페인 고정 동물 목록을 바꾸거나 동물을 구매·해금하는 흐름을 만들지 않는다. 현재 DEV 식별자 3개를 출시 동물 3종으로 해석하지 않는다.

**필요 아트:** 동물 카드 프레임, 선택 표시, 잠긴 초상 처리, 큰 초상 영역, 액티브/패시브 트랙 프레임, 5단계 게이지, 숙련도 아이콘·표시부. 동물별 초상 및 능력 아이콘은 **최종 동물 명단과 능력 확정 후 종수에 맞춰 제작**한다. 우선 토끼를 이용한 레이아웃 검증본 1종을 만든다.

### U4. 강화 공통 확인·결과·안내

독립 전체 화면보다 공용 모달/패널 템플릿을 사용한다.

| 상황 | 표시 요소 | 가능한 행동 |
|---|---|---|
| 강화 확인 | 대상, 현재→다음 레벨, 변화 효과, 코인/숙련도 비용 | 취소, 확정 |
| 처리 중 | 요청 중 표시, 중복 요청 비활성 | 실제 취소 가능 여부에 따라 안내 |
| 성공 | 확정된 레벨·효과·잔액 | 닫기 또는 계속 보기 |
| 재화 부족 | 부족한 재화와 수량 | 닫기. 실제 경로가 있을 때만 획득처 보기 |
| MAX | 더 강화할 수 없음을 표시 | 상세 열람, 뒤로 가기 |
| 연결/조회 실패 | 조회 실패와 구매 미확정을 구분 | 재시도, 닫기 |
| 콘텐츠 미설정 | 효과·가격을 확정하지 않았음을 표시 | 열람·닫기, 구매 비활성 |

재화 부족을 곧바로 결제 유도로 연결하지 않는다. 성장 완료 팩은 현재 계정 공통 3트랙 대상 계약이며 동물 강화·동물 해금은 포함하지 않는다. 팩의 판매 가격과 보전 정책이 미확정이므로 이번 필수 UI 제작에서 실제 판매 화면은 제외한다.

## 6. 화면 전체가 공유할 UI 부품

아래는 **고유 형태 기준 목록**이다. 버튼 상태마다 별도 PNG를 반드시 만들라는 뜻은 아니다. 프레임·아이콘·런타임 색/선택 표시를 조합할 수 있다.

| 분류 | 필요한 부품 |
|---|---|
| 내비게이션 | 뒤로, 닫기, 좌/우 또는 이전/다음, 탭 선택 표시 |
| 버튼 | 주 행동, 보조 행동, 작은 아이콘 버튼, 비활성 상태, 선택/눌림/포커스 표현 |
| 화면 틀 | 상단 제목 바, 본문 패널, 상세 패널, 하단 행동 영역 |
| 목록 | 테마 카드, 스테이지 노드, 강화 카드, 동물 카드, 스크롤 표시 |
| 정보 영역 | 읽기 쉬운 텍스트 받침, 툴팁, 구분선, 접기/펼치기 표시 |
| 재화·재료 | 기존 코인 아이콘·캡슐 재사용, 숙련도 아이콘, 비용 슬롯 |
| 진행 표시 | 테마 진행 바, 레벨 게이지, 로딩 표시 |
| 상태 배지 | 잠김, 해금/사용 가능, 선택됨, 클리어, MAX, 준비 중, 오류 |
| 캠페인 아이콘 | 방울, 출구, 시간, 체크포인트, 기록, 동물, 보상 |
| 강화 아이콘 | 공통 강화 3트랙, 동물 성장, 액티브, 패시브 |
| 모달 | 공용 창 프레임, 배경 딤, 확인/취소 배치 |
| 상태 화면 | 로딩 중, 데이터 없음, 연결 불가, 콘텐츠 준비 중, 오류+재시도 |

배경과 장식은 클릭을 받지 않는다. 반대로 실제 모달의 딤은 아래 화면으로 클릭이 전달되지 않도록 한다. 비활성 상태는 색 차이만으로 구분하지 않고 라벨·아이콘·이유를 함께 제공한다.

## 7. 필요한 UI 배경 목록

다음 신규 배경은 **제작 제안**이며 현재 승인된 v7 로비를 대체하지 않는다. 정보가 많은 화면은 정적인 배경을 우선 사용한다.

| ID | 용도 | 수량/상태 | 제작 방향 |
|---|---|---|---|
| BG-LOBBY | 시작 화면·메인 로비 | 기존 5테마, 20레이어+토끼 시트 2개 | v7 그대로 유지 |
| BG-CAMPAIGN-BASE | 테마 선택의 공통 바탕 | 신규/재구성 1종 | 여행 안내판·지도 또는 세계의 입구 분위기. 가운데 카드 영역 확보 |
| BG-CAMPAIGN-T01~05 | 선택한 테마의 스테이지 목록 | 신규/재구성 5종 | 각 테마의 환경을 보여주되 노드·번호와 겹치지 않는 배치 |
| BG-GROWTH-BASE | 강화 허브·계정 강화·동물 강화 | 신규/재구성 1종 | 성장 작업실·훈련 공간 계열 제안. 세 화면이 공유하고 패널·소품만 전환 |
| DETAIL/LOADING | 상세·로딩의 환경 표현 | 전용 전체 배경 신규 제작 없음 | 테마 배경 또는 대표 이미지 재사용 |

**1차 UI 배경 제작량 제안: 7종**(캠페인 공통 1 + 테마별 목록 5 + 강화 공통 1). 예산을 줄이는 경우 테마별 목록 배경은 v7 승인 원본의 대표 구도에서 재구성할 수 있다. 로비 runtime 원본을 덮어쓰지 않고 별도 용도 파일로 제작한다.

별도로 **테마 대표 썸네일 5종**이 필요하다. 테마 카드·상세·로딩에 공용으로 사용한다. 썸네일과 전체 화면 배경을 별개의 크기·구도 산출물로 구분한다.

## 8. 실제 게임플레이 배경 목록

다섯 테마는 로비와 같은 세계관을 사용하지만 실제 플레이 카메라·맵 공간에 맞는 게임용 배경이 필요하다. 기존 게임용 아트의 재사용 가능 여부는 해당 씬·맵을 별도로 검사한 뒤 결정한다. 아래는 **필요 구성 목록이며 기존 게임 배경 전체가 없다는 판정은 아니다**.

| 테마 | 원경 | 중경·랜드마크 | 플레이 공간 뒤의 장식 | 선택적 근경 |
|---|---|---|---|---|
| T01 월궁 | 달, 밤하늘, 먼 구름 | 궁궐 지붕, 누각, 먼 산 | 담장·기둥·등불 | 모서리 처마·안개 |
| T02 구름고래 목장 | 하늘, 먼 구름, 고래 실루엣 | 부유 지형·목장·풍차 | 울타리·목장 시설 | 가장자리 구름 |
| T03 별가루 도서관 | 별빛 창문·먼 서가 | 높은 서가·아치·천문 장식 | 기둥·책·책상 장식 | 화면 끝 책장·현수 장식 |
| T04 시간유리 온실 | 유리 돔 밖 하늘·빛 | 온실 구조·큰 모래시계 | 식물·덩굴·시간 장치 | 가장자리 잎·유리 프레임 |
| T05 오로라 수정광산 | 오로라·동굴 깊이 | 큰 수정·동굴 벽 | 광산 설비·작은 수정 | 화면 끝 암석·수정 |

1차 구성 제안은 **테마별 기본 3레이어 × 5 = 15개**, 근경은 필요할 때 5개를 추가한다. 실제 월드 폭이 넓으면 한 장을 강제로 늘리지 않고 반복 구간·연결 구간·랜드마크 구간으로 제작한다. 최종 픽셀 크기와 PPU는 기존 게임 카메라 및 맵 단위를 확인한 후 확정한다. 로비 규격 352×704를 게임 월드 전체에 그대로 강제하지 않는다.

배경과 분리해야 할 게임 아트:

- 테마별 **실제 충돌 발판/지형 타일셋 5세트**: 현재 맵·타일 단위와 충돌 경계에 맞춰 보강 여부 결정.
- 상호작용 기믹: 문, 체크포인트, 움직이는 발판, 테마 장치 등. 장식 배경에 구워 넣지 않음.
- 방울·출구 등 공통 게임 오브젝트: 실제 게임 상태와 연동되는 별도 에셋.
- 캐릭터·스킬·이펙트: 이번 UI 배경 제작과 별도. 메뉴 토끼를 게임 플레이어로 대체하지 않음.

근경이 플레이어·귀·발·스킬 판정·발판 모서리·방울·출구를 가려서는 안 된다. 접촉할 수 없는 장식 바닥은 실제 발판처럼 보이지 않게 구분한다. 충돌·진행·보상은 아트와 분리된 기존 게임 로직이 결정한다.

## 9. 제작 우선순위와 1차 납품 묶음

| 순서 | 납품 묶음 | 완료 기준 |
|---|---|---|
| P0-1 | 공통 UI 부품과 로비 강화 진입점 | 현재 v7 로비와 어울리는 스타일, 실제 눌릴 위치·상태 정의 |
| P0-2 | 캠페인 테마 선택·스테이지 선택·상세 | 5테마·20노드 대응, 입장 가능/잠금/제작 중 구분 |
| P0-3 | 강화 허브·계정 강화·동물 강화 | 3공통 트랙, 동물 2성장 트랙, 비용·MAX·미설정 상태 정의 |
| P0-4 | 로딩·확인·오류·재시도 | 캠페인 실행 연결과 강화 요청 상태를 구현할 수 있는 디자인 |
| P1 | 테마 대표 5종·캠페인 배경 6종·강화 배경 1종 | 실제 UI를 얹은 두 해상도 목업으로 가독성 검토 |
| P1 | T01 게임 배경 및 기존 타일셋 점검 | 실제 플레이 맵에서 카메라 이동·가림·발판 식별 검증 |
| P2 | T02~T05 게임 배경·기믹 아트 보강 | T01에서 확정한 레이어·반복·정렬 규칙 적용 |

첫 전달 묶음의 수량 기준:

- 전체 화면 설계 **7종** + 기존 로비 진입점 보강 **1건**.
- 공용 확인 모달, 요청/결과 표시, 부족/잠금/오류 안내 템플릿.
- 테마 대표 이미지 **5종**.
- 메뉴용 배경 **7종 제안**. 이미 승인된 로비 배경은 신규 수량에서 제외.
- 계정 강화 트랙 아이콘 **3종**, 공용 성장·액티브·패시브·숙련도 표시.
- 동물 UI 레이아웃 검증용 초상 **1종부터**. 최종 종별 초상/능력 아이콘 수량은 명단 확정 후 산정.
- 게임 배경은 **기본 15레이어 + 선택적 근경 5레이어**를 별도 작업으로 산정.

상점, 결제, 광고 보상, 경쟁·협동 방, 이모티콘, 프로필, 게임 결과·일시정지는 후속 범위다. 이번 화면과 연결되는 공통 버튼·패널·오류 처리의 형태만 재사용 가능하게 만든다.

## 12. 구현 및 검수 체크리스트

- [ ] 시작·로비의 v7 배경과 현재 UI 외형을 유지했다.
- [ ] 로비에서 강화 화면으로 실제 접근할 수 있다.
- [ ] 캠페인 테마→스테이지→상세→시작 흐름과 뒤로 가기가 연결된다.
- [ ] 동물 강화 화면과 캠페인의 고정 동물 안내를 혼동시키지 않는다.
- [ ] 로딩 화면이 실제 캠페인 실행 경로에 연결되고 실패·재시도를 처리한다.
- [ ] 가격·효과·잔액·보상·진행률은 실제 데이터에 근거하며 미설정을 성공처럼 표시하지 않는다.
- [ ] 요청 중 중복 구매를 방지하고 확정 응답 전에 재화를 차감하거나 레벨을 올리지 않는다.
- [ ] 1080×1920·1080×2400에서 Safe Area, 작은 글자, 긴 한글, 큰 숫자, 스크롤을 확인했다.
- [ ] 배경은 클릭을 막지 않고 모달 아래 버튼은 터치를 받지 않는다.
- [ ] 버튼·일반 강화 피드백은 짧게 표현하며 진동·카메라 흔들림·전체 화면 플래시를 추가하지 않는다.
- [ ] 게임 배경이 캐릭터·발판·방울·출구·위험 요소를 가리지 않는다.
- [ ] UI 생성 경로에도 반영되어 재생성 후 유지된다.
- [ ] 관련 정책·화면 이동 테스트를 실제 실행하고 미실행 항목을 구분한다.
- [ ] 기존 플레이어·입력·물리·경제·수동 편집 맵을 UI 작업과 섞어 변경하지 않는다.
