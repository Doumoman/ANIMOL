# 진입 연결선 무작위화 · 지도 하단 테마 이동

이번 패치는 두 가지 변경만 다룬다. 캠페인 시작 셰이더의 가는 연결선 배치를 진입마다 바꾸고, 별자리 지도 하단에 I·II·III·IV 테마 이동 버튼을 추가한다. 기존 네온 지도·별자리 그림·스테이지 별·BM은 유지한다.

## 진입 연결선

기존 별 27개·깊이 3층·연결선 8개·1.10초 전환과 지도 교체 시점은 유지한다. 각 진입을 시작할 때 기존 별 중 서로 다른 두 별을 잇는 연결선 8개를 한 번만 정한다. 자기 자신과의 연결과 중복된 무방향 연결을 제외하고, 과도하게 긴 선·과밀한 연결·교차를 줄인다. 같은 진입의 매 프레임에는 같은 연결을 사용해 선이 깜빡이거나 재추첨되지 않게 한다. 다음 진입에는 직전 구성과 다른 연결을 선택한다.

추첨은 전환 전용 난수 상태를 사용한다. 게임의 전역 난수나 스테이지·장치·전리품 판정에 영향을 주지 않는다. 셰이더는 CPU에서 정한 8개 쌍을 받아 기존 가는 선 표현으로 그린다. 새 별자리 지도 그림이나 기존 정점 연결은 이 무작위화의 대상이 아니다.

## 하단 테마 이동

1080 기준 내비게이션 영역은 기존 선택 정보 패널과 같은 984×240이며, 화면 하단 중앙에서 Safe Area 기준 24만큼 떨어진다. 네 칸은 각각 246 너비를 차지하고 각 버튼은 234×192, 칸 안에서 좌우 6·상하 24 여백을 가진다. 글자는 흰 갈무리14의 I·II·III·IV만 표시한다. 원래 네온 UI와 맞춘 정적 PNG 상태를 사용하며 배경색이나 프레임을 런타임에 다시 그리지 않는다.

| 버튼 | 대상 |
|---|---|
| I | 별길 목장 |
| II | 잔영 극장 |
| III | 낙일 성소 |
| IV | 별너울 해안 |

버튼을 누르면 실제 카탈로그의 해당 테마 startY로 약 0.42초 동안 부드럽게 스크롤한다. 스크롤 범위를 콘텐츠와 뷰포트 크기에 맞게 제한하며 새 버튼 입력은 현재 위치에서 새 목적지로 전환한다. 손가락 드래그·휠 등 수동 조작은 자동 스크롤을 취소한다. 직접 스크롤해도 현재 테마 강조 표시가 갱신된다.

구매하지 않은 테마도 지도 위치를 볼 수 있다. 버튼이 구매·스테이지 입장·클리어·망원경 소모를 실행하지 않으며 기존 해금·입장 검사는 실제 입장 버튼에 그대로 남는다.

## 선택 정보와의 전환

지도 진입 때 네 버튼을 표시하고 선택 정보 패널은 숨긴다. 별을 처음 선택하면 네 버튼의 입력을 즉시 차단한다. 0.07초 동안 위로 14만큼 가볍게 튀고, 총 0.28초까지 아래로 내려가 사라진다. 버튼이 사라진 뒤 기존 정보 패널을 0.20초 동안 올린다. 두 영역이 동시에 겹쳐 보이지 않게 한다. 이미 패널이 열린 상태에서 다른 별을 선택하면 정보를 갱신하며 같은 대기 연출을 반복하지 않는다.

선택 정보 패널을 닫고 지도 탐색으로 돌아오면 네 버튼을 약 0.18초에 걸쳐 복귀시킨다. 지도 이탈·재진입·포커스·일시정지·비활성화에서도 지연된 콜백이나 화면 밖 입력 영역이 남지 않아야 한다. 기존 움직임 감소에서는 스크롤과 등장·퇴장을 즉시 완료한다. 별의 기존 선택 4fps와 번호·잠금·선택 표시의 고정 동작은 유지한다.

## 적용 범위

기존 최신 UI 설치 위에 이번 패치 파일만 같은 경로로 병합한다. 실제 활성 Scene 또는 Prefab Stage의 NotebookRoot를 선택하고 `ANIMOL > New Notebook UI > Apply Theme Navigation To Selected Notebook`을 실행한다. 기존 지도 전체를 다시 만들지 않고 하단 내비게이션과 참조만 추가·갱신한다. Undo와 실패 복원을 확인하고 결과를 검토한 뒤 저장한다. 전체 씬 생성이나 이전 네온 지도 재생성은 이번 패치의 적용 단계가 아니다.

원본 얼굴 PNG·셰이더·모션, 배경·캐릭터·32개 별자리 그림·110개 스테이지 좌표와 원래 진행선, 48개 별 프레임, 메인·설정·인게임 HUD·클리어 UI, 지갑·구매·광고·스토리 서비스는 유지한다. 일반 시간 회복을 제외하면 이번 기능 자체로 재화·진행 기록이 달라지지 않는다.

브라우저의 셰이더·UI 검증과 C# 구문 검사를 실제 Unity 컴파일·Play Mode·Prefab Stage·Undo·모바일 GPU 성능 검증과 구분한다. 제공 환경에는 실제 Unity 프로젝트·Editor가 없어 후자의 검증은 별도다.
