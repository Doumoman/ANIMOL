ANIMOL 기존 프로젝트에 별길 목장 V04 아트와 연출을 적용하라.
설명만 작성하지 말고 실제 파일·프리팹·씬에 적용하고 검증 결과까지 남겨라.
입력 자산은 프로젝트 루트 또는 mcp_inbox에 둔 ANIMOL_REFERENCE_SPRITES_V04.zip이다.
ZIP 안 README_KO.md, manifest.json, unity_import_manifest.json을 먼저 읽어라.
큰 JSON은 프로그램으로 전체 파싱하고 필요한 요약만 출력하라.
reference/art_reference.png는 그림체·비례 확인용이며 현재 맵/고정 COST 24를 이 그림으로 덮어쓰지 말라.
프로젝트의 AGENTS.md, ProjectSettings/ProjectVersion.txt, Packages/manifest.json을 읽어 현재 환경을 확인하라.

1. 이 작업에서 유지해야 하는 게임 규칙
- 세로 모바일 중심 2D 탑뷰 스와이프 퍼즐이다.
- 바닥은 상하좌우 정렬된 정사각형 셀이다.
- 유효한 스와이프·밀기 한 번의 코스트는 1이다.
- 막혀 아무 상태 변화가 없는 입력은 코스트 0이며 장치 턴도 진행하지 않는다.
- 한 입력 안의 굴림·포털·무빙워크·바람 등 자동 연쇄에는 추가 코스트가 없다.
- 폭탄·석상·무대처럼 행동에 반응하는 장치는 기존 유효 행동 기준으로만 갱신한다.
- 방울 3개 수집 후 출구에 도착해야 성공한다.
- 스와이프 이동 거리와 정지 조건은 실제 기존 코드를 확인해 유지하라.
- 기존 코스트 0 처리, 리셋, 실패, 성공, 자동 연쇄 종료 규칙도 유지하라.
- 아트나 애니메이션 때문에 턴·코스트·이동·충돌·수집 횟수가 달라져서는 안 된다.

2. 실제 코드의 연결 지점부터 찾기
- 현재 플레이 씬, 맵 데이터, 그리드 변환, 입력 처리, 이동/밀기, 충돌 판정을 확인하라.
- 코스트와 유효 행동 커밋, 장치 턴, 자동 연쇄의 소유자를 찾아라.
- 방울의 수집/중복 방지, 출구 조건, 승리/실패, 리셋과 일시정지 경로를 찾아라.
- HUD와 기존 스프라이트 애니메이터, 오디오, 햅틱 서비스의 소유자도 찾아라.
- 실제 파일명과 클래스/이벤트명을 기록하고 그 지점에 최소한의 표현 어댑터를 연결하라.
- 이미 있는 애니메이터나 이벤트를 재사용하고, 병렬 코스트/턴/수집 매니저를 만들지 말라.
- 과거 러너·점프·스태미나 규칙을 이번 탑뷰 퍼즐에 섞지 말라.
- 탑뷰 퍼즐 구현 자체가 없다면 아트 임포트와 독립 검수 씬은 완성하고, 실제 적용 불가 원인을 보고하라.
- 이를 숨기기 위해 기존 게임을 임의로 다른 이동 규칙으로 재작성하지 말라.

3. 자산 임포트와 크기
- 사용 자산을 Assets/ANIMOL/Art/StarwayPasture/V04 아래로 정리하라.
- sprites/, 필요한 개별 animation 프레임, background/만 게임 자산으로 가져와라.
- preview/, source/, reference/, 검수 합성 PNG/GIF를 게임 스프라이트로 가져오지 말라.
- 이 적용에서는 개별 프레임을 사용하고 _sheet.png를 별도의 중복 재생 자산으로 연결하지 말라.
- 기존 자산을 교체할 때 참조와 .meta/GUID를 보존하거나 모든 참조를 검증하여 갱신하라.
- unity_import_manifest.json은 배열 구조여서 JsonUtility로 읽을 수 있다. 불필요한 JSON 의존성을 추가하지 말라.
- 전경 PNG는 Texture Type=Sprite, Alpha Source=Input, Alpha Is Transparency=true로 설정하라.
- Mip Maps=false, Wrap=Clamp, NPOT 리사이즈 없음, 우선 무압축으로 검수하라.
- 이미지와 프레임 크기를 자동 축소하는 Max Size/플랫폼 Override를 제거하라.
- Mesh Type=Full Rect, Custom Pivot를 manifest 값으로 명시하라.
- Point/Nearest가 기본이며 soap_bubble/bubble 애니메이션만 Bilinear를 사용하라.
- 패킹을 사용할 때 회전/타이트 패킹을 끄고 패딩 4px로 UV 번짐을 검수하라.
- 기존 렌더 파이프라인에 맞는 스프라이트 셰이더와 올바른 알파 블렌딩을 사용하라.
- 원화의 명암은 이미 그려져 있으므로 별도의 강한 조명·후처리로 색을 바꾸지 말라.
- 새 팩의 한 논리 셀 시각 폭은 80px이고 96px는 패딩 캔버스다.
- 기존 한 셀의 월드 폭이 s라면 자산별 PPU=pixelsPerCell/s로 맞춰라.
- pixelsPerCell은 일반 픽셀 자산 80, 월드 방울/방울 애니메이션 128이다. s=1이면 각각 80/128 PPU다.
- 방울의 실제 원은 약 0.75칸 크기다. 128px 방울 프레임을 80 PPU로 가져와 큰 원으로 만들지 말라.
- 프로젝트 전체 PPU·Grid·카메라·충돌 크기를 일괄 바꾸지 말라.
- 기존 물리/논리 Root는 유지하고 필요한 오프셋은 Renderer 자식에서만 조정하라.
- 벽/상자/이동패드는 첫 논리 셀 중심, 캐릭터는 발 기준, 방울은 원 중심으로 지정된 Pivot을 사용하라.
- 기존 AssetPostprocessor가 32 PPU/압축/Pivot을 덮어쓰는지도 확인하고 V04 경로에 한정해 조정하라.
- Renderer.bounds/자동 타일 콜라이더로 충돌 크기가 바뀌지 않도록 기존 논리 점유와 Collider를 보존하라.
- 피벗은 왼쪽 위 좌표 기준이며 Unity 정규화 값은 (x/width, 1-y/height)다.
- 프레임마다 Trim/자동 Pivot/Bounds 중심을 다시 계산하지 말라.

4. 수풀 연결과 잘림 방지
- 단일 수풀은 vine_tile이다. 끝이 잘린 V02/V03 덩굴 이미지는 교체하라.
- vines는 온전한 두 단위를 세로로, vine_strip은 온전한 세 단위를 가로로 조립한 이미지다.
- 단일 단위의 간격은 가로·세로 모두 80px다. 96px 캔버스 크기를 간격으로 쓰지 말라.
- 수풀 3종의 Pivot=[48,48]은 첫 논리 셀의 중심이다.
- visual_roots는 흔들림을 고정하는 점이며 배치 Pivot과 다르다. 배치에 혼용하지 말라.
- 개별 vine_tile 배치와 vines/vine_strip 묶음 배치를 같은 칸에 중복 생성하지 말라.
- 논리 칸마다 Sprite를 80x80 Rect로 잘라 다시 생성하지 말라. 96x96 전체 프레임을 유지하라.
- 잎이 물리 셀 경계를 넘는다고 SpriteMask/RectMask2D/셀 사각형으로 클리핑하지 말라.
- SpriteRenderer 크기·Draw Mode·Tilemap Anchor·행 방향·정렬을 실제 맵 좌표와 맞춰라.
- 행 축 방향이 PNG와 다르면 묶음 Renderer의 셀 기준 오프셋만 조정하고 실제 점유 셀은 바꾸지 말라.
- Sprite Sort Point/Sorting Layer/Order를 확인하고 아랫줄 수풀이 잘못 가려지지 않게 하라.
- 셀 인덱스나 충돌 순서로 시각 Root를 이동시키지 말고 렌더 순서만 수정하라.
- Tilemap을 사용하면 Chunk Culling Bounds를 실제 스프라이트/흔들림 외곽에 맞춰 검수하라.
- Auto를 먼저 확인하고, 필요할 때만 해당 수풀 Tilemap의 Manual Bounds를 늘려라.
- Sprite Atlas와 일반 텍스처 양쪽에서 연결부를 확인하라.
- 콜라이더는 기존 맵의 고체/장식 역할과 논리 점유를 유지하라. 알파 모양으로 재생성하지 말라.

5. 애니메이션과 기존 사건 연결
- manifest의 프레임별 duration_ms를 정확히 사용하여 Sprite 키프레임을 생성하라.
- 임의의 균등 fps로 바꾸지 말고 누적 시간에 프레임을 배치하라.
- 클립 끝 시간을 보장하고 스프라이트 보간 없이 이산적으로 바꿔라.
- idle은 loop, touch와 collect는 one-shot이다. 기존 일시정지 정책에 연동하라.
- 식물의 idle 시작 위상을 분산하고 물리 Root/Collider/Grid는 움직이지 말라.
- 위상 분산은 시각 ID 해시/독립 시각 RNG를 사용하고 주사위 등 게임플레이 RNG를 소비하지 말라.
- 식물 touch는 이미 발생하는 접촉/밀기 사건에서 한 번만 호출하라.
- 트리거 의미가 없는 단순 이웃 칸까지 매 프레임 흔들지 말라.
- 재접촉은 touch 재시작으로 처리하고 흔들림을 무한 중첩하지 말라.
- touch 450ms가 끝나면 idle 첫 프레임으로 정착한다.
- Renderer의 스프라이트 또는 자식 표현만 바꾸고 이동 가능 칸을 가리지 말라.
- 방울은 접촉 순간 기존 로직에서 수집 판정을 딱 한 번 커밋한다.
- 즉시 해당 방울의 수집 충돌을 끄고 bubble_collect를 재생하라.
- 기존 로직이 수집 즉시 엔티티를 제거한다면 판정을 늦추지 말고 비상호작용 FX 시각 객체로 분리해 재생하라.
- 수집 수/HUD는 즉시 갱신하고, 280ms 시각 효과 때문에 자동 연쇄/다음 입력을 기다리게 하지 말라.
- bubble_collect 마지막 프레임은 완전 투명하다. 끝나면 풀 반환/비활성화를 하라.
- AnimationEvent가 수집·코스트·턴을 다시 커밋하지 않게 하라.
- 풀에서 재사용할 때 idle, visibility, 충돌, collected 상태를 모두 복원하라.
- 기존 pop 효과음이 있으면 막 끊김 시점(접촉 뒤 100ms)에 한 번 동기화하라.
- 기존 짧은 수집 햅틱 서비스가 있다면 설정이 켜진 모바일에서만 연결하라.
- idle에는 사운드·햅틱을 추가하지 말고 일반 접촉에 큰 흔들림·줌·히트 스톱을 붙이지 말라.

6. HUD와 출구
- 플레이 HUD는 일시정지, 남은 코스트, 수집 방울 수의 위계를 유지하라.
- blank 패널에 실제 숫자를 렌더링하고 원본 화면의 COST 24 / 0/3을 고정 텍스트로 쓰지 말라.
- pause Normal/Press/Release/Disabled를 연결하라. 모바일에 Hover 상태를 새로 요구하지 말라.
- 기존 읽기 쉬운 픽셀 폰트를 재사용하고 Safe Area, 숫자 대비, 패널 안쪽 여백을 확인하라.
- 출구는 exit_arch/exit_star/exit_steps를 같은 출구 Root의 별도 시각 레이어로 사용하라.
- 별 중심을 아치 PNG 왼쪽 위 기준 [112,82]에 배치하고 월드 좌표에는 아치 Pivot을 반영하라.
- 출구 활성화·승리는 기존 규칙에서 판단하고 별 표시가 승리 판정을 대신하지 않게 하라.
- 3개 미만 출구 진입은 성공하지 않으며 3개 이상에서 기존 이동/연쇄가 정착하면 성공을 한 번 처리한다.
- 기존 결과 화면/보상 경로를 연결하고 성공 시 코스트나 수집을 중복 변경하지 말라.

7. 반드시 실행할 검수
- 독립 ANIMOL_Starway_Art_QA 씬에 1개, 1x2, 2x1, 3x1, 1x3, 3x3 수풀을 배치하라.
- 밝음/어두움/풀 배경과 정수배 1x·2x·4x에서 외곽 누끼·내부 구멍·연결부를 확인하라.
- idle과 touch의 최대 기울기에서 위·아래·양끝 잎과 카메라/Tilemap 경계 잘림을 확인하라.
- 단일 tile 조립과 aggregate 이미지 배치의 셀 위치가 일치하는지 비교하라.
- 벽·상자·울타리·캐릭터·UI·달·구름·방울에도 배경 조각과 색 번짐이 없어야 한다.
- PlayMode: 유효 이동 코스트 -1, 무효 입력 코스트/장치 턴 변화 없음.
- PlayMode: 유효 밀기 -1, 막힌 밀기는 기존 상태 불변.
- PlayMode: 무빙워크/바람/포털 등 한 행동의 자동 연쇄에 추가 코스트 없음.
- PlayMode: 방울 중복 접촉/재접촉/풀 재사용에서 중복 수집 없음.
- PlayMode: 0/3->3/3, 출구 잠김/해제, 성공 1회, 리셋, 일시정지/재개를 확인하라.
- 애니메이션을 끄고 켜도 논리 결과가 같아야 한다.
- 프로젝트가 사용하는 Unity 버전으로 컴파일, EditMode/PlayMode 및 가능한 세로 모바일 화면 검사를 하라.
- 실제 실행할 수 없는 항목은 실행 완료로 기록하지 말고 사유와 재현 절차를 남겨라.

- 현재 코드에서 확인한 수풀 잘림 원인(원본 Rect/간격/Pivot/Mask/Sort/Culling)을 구분해 기록하라.
