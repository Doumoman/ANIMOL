ANIMOL 기억 극장 V01 실제 적용 지시문

이 문서 전체를 작업 지시로 읽고 현재 Unity 프로젝트에 실제 적용해라.
계획이나 코드 예시만 제출하지 말고, 임포트·프리팹·현재 플레이 씬 연결·실행 검수까지 수행해라.
원본 파일: ANIMOL_MEMORY_THEATER_V01.zip.
기존 V04와 ANIMOL_DEVICE8_V01은 유지하고 기억 극장 테마 변형으로 추가한다.

1. 먼저 현재 프로젝트 확인
- AGENTS.md, Unity 버전, 현재 퍼즐 씬, 테마 선택/레벨 데이터, Grid 셀 크기를 확인한다.
- 이 프로젝트는 현재 세로 2D 탑뷰 스와이프 코스트 퍼즐이다. 레거시 러너 규칙을 섞지 않는다.
- 현재 입력→유효 행동 확정→자동 연쇄→장치 턴→결과 이벤트의 실제 호출 지점을 찾는다.
- 실제 구현 여부, 표현 누락, 중복 구독/연출/프리팹을 조사한 뒤 기존 사건에 연결한다.
- 현재 브랜치의 사용자 변경을 보존한다. 다른 테마나 관련 없는 시스템을 일괄 정리하지 않는다.

2. 읽을 자료
- README_KO.txt, manifest.json, unity_import_manifest.json.
- DEVICE_EVENT_BINDINGS.csv, data/DICE_ORIENTATIONS.json.
- QA_REPORT.json, source/ADDED_DECISIONS_KO.txt.
- preview/PLAYFIELD.png는 아트 배치 예시다. 이 배치를 실제 새 퍼즐 맵으로 간주하지 않는다.
- source와 preview, 생성 원화를 게임용 Sprite로 임포트하지 않는다.

3. 자산 경로와 임포트
- 프로젝트의 기존 sprites 폴더 규칙을 따라 테마 식별자를 memory_theater로 둔다.
- 공통 변형: sprites/obstacles/common/memory_theater/장치별 폴더.
- 전용 7종: sprites/obstacles/memory_theater/장치별 폴더.
- 바닥/벽은 tiles, 상자는 props, 배경/막/기둥/조명은 background에 둔다.
- 기존 별길 목장의 공통 장치 프리팹 로직을 재사용하고 기억 극장 Sprite/클립만 테마별 데이터로 교체한다.
- 같은 상태에 단일 PNG와 시트를 동시에 연결하지 않는다. 이미 쓰는 프로젝트 방식 하나를 선택한다.
- Point 필터, 압축 없음, Mipmap 없음, Sprite Full Rect를 기본으로 한다.
- Sprite Atlas에서도 샘플링/압축으로 새 RGB와 색 번짐이 생기지 않는지 확인한다.
- 이 팩은 논리 셀80px, 보통 캔버스96px다. 캔버스 여백을 셀 간격으로 해석하지 않는다.
- 한 셀 월드 폭이 s면 PPU=80/s. Grid/Collider 크기를 새 아트 크기에 맞춰 바꾸지 않는다.
- JSON 피벗은 왼쪽 위 픽셀 기준이다. normalized=(pivotX/width,1-pivotY/height).
- 책장256px 캔버스와 중앙피벗, 인형 발피벗, 막 고정점을 개별 메타데이터대로 적용한다.
- 책장·막처럼 셀 밖으로 보이는 부분은 셀 경계에서 자르거나 RectMask로 가리지 않는다.
- 배경을 카메라 뒤에 두고 평평한 정사각형 타일로 보드를 구성한다. 퍼즐 칸에 원근을 적용하지 않는다.
- 기존 상단 일시정지/남은 코스트/방울 수 UI와 플레이어·분홍 방울을 유지한다.

4. 공통 실행 계약
- 유효 스와이프·밀기1회 비용1, 변화 없는 입력 비용0·장치 턴0.
- 한 행동 안의 굴림/무빙워크/반사/기타 자동 연쇄는 추가 비용0.
- 방울3개 후 출구 규칙과 현재 이동거리·정지 규칙을 유지한다.
- 논리 좌표·충돌·장치 상태는 기존 코드가 소유한다. 애니메이션 이벤트로 비용/턴/상태를 다시 커밋하지 않는다.
- 동일 행동 ID/사건에 이펙트가 중복 재생되지 않게 한다. Retry/씬 재진입 시 구독 중복을 방지한다.
- 루트 이동은 기존 from/to에 연결한다. PNG에는 셀 간 위치 이동이 없으므로 Transform에서 한 번만 보간한다.
- 무대/주사위/석상/인형을 한 칸96px 이동시키지 말고 기존80px 논리 셀 또는 해당 월드 거리로 이동한다.
- 프레임 시간은 JSON durationMilliseconds를 누적해서 사용한다. 모두 같은 FPS로 바꾸지 않는다.
- 시각 효과 종료까지 다음 입력을 일괄 잠그지 않는다. 기존 입력 큐·취소·정착 정책을 존중한다.
- 시각 보간은 기존 엔진 구조에 연결하고 픽셀 위치 안정성을 확인한다. 외부 Tween 패키지를 새로 도입할 필요는 없다.

5. 장치별 연결
07 무빙워크
- 방향 enum을 e/s/w/n=화면 우/하/좌/상에 매핑한다.
- run 반복은 시각만 움직인다. 대상 운반과 끝/막힘 정지는 기존 로직 사건을 따른다.
09 단방향 문
- 허용 통과 시작=open, 실제 통과 완료/칸 이탈=close.
- 역방향 거부에는 짧은 blocked만 사용하고 비용/장치 턴을 추가하지 않는다.
- 고정 기둥 전체를 흔들거나 전체 Sprite를 회전시키지 않는다.
18 튕김 모서리
- nw/ne/se/sw는 벽 모서리 위치, 빈 쪽은 반대다. README의 외형-벡터 표와 기존 반사 enum을 대조한다.
- 내부 투명 홈을 메우지 않는다. 기존 반사 확정 순간에 impact를 한 번 재생한다.
19 제동판
- 강제 이동이 실제로 멈춘 순간 brake. 연출 때문에 한 칸 튕기거나 이동을 재개하지 않는다.
04 교대 무대 셔터
- A/B는 한 줄/두 줄 문양이다. 유효 행동에만 현재 위상 전후의 open/close를 연결한다.
- 다음에 닫힐 셔터에만 closing_warning. idle 시간으로 상태가 바뀌지 않는다.
- 플레이어나 물체가 점유하면 열린 상태를 유지하고 blocked_open을 사용한다.
- 점유 때문에 닫지 못했을 때 두 셔터 위상 처리 방식은 기획서 미확정이다. 실제 코드 정책을 확인한다.
06 행동 연동 이동 무대
- 고정 레일과 움직이는 무대를 분리한다. 유효 행동에만 한 칸 전진한다.
- advance는220ms 시각 권장값이며 위치는 기존 from/to에 연결한다. 기존 이동 타이밍과 필요한 경우 동기화한다.
- 끝에서 방향 표시를 바꾸고 다음 도착 칸 outline은 기존 예정 칸에만 둔다.
- 막힌 다음 칸 앞 정지는 기존 로직을 따른다. 방향 유지/반전/다음 턴 재시도 정책을 새로 추측하지 않는다.
08 회전 책장
- 연결 누름판의 실제 활성 사건에 중앙축90도 회전을 연결한다.
- 0/90/180/270 완료 상태와 각 시계/반시계8클립을 사용한다. 회전할 때 중앙축이 이동하면 안 된다.
- 누름판 지속 점유 중 반복 회전 여부와 대상 점유 충돌은 기존 코드 정책을 따른다.
- 기획서에서 회전 보류/전체 입력 취소가 미확정이다. 압착 규칙을 임의로 추가하지 않는다.
13 연쇄 도미노벽
- 실제로 접히는 각 조각의 사건 순서대로 fold를 재생한다. 전체 벽을 동시에 사라지게 하지 않는다.
- 연쇄 시작 입력만 비용1, 조각마다 비용/장치 턴을 추가하지 않는다.
- 완료 시 folded 상태를 유지하고 이동 가능 여부는 기존 커밋 값을 따른다.
- 접힐 자리/연쇄 끝 점유 시 중단·불발 조건은 기존 구현을 확인한다.
17 돌진 석상
- 발견→warning_enter→warning_hold와 확정된 직선 danger cell 표시.
- 다음 플레이어 유효 행동→charge_enter→charge→실제 충돌/정지→impact/recover.
- 경고 후 플레이어가 옆으로 피했다고 경로를 다시 추적하지 않는다.
- warning_hold 루프가 끝났다고 돌진하지 않는다. 다음 유효 행동 사건만 돌진을 시작한다.
- 금 간 벽 파괴는 기존 파괴 사건에 cracked_wall_break를 연결한다. 마지막 완전 투명 프레임은 정상이다.
- 단단한 벽 앞 실제 정지 위치, 플레이어 접촉 결과 등은 기존 코드에 있는 정책을 사용한다.
22 주사위 블록
- 여섯 면 전체 방향을 보존한다. top 값 하나만으로 방향을 추정하거나 매번 초기화하지 않는다.
- 초기 위1/아래6/북5/남2/동3/서4, 첫 굴림 결과 우4/좌3/상2/하5를 대조한다.
- DICE_ORIENTATIONS의24상태·96전이는 렌더 상태 검증 자료다. 기존 로직 표현에 맞춰 어댑터로 연결한다.
- 실제 한 칸 굴린 경우에만 상태를 바꾸고 해당 fromOrientation+direction 클립을 재생한다.
- 움직이지 않은 밀기와 순간이동에는 굴림이나 면 갱신이 없어야 한다.
- 같은 윗면과 숫자 발판 점유가 동시에 만족할 때 on; 일치/점유가 풀리면 off.
- next_top 예고는 기존 예정 이동이 확정될 수 있는 칸에만 표시한다. 모든 칸에 상시 표시하지 않는다.
23 겁쟁이 인형
- 유효 행동 후 상하좌우 바로 인접했을 때 플레이어를 향한 모습으로 startle.
- retreat 파일의 방향은 바라보는 방향이다. 실제 이동은 그 반대쪽 한 칸이다.
- 행동당 한 번만 물러나며, 막혔을 때 blocked를 재생하고 자리에 둔다. 먼 도피 경로를 탐색하지 않는다.
- idle 흔들림이 새 행동이나 충돌 이동을 일으키지 않게 한다.

6. 연출 강도와 중복 정리
- 입력→준비→행동→충돌/변화→결과→정착 순서로 실제 사건을 확인한다.
- 일반 이동은 방향/위치 보간만, 문·제동·모서리는 짧은 국소 반응만 사용한다.
- 셔터/책장/주사위는 전후 상태를 분명히 보이는 것이 우선이다.
- 석상 경고는 한 턴 유지하고 실제 충돌에만 기존 사운드·짧은 햅틱을 연결한다.
- 이 팩에는 오디오/햅틱 바이너리 자산이 없다. 프로젝트에 있는 대응 자산/플랫폼 서비스를 재사용한다.
- 모든 입력에 화면 흔들림·카메라 줌·Hit Stop·Particle를 일괄 추가하지 않는다.
- 기존 강조 효과와 새 프레임 강조가 같은 사건에서 중복되면 더 명확한 한 쪽으로 통합한다.
- 버튼/UI는 이번 팩에서 새로 만들지 않는다. 이미 있는 상태·코스트 표시는 기존 기능을 유지한다.
- 중복된 Animator/프레임 플레이어/이벤트 구독을 확인하고 유지·통합·삭제 판단과 근거를 기록한다.

7. 미확정 처리
- 미확정 정책이 현재 코드에 있으면 실제 동작과 선택 근거를 결과 문서에 명시한다.
- 코드에도 없다면 그 미정 분기만 표시하고 다른 장치의 적용·검수는 계속 완료한다.
- 압착/추가 비용/임의 경로 탐색/스태미나/대기시간을 새 게임 규칙으로 도입하지 않는다.

8. 실제 완료 검수
- 기억 극장 QA 씬과 현재 플레이 씬에서 11종을 실제 참조하는지 확인한다.
- 방향별 크기·피벗·레이어·픽셀 샘플링·Atlas 가장자리·책장 캔버스 잘림을 확인한다.
- 타일의 가로/세로 반복에서 틈과 겹침, 열린 문/셔터/모서리의 의도된 투명을 확인한다.
- 무효 입력에서는 비용·장치 턴·주사위 면·인형 위치가 그대로인지 확인한다.
- 한 유효 행동의 자동 연쇄가 추가 비용을 만들지 않는지 확인한다.
- 셔터 점유 보호, 무대 끝/막힘, 책장 대상 점유, 도미노 연쇄 차단 사례를 실제 구현 범위에서 검수한다.
- 석상은 한 턴 예고한 선을 유지하고, Idle 시간이나 무효 입력으로 돌진하지 않는지 확인한다.
- 주사위24상태/96전이, 반대 방향 왕복, 같은 방향4번, 숫자 발판 일치/해제를 확인한다.
- 인형 4방향 인접, 후퇴 칸 막힘, 대각선 비인접, 행동당1회 반응을 확인한다.
- Retry/테마 전환/씬 재진입에서 중복 구독·상태 잔류·미리보기 오브젝트 잔류가 없는지 확인한다.
- 가능한 실제 PlayMode와 모바일 세로 해상도에서 검수한다. 수행하지 못한 항목은 미실행으로 적는다.
