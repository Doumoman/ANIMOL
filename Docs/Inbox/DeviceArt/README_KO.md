# ANIMOL · 공통 + 별길 목장 장치 8종 · V01

기존 ANIMOL_REFERENCE_SPRITES_V04에 추가하는 장치 팩입니다. 기본 배경·캐릭터·UI·비눗방울을 교체하는 팩이 아닙니다.

게임용 정적 PNG 52개, 애니메이션 59종, 개별 프레임 402개와 시트를 포함합니다. `sprites/` 아래의 신규 게임 PNG는 Sweetie16의 15색만 사용하며 알파는 0 또는 255입니다. 생성 원화와 미리보기는 게임 PNG의 색상 검수 대상이 아닙니다.

## 크기와 배치

V04의 배치 크기를 유지한 **80px 논리 셀 기준**입니다. 네이티브 32×32 타일 팩이 아닙니다.

| 대상 | PNG 캔버스 | PNG 왼쪽 위 기준 피벗 | 셀 간격 |
|---|---|---|---|
| 일반 장치·효과·누름판·연결 덩굴 | 96×96 | [48,48] | 80px |
| 펼친/접힌 다리 및 해당 애니메이션 | 128×128 | [64,64] | 80px |
| 병아리 | 64×64 | [32,54], 발 기준 | 기존 추종 경로 |

Unity에서 한 셀의 월드 폭이 s이면 PPU=80/s입니다. 전역 Grid나 물리 크기를 바꾸지 않습니다. 개별 자산의 실제 캔버스·피벗·시간은 `unity_import_manifest.json`이 기준입니다. Unity 정규화 피벗은 `(pivotX/width, 1-pivotY/height)`입니다.

덩굴 다리는 온전한 잎을 보존하기 위해 128px 프레임을 사용합니다. 전체 프레임을 80px 간격으로 겹쳐 배치합니다. 가로·세로 반복에서도 잎을 셀마다 자르지 않습니다. 다리 양끝은 기존 땅과 연결하고, 외곽 여유 영역을 별도 이동 가능 칸으로 계산하지 않습니다. 장식 끝 부품은 필요할 때 별도 시각 레이어로 사용합니다.

## 튕김 모서리의 홈

사용자가 제공한 오목한 홈 사진을 형태 기준으로 삼았습니다. 내부의 빈 공간은 실제 투명 영역입니다. 이 공간을 자동 누끼 보정으로 채우거나, 단단한 정사각형 벽으로 해석하지 않습니다.

이름은 **단단한 벽이 붙어 있는 모서리**를 나타냅니다. 예를 들어 NW는 위·왼쪽 벽이며, 열린 쪽은 SE입니다.

| 외형 | 열린 쪽 | 들어오는 이동 벡터 → 나가는 벡터 |
|---|---|---|
| NW | SE | N→E, W→S |
| NE | SW | E→S, N→W |
| SE | NW | E→N, S→W |
| SW | NE | W→N, S→E |

이는 외형 연결용 표입니다. 프로젝트의 모서리 enum·좌표계·기존 반사 규칙을 확인해 매핑하고, 이 표만으로 새 이동 로직을 만들지 않습니다.

## 파일 사용

- `sprites/obstacles/common/`: 공통 4종.
- `sprites/obstacles/starway_pasture/`: 별길 목장 4종.
- 장치별 `static/`: 정적 모습과 구성 부품.
- 장치별 `animation/클립명/`: 개별 프레임과 `_sheet.png`.
- `manifest.json`: 장치, 자산, 방향, 상태, 시트 정보.
- `unity_import_manifest.json`: 배열형 Unity 임포트 정보.
- `DEVICE_EVENT_BINDINGS.csv`: 클립별 기존 사건 연결표.
- `UNITY_APPLY_DEVICE8_V01.txt`: 실제 프로젝트 적용 지시문.
- `PREVIEW.html`: 압축을 풀고 열어 방향·상태별 프레임을 확인하는 오프라인 재생기.
- `preview/`: 합성 이미지와 GIF. 게임용 스프라이트로 가져오지 않습니다.
- `source/`: 제작 프롬프트, 추가 결정, 검수 기록. Unity로 가져오지 않습니다.

송풍기의 `blower_housing_*`는 분리 구성용 부품입니다. 기본 적용에서는 완성된 `blower_run_*` 프레임을 재생하며 몸체를 중복으로 겹치지 않습니다. GIF는 50ms 간격으로 샘플링한 미리보기이고, 게임에서는 PNG와 정확한 JSON 시간을 사용합니다.

## 연출과 게임 로직

프레임은 스프라이트 교체 방식으로 재생합니다. idle/run은 표기된 경우에만 반복하고, open/close/impact/press/insert/extend/retract는 한 번 재생한 뒤 완료 상태를 유지합니다. 다음 논리 입력을 모든 시각 효과 종료까지 일괄 대기시키지 않습니다.

입력→준비→행동→변화→결과→정착 흐름은 기존 사건을 표현하는 데 사용합니다. 무빙워크는 이동 방향을 계속 보여주고, 문은 허용된 통과에서만 열립니다. 모서리·제동판은 접촉 순간 짧게 반응합니다. 별돌·누름판·다리는 상태 전후를 분명히 보여주고, 병아리는 실제로 지나온 경로를 따라갈 때만 걷습니다. 일반 접촉에 화면 흔들림·줌·히트 스톱을 일괄 추가하지 않습니다.

유효 행동 코스트 1, 무효 입력 코스트·장치 턴 0, 한 행동 안 자동 연쇄 추가 코스트 0, 방울 3개 후 출구 규칙을 보존합니다. 별돌의 다른 문양 처리, 점유 중 다리 회수, 병아리의 포털·도약·배·둥지 처리는 기획 문서에서 미확정이므로 실제 코드에 있는 규칙만 사용합니다.

## 검수 범위

모든 게임 PNG의 팔레트·알파·투명 픽셀 RGB·캔버스 잘림, 시트와 프레임 일치, 프레임 시간, 완료 상태, 문 기둥 고정, 무빙워크 프레임 고정, 송풍기 몸체 고정, 병아리 발 기준점, 다리 반복 연결, 모서리 내부 투명을 확인했습니다. 의도된 연결 덩굴의 틈을 제외한 내부 투명 구멍은 검수 대상입니다.

실제 Unity 프로젝트가 제공되지 않아 Unity 임포트, 셰이더·Atlas·Tilemap 경계, PlayMode 로직 검수는 실행하지 않았습니다. 이 항목들은 적용 지시문의 완료 조건으로 명시했습니다.
