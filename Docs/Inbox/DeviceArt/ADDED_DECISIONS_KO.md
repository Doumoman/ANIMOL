# 추가한 제작 결정 복기

사용자가 요청한 범위는 기존 그림체 수준의 공통·별길 목장 8종, 방향별 모습, 애니메이션, 첨부 사진처럼 오목한 튕김 홈입니다. 원문 PDF의 ID 07/09/18/19/01/02/20/24를 그대로 사용했습니다.

이번에 제작·적용 편의를 위해 추가한 결정은 다음과 같습니다.

1. V04와 맞추기 위해 논리 셀은 80px로 유지했습니다. 일반 프레임96, 병아리64, 온전한 다리 잎 보존용128px 캔버스를 사용합니다. 이는 네이티브32px 제작이 아닙니다.
2. 새 게임용 PNG는 Sweetie16 안의15색으로 마감하고, 알파0/255와 투명 픽셀RGB0을 적용했습니다. 생성 원화의 보간색·헤일로는 게임용 PNG에 남기지 않습니다.
3. 방향 이름 e/s/w/n은 화면의 우/하/좌/상입니다. 모서리 이름은 벽이 붙은 쪽입니다. 문 기둥·송풍기 몸체·물리 Root는 고정하며 움직이는 부품만 변합니다.
4. 무빙워크는 화살표가 있는 벨트, 문은 열린 통로가 생기는 문짝, 제동판은 두 정지선으로 구분했습니다. 이 구분은 새로운 게임 규칙을 추가하지 않습니다.
5. 튕김 모서리의 열린 내부는 의도된 음영 없는 투명 공간입니다. 외곽을 채우는 누끼 후처리와 분리했습니다.
6. 덩굴 다리는 잎 전체를 보존한128px 프레임을80px 간격으로 겹쳐 연결합니다. 사각 연결 바탕이 튀던 초안은 최종본에서 제거했습니다.
7. 송풍기는 생성 원화에서 몸체와3날개 회전자를 분리해 고정 몸체의12프레임 회전으로 조립했습니다. 원화의 뿌연 바람은 세 개의 단순한 바람줄로 교체했습니다.
8. 별돌과 홈·누름판과 다리는 각각 하나의 장치 시스템으로 계산합니다. 따라서8종이52개의 정적 PNG로 나뉩니다. 구성 부품을 별도의 신규 장치로 세지 않습니다.
9. 프레임 시간은0.12~0.36초의 일반 작동, 짧은 접촉 강조, 잔잔한 idle을 기준으로 정했습니다. 실제 게임 상태 확정은 기존 코드가 담당합니다.
10. 제동판은 방향 제한이 없는 장치이므로 네 개의 가짜 기능 방향을 만들지 않고 두 가지 정지선 배치를 제공합니다. 별돌은 위쪽 꼭짓점을 유지한 네 방향 밀기 동작을 제공합니다.
11. 병아리의 이동거리·코스트·경로 기록, 점유 중 다리 회수, 다른 문양 별돌, 포털·도약·배·둥지 판정은 제작자가 새로 정하지 않았습니다. 미확정 내용은 적용 지시문에 표시했습니다.
12. PNG 검수와 Unity 적용 검수를 구분했습니다. 이 환경에서는 실제 프로젝트가 없어 Unity 실행을 완료했다고 표시하지 않습니다.

GENERATION_PROMPTS.json과 FIX_PROMPTS.json에 사용한 기본 생성 및 수정 프롬프트를 그대로 동봉했습니다. 내장 이미지 생성 도구를 사용했으며, 이후 프레임 분리·크기·팔레트·레이어 조립·시간·검수는 파일 제작 과정에서 고정했습니다.
