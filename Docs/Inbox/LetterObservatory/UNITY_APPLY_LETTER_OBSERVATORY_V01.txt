ANIMOL 편지 천문대 V01 실제 적용 지시문

이 문서 전체를 작업 지시로 읽고 현재 Unity 프로젝트에 실제 적용해라.
계획·예제만 제출하지 말고 자산 임포트·기존 프리팹/테마 연결·현재 플레이 씬·실행 검수까지 수행해라.
대상: ANIMOL_LETTER_OBSERVATORY_V01.zip. 기존 별길 목장·기억 극장 팩과 사용자 변경을 보존한다.

1. 현재 프로젝트와 기존 사건 확인
- AGENTS.md, Unity 버전, 현재 세로 탑뷰 퍼즐 씬, 테마 데이터, Grid 셀 크기를 확인한다.
- 유효 입력 확정→자동 연쇄→장치 갱신→결과 이벤트의 실제 호출 지점을 찾는다.
- 스태미나 러너/플랫포머와 레거시 맵 에디터 규칙을 다시 넣지 않는다.
- 이미 있는 공통 장치 로직을 재사용하며 테마 Sprite와 클립만 분리한다.
- 현재 구현 여부와 표현 누락을 코드에서 확인한다. 이 팩의 QA는 프로젝트 구현 검수가 아니다.

2. 읽을 파일
- README_KO.txt, manifest.json, unity_import_manifest.json.
- data/OPTICS_RULES.json, data/MOTION_BINDINGS.json, DEVICE_EVENT_BINDINGS.csv.
- QA_REPORT.json, POLISH_REVIEW_KO.csv, source/ADDED_DECISIONS_KO.txt.
- 배치 그림과 GIF는 시각 자료다. 새 레벨이나 실제 플레이 검수 증거로 간주하지 않는다.

3. 폴더·임포트·규격
- 테마 식별자는 letter_observatory. 프로젝트의 sprites 폴더 규칙에 맞춰 배치한다.
- 공통4종: sprites/obstacles/common/letter_observatory/장치별 폴더.
- 전용5종: sprites/obstacles/letter_observatory/장치별 폴더.
- 바닥/벽은 tiles, 배경/망원경/편지 장식은 background. source/preview/원화는 런타임에서 제외한다.
- 같은 Sprite를 개별PNG와 시트에서 동시에 생성하지 않는다. 기존 프로젝트 방식 하나를 사용한다.
- Point 필터, 압축 없음, Mipmap 없음, Sprite Full Rect. Atlas에서도 번짐·잘림·색 변경을 검사한다.
- 논리 셀80px, 일반 캔버스96px다. Grid와 Collider를 아트 여백에 맞춰 변경하지 않는다.
- 한 셀 월드 크기가 s면 PPU=80/s. 네이티브32px 팩으로 오인해 PPU32로 덮어쓰지 않는다.
- 유리는128×128, 망원경160×128, 봉투64×64, 별등64×96. 실제 JSON 크기를 읽는다.
- 피벗은 왼쪽 위 픽셀 기준. Unity normalized=(pivotX/width,1-pivotY/height).
- 도약 궤적은256×96/96×256이며 시작점 피벗이 비대칭이다. 중앙으로 덮어쓰지 않는다.
- 배경은1024×1792이며 대부분을 보드에 쓴다. 정사각형 Grid에 원근을 적용하지 않는다.
- 기존 토끼/분홍 방울/상단 일시정지·코스트·방울 수/출구 프리팹을 유지한다.

4. 공통 논리 계약
- 유효 스와이프·밀기1회 비용1, 변화 없는 입력 비용0·장치 턴0.
- 한 행동 안의 도약·견인·포털·무빙워크·반사 연쇄는 추가 비용0.
- 방울3개 후 출구 규칙, 이동 거리·충돌·점유는 기존 코드가 소유한다.
- 시각 프레임 이벤트가 비용·턴·상태를 다시 커밋하지 않게 한다.
- 동일 행동ID/사건에 이펙트 중복 재생·이벤트 중복 구독이 없어야 한다.
- PNG에는 셀 간 이동이 없다. 기존 from/to를 받아 시각 자식만 보간한다.
- JSON의 durationMilliseconds를 누적한다. 모든 클립을 동일FPS로 재작성하지 않는다.
- 연출이 끝날 때까지 입력을 일괄 잠그지 말고 현재 입력 큐·취소 정책을 보존한다.
- idle·점멸·시간 경과가 논리 턴을 진행시키면 안 된다.

5. 공통 장치4종
- 07 무빙워크: e/s/w/n=화면 우/하/좌/상. 벨트 반복은 내부만, 이동은 기존 사건에 연결한다.
- 09 단방향 문: 허용 통과 시작=open, 실제 통과/칸 이탈 완료=close, 역방향 거부=blocked.
- 문 기둥 전체를 회전·흔들지 않는다. 무효 거부에 코스트나 장치 턴을 추가하지 않는다.
- 18 튕김 모서리: nw/ne/se/sw는 벽 모서리 위치이며 열린 홈은 각각se/sw/nw/ne다.
- 모서리 Sprite의 투명 홈을 채우지 않는다. 기존 반사 확정 순간 impact를 한 번만 재생한다.
- 19 제동판: 강제 이동의 실제 정지에 brake를 연결한다. 시각 압축 때문에 새 반동 이동을 만들지 않는다.

6. 03 초승달 도약판
- 현재 로직의 유효 도약 확정→prepare→launch→3칸 이동→land 순서에 연결한다.
- 출발·목적지에 같은 초승달, 필요할 때만3셀 점선과 착지 테두리를 표시한다.
- 한 입력에서3칸 이동하며 자동 이동에 추가 코스트가 없다.
- 시각 높이18px·320ms는 권장값이다. 논리 좌표를 공중 높이만큼 옮기지 않는다.
- 중간 칸 장치 반응, 착지 막힘, 정확한 입력 시점은 기획서 미확정이다. 실제 코드 정책을 먼저 확인한다.
- 막히면 출발하지 않는 안은 초안이며, 이 팩을 근거로 새 규칙으로 확정하지 않는다.

7. 10 광원·거울·빛 감지기
- 광원 방향과 현재 추적 결과를 받아 실선 광선 부품을 타일 경계에서 이어 붙인다.
- 광선은 유리 외형 위, 불투명 몸체 아래. 벽/상자/플레이어 뒤로 광선 잔상을 남기지 않는다.
- slash(/)는 E→N,N→E,W→S,S→W. backslash는 E→S,S→E,W→N,N→W.
- 방향 enum은 진행 방향 기준이다. 입사한 쪽의 방위와 혼동하지 않는다.
- mirror_base·반사면·pivot을 중복 그리지 않는다. 합성 완료 클립을 쓰거나 분리 부품 방식 중 하나만 사용한다.
- 회전 시 받침대를 고정하고 중앙축만 사용한다. 실제 경로 재계산은 기존 논리 커밋 시점에 수행한다.
- 거울 직접 조작 입력은 기획서 미확정이다. 새 버튼·스와이프 규칙을 임의로 넣지 않는다.
- 빛이 닿는 동안 sensor_on, 끊기면 sensor_off. 연결 문 상태는 실제 감지기 결과에 연결한다.
- 수신/해제 애니메이션이 논리 활성 해제를 늦춰 잘못된 통과를 허용하면 안 된다.
- source_off는 이미 비활성 광원 상태가 있는 경우에만 사용한다. 고정 광원에 새 토글 기능을 만들지 않는다.

8. 14 자석 견인
- 연결 스위치의 실제 상태에 activate/active/deactivate를 연결한다.
- 같은 직선 금속 상자만 자석을 향해 장애물 앞까지 이동한다. 나무 상자는 움직이지 않는다.
- 자석 방향은 열린 자극 쪽이고, pull_guide의 이동 화살표는 그 반대다.
- 금속 상자의 루트 이동은 기존 경로와 정지 결과에 연결하고 crate_pull/settle은 시각만 담당한다.
- 이미 막혀 움직이지 못하는 상자는 제자리에 둔다. 여러 상자의 처리 순서는 현재 코드를 따른다.

9. 16 짝 포털
- A/B는 같은 별자리이며 상단 금색 표식1개/2개로 구분한다. 쌍 연결은 기존 ID 데이터로 유지한다.
- 진입 방향과 걷기/미끄러짐 상태를 그대로 보존한다. 텔레포트마다 새 입력을 소비하지 않는다.
- 걸어 진입했으면 짝 포털 다음 한 칸으로 나와 정지, 미끄러져 진입했으면 같은 방향으로 계속한다.
- 출구 다음 칸이 막혔으면 입구 직전에서 정지한다. 최초 걸음 시도 자체가 불가능하면 무효0이다.
- 미끄러지는 도중 불발이면 이전 유효 입력 비용만 유지한다. 불발마다 비용을 추가하지 않는다.
- enter→exit 순서와 기존 위치 커밋을 연결한다. Sprite의 축소·페이드로 Collider를 옮기지 않는다.
- exit_preview는 짝 포털의 진행 방향 바로 다음 칸에, blocked X도 실제 막힌 칸에 표시한다.
- 목적지 포털에 머물렀다는 이유만으로 반복 재진입하지 않게 기존 연쇄 방지 정책을 보존한다.

10. 21 유리벽
- 큰 투명 중심은 의도된 유리다. 알파·불투명 픽셀로 Collider를 자동 생성하지 않는다.
- 온전한 유리는 빛만 통과, 플레이어/물체/바람은 차단한다.
- 직접 걷기나 밀기로 통과하려는 입력은 기존 무효 판정을 따른다.
- 폭탄/석상의 실제 파괴 사건에 방향에 맞는 break를 연결한다.
- cracked는 같은 파괴 연출의 중간 모습이다. 새2회 타격이나 내구도 규칙을 추가하지 않는다.
- broken과 마지막 완전 투명 프레임은 정상. 충돌 제거는 기존 로직 커밋 시점에 수행한다.
- 128px 캔버스의 파편 여백을 셀 경계에서 자르지 않는다. 몸체 흔들림이나 네 방향 대칭 폭발을 덧붙이지 않는다.

11. 연출 강도·중복 정리
- 입력→준비→행동→충돌/변화→결과→정착 순서가 실제 사건과 맞는지 점검한다.
- 일반 이동은 짧은 보간, 문/제동/모서리는 국소 반응, 도약·포털은 출발/도착 구분이 우선이다.
- 광선·감지기·연결 문은 원인과 결과가 함께 읽히도록 동기화한다.
- 유리 파괴에는 기존 충돌음·짧은 햅틱이 있으면 한 번만 연결한다. 이 팩은 새 오디오를 포함하지 않는다.
- 모든 장치에 화면 흔들림·Zoom·HitStop·입자·긴 대기시간을 일괄 추가하지 않는다.
- 기존 이펙트와 프레임 효과가 중복되면 의미가 분명한 한 방식으로 통합한다.
- 별등·봉투 idle은 보드 바깥에서 낮은 강도로 유지하고 플레이 칸이나 충돌 경계를 가리지 않는다.
- 중복 Animator/프레임 플레이어/이벤트 구독/스타일이 다른 UI는 유지·통합·삭제 판단과 근거를 기록한다.

12. 실제 완료 검수
- 현재 플레이 씬과 QA 씬에서9장치군이 실제 테마 데이터에 연결되었는지 확인한다.
- 방향별 크기·피벗·레이어·Point·Atlas 가장자리, 가로/세로 반복 틈과 파편 잘림을 확인한다.
- 무효 입력 비용/턴0, 한 행동 자동 연쇄 추가 비용0, idle로 턴이 진행되지 않음을 확인한다.
- 도약4방향·3칸 거리·막힌 목적지·중간 칸 상호작용은 현재 확정 정책에 맞춰 검수한다.
- 거울8반사 경우, 유리 통과, 벽/금속·나무 상자/플레이어 차단, 감지기 on/off와 연결 문을 확인한다.
- 자석4방향, 금속/나무 구분, 중간 물체와 옆칸 막힘, 다수 상자는 기존 정책대로 확인한다.
- 포털4방향 걷기/미끄러짐, 출구 다음 칸 막힘, 추가 비용·재진입·방향 손실이 없는지 확인한다.
- 유리 빛 통과/몸체·바람 차단/폭탄·석상 파괴/파괴 칸에 선 플레이어의 빛 차단을 확인한다.
- Retry·테마 전환·씬 재진입에서 중복 구독과 상태 잔류를 확인한다.
- 실제 PlayMode 및 모바일 세로 화면에서 수행하고, 불가능한 항목은 미실행으로 표시한다.

13. 미확정 분기와 결과 문서
- 미확정 정책이 코드에 있으면 실제 동작과 선택 근거를 기록한다. 코드에도 없으면 그 분기만 미정으로 남긴다.
- 다른 장치의 적용·검수는 계속 완료한다. 추가 코스트·압착·임의 조작 규칙을 새로 만들지 않는다.
- ANIMOL_LETTER_OBSERVATORY_V01_APPLY_RESULT.md에 실제 변경 파일·씬·프리팹·사건 연결·검수 증거를 기록한다.
- 현재 구현 여부/표현 문제/개선 효과/난이도/우선순위를 실제 코드 근거로 평가한다.
- 남은 항목은 즉시 효과 큰 수정→적은 비용 개선→나중 디테일 순으로 정리한다.
- 준비된 PNG 파일 검수와 Unity 엔진 검수를 혼동해 모두 완료했다고 쓰지 않는다.
