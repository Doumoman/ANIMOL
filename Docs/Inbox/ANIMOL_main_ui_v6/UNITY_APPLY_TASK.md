# ANIMOL 메인 UI 판타지 배경 v6 적용 작업

작업 ID: `ANIMOL_MAIN_UI_FANTASY_BACKGROUND_V6_INTEGRATION`

## 실행 지시

이 문서와 동봉 에셋을 읽고 현재 Unity 프로젝트에 실제로 적용한다.
조사, 구현, 기존 로비 연결, 컴파일, 관련 검증, 증거와 결과 보고까지 한 작업으로 끝낸다.
계획이나 코드 초안만 제출하지 말고 기존 메인 로비에서 재생되는 상태로 완성한다.
현장 소스 구조에 맞게 구현하며 이 패키지에는 starter C#가 없다.
로컬 Unity 접근이 막힌 항목은 사유를 기록하고 확인하지 않은 성공을 선언하지 않는다.

새 독립 데모 씬만 만들어 기존 로비 연결을 생략하면 완료가 아니다.

- 게임 플레이어 FSM, Physics, 충돌체, 입력, 이동 규칙을 변경하지 않는다.
- Economy, 저장 데이터, 재화, 보상, 스테이지 진행 상태를 변경하지 않는다.
- Campaign 지도와 Ready/S01 등 기존 운영 맵을 재생성하거나 수정하지 않는다.
- 작업 전 보호 대상 지도 파일을 식별하고 경로별 SHA-256을 기록한다.
- 작업 후 같은 파일의 해시와 경로 목록을 비교한다.
- 씬 전체 자동 생성이나 맵 재생성 메뉴를 실행하지 않는다.
- 기존 버튼·제목·텍스트·Safe Area 레이아웃을 임의로 다시 디자인하지 않는다.
- 이미 연결된 EventSystem, 오디오, 카메라를 중복 생성하지 않는다.
- 배경 토끼를 실제 gameplay player prefab으로 교체하지 않는다.
- 필요한 수정은 UI 배경 자산, 전용 구현, 로비 연결, 관련 생성 경로에 한정한다.

## 패키지 파일

패키지를 읽는 경로는 압축을 푼 위치를 기준으로 한다.

- `runtime/manifest.json`: 에셋·해상도·움직임 규격.
- `runtime/assets/T01-far.png` 등: 테마별 네 개의 원본 레이어.
- `runtime/assets/rabbit-run-right.png`: 오른쪽 달리기 시트.
- `runtime/assets/rabbit-run-left.png`: 왼쪽 달리기 시트.
- `reference/animation.js`: 기존 연출을 확인할 기준 구현.
- 참조 이미지나 합성본이 있으면 시각 검토에만 사용한다.
- 실제 runtime PNG는 배경 20개와 토끼 시트 2개, 총 22개다.
- 합성 PNG, 확대 이미지, GIF, HTML 미리보기를 런타임 배경으로 사용하지 않는다.
- 프로젝트 내부 목적지는 기존 ANIMOL UI 자산·스크립트 규칙을 조사해서 결정한다.
- 원본 파일을 복사할 때 이름과 픽셀 내용을 보존한다.
- 자동 생성된 Unity `.meta`와 필요한 참조는 함께 관리한다.

## 아트 규격

- 네이티브 화면과 각 배경 레이어는 352×704px, 비율 1:2다.
- 4배 확대하면 1408×2816px이다.
- 1400×2400으로 강제 늘려 가로·세로 비율을 바꾸지 않는다.
- 제공한 Sweetie16 팔레트만 배경과 토끼 아트에 사용한다.
- 새 색, 안티앨리어싱, 그라데이션, 색을 섞는 블러를 추가하지 않는다.
- 원근감의 부드러운 인상은 제공된 근경 도형과 시차로 표현한다.
- v6 토끼는 판타지 모험가 캐릭터이며 왕관·뿔이 제거되어 있다.
- 귀 장식은 귀 옆에 납작하게 붙은 작은 초록 세잎클로버 모양 핀만 보이게 한다.
- 귀 장식에 꽃, 금속 바, 줄기를 추가하거나 머리에 줄기가 삽입된 모습으로 바꾸지 않는다.
- 크림색 튜닉, 초록 조끼, 짧은 청록 망토와 제공된 털·발·꼬리 디자인을 유지한다.
- 구형 닌자 토끼 및 v2~v5의 왕관·귀 보석·네잎클로버·꽃·줄기가 있는 구형 시트를 혼용하지 않는다.
- 모든 PNG의 alpha는 0 또는 255인 픽셀 경계다.
- T01/T04/T05 far에는 투명 영역이 있으므로 불투명 바탕이 필요하다.
- 매 네이티브 프레임을 `#1a1c2c` 바탕으로 먼저 채운다.
- UI 버튼과 텍스트의 기존 색은 이 아트 팔레트 제한의 대상이 아니다.

## 가져오기와 토끼 프레임

- 실제 파일과 manifest의 크기가 맞는지 가져오기 전에 확인한다.
- Point 필터, 압축 없음, mipmap 없음으로 원본 픽셀을 보존한다.
- 플랫폼별 압축 override가 색과 alpha를 바꾸지 않는지 확인한다.
- 사용할 렌더 경로에 맞게 Texture 또는 Sprite 설정을 일관되게 적용한다.
- Sprite를 쓰면 원본 셀 크기와 피벗을 보존한다.
- 토끼 시트 크기는 512×96px이다.
- 가로 64×96px 셀 여덟 개를 왼쪽부터 0~7번으로 사용한다.
- 구형 48×64 셀 크기로 자르지 않는다.
- 자동 trim이나 프레임마다 다른 피벗으로 위치가 흔들리게 하지 않는다.
- 토끼 재생 속도는 14fps이며 프레임은 `floor(t×14) % 8`이다.
- 좌·우 시트를 정확한 진행 방향에 대응시킨다.
- 이미지의 바깥 투명 여백도 고정된 64×96 셀의 일부다.

## 네이티브 렌더와 화면 대응

352×704 오프스크린 최종 이미지를 렌더하고 Point 방식으로 메인 UI 뒤에 표시한다.
실제 구현 방식은 기존 프로젝트의 렌더 파이프라인에 맞게 선택한다.
렌더 텍스처·카메라·셰이더가 필요하면 이 화면 전용으로 명확히 관리한다.

- 네이티브 좌표에서는 좌상이 (0,0), 오른쪽과 아래쪽이 양수다.
- Unity 좌표로 바꿀 때 Y축 방향과 피벗을 명시적으로 변환한다.
- 레이어 위치와 그리기 크기는 네이티브 정수 픽셀에 맞춘다.
- 기본 화면 대응은 1:2 비율을 유지하는 중앙 cover crop이다.
- 로비 위젯의 기존 CanvasScaler와 Safe Area 처리를 유지한다.
- 배경 때문에 공통 UI 전체 기준 해상도를 바꾸지 않는다.
- 1080×1920과 1080×2400 두 Game View에서 실제로 확인한다.
- 두 화면에서 발 기준선 Y=526과 토끼가 보이는지 확인한다.
- cover 영역, 클리핑, UI 겹침을 보고 필요하면 배경 viewport 배치를 조정한다.
- 위젯 가독성 문제를 해결할 때 토끼·근경을 UI 위에 올리지 않는다.
- 하얀 tint와 색을 보존하는 렌더 상태를 사용한다.
- 이 아트에 색을 바꾸는 조명·후처리·필터 효과를 추가하지 않는다.

## 레이어 순서와 고정 발판

아래에서 위 순서는 바탕 → far → mid → platform → rabbit → near → 기존 로비 UI다.
건물·발판은 각 테마를 표시하는 동안 화면 좌표에 고정되어 있어야 한다.
테마 전환에서는 다음 테마의 발판 그림으로 교체된다.

- platform은 네이티브 (0,0)에 352×704 그대로 그린다.
- platform 시차와 추가 이동 속도는 0이다.
- 토끼는 카메라 시차를 받지 않고 발판 위를 가로로 달린다.
- 가까운 장식은 빠르게 이동하되 기존 UI 전체보다 아래에 둔다.
- 배경과 토끼가 모든 버튼, 모달, 오버레이의 클릭을 통과해야 한다.
- 배경 전용 Graphic의 raycast와 기타 입력 가로채기를 비활성화한다.
- 공통 ScreenHost 전체에 적용해서 다른 메뉴나 gameplay에 남기지 않는다.
- 기존 UI 모션 스크립트가 배경 발판을 움직이거나 tint를 바꾸지 않게 한다.
- 생성된 프리팹을 직접 고치는 것만으로 끝내지 않는다.
- 관련 UI 생성·등록 경로도 수정해 이후 자동 UI 재생성에 연결이 보존되게 한다.
- 이 확인을 위해 금지된 씬 전체 생성 메뉴를 실행하지 않는다.

## 시차와 방향

테마 내 경과 시간을 `local`, `p=local/5`, `phase=p−0.5`로 둔다.
배경의 수평 방향 `cameraDirection`은 테마 슬롯마다 −1 또는 +1로 선택한다.
각 레이어를 화면 중앙 기준으로 확대하고 다음 이동을 더한다.

| 레이어 | 확대 | X 이동 | Y 이동 |
|---|---:|---:|---:|
| far | 1.16 | cameraDirection×88×phase×0.30 | 72×phase×0.30 |
| mid | 1.36 | cameraDirection×88×phase×0.62 | 72×phase×0.62 |
| platform | 1.00 | 0 | 0 |
| near | 1.60 | cameraDirection×88×phase×1.60 | 72×phase×1.60 |

방향은 좌상→우하 또는 우상→좌하다. 아래로 이동하는 Y를 뒤집지 않는다.
확대 여유 영역이 화면 밖으로 이동해도 빈 틈이 노출되지 않아야 한다.
토끼 방향은 배경 방향과 별도로 선택하며 두 선택을 하나로 묶지 않는다.
검증 가능한 seed 또는 동등한 재현 방법을 제공한다.
연속 두 슬롯의 방향이 같은 경우도 정상 난수 결과다.

## 토끼 위치와 제작 기록 주의

- 발판의 네이티브 기준선은 Y=526이다.
- 토끼 셀의 발 기준선은 Y=90이다.
- 전체 토끼 셀의 좌상 Y는 `526−90=436`으로 고정한다.
- 오른쪽 진행의 셀 좌상 X는 `−64+p×416`이다.
- 왼쪽 진행의 셀 좌상 X는 `352−p×416`이다.
- 반올림한 네이티브 X로 시트의 해당 프레임을 그린다.
- 한 슬롯에서 5초에 걸쳐 화면 한쪽 밖에서 다른 쪽 밖으로 달린다.
- 3·7번 공중 프레임은 PNG 안에서 발이 4px 높게 제작되어 있다.
- 추가 bob이나 프레임별 발선 보정으로 이 움직임을 지우지 않는다.
- `sourceWalkY`, `platformShiftY`, `exportFrames.shiftY`는 제작 과정 기록이다.
- 이 값은 최종 PNG에 이미 반영됐으므로 런타임에서 다시 더하지 않는다.

## 테마 주기와 픽셀 전환

- T01 월궁 → T02 구름고래 목장 → T03 별가루 도서관 순서로 진행한다.
- 이어서 T04 시간유리 온실 → T05 오로라 수정광산 → T01로 반복한다.
- 새 테마 시작 시각은 0, 5, 10, 15, 20, 25초다.
- 전환 0.36초를 포함해 각 슬롯이 5초이며 5.36초로 늘리지 않는다.
- 첫 프레임에서는 첫 테마를 바로 표시한다.
- 후속 슬롯 시작에는 8×8 네이티브 픽셀 블록의 대각선 wipe를 사용한다.
- 이전 화면은 직전 슬롯 진행률 0.999 위치로 렌더한다.
- 새 화면은 현재 슬롯 진행률로 렌더한다.
- 블록 좌상 (x,y)의 값은 `d=0.5×x/352+0.5×y/704`다.
- `d < local/0.36×1.22−0.11`이면 새 화면 블록을 표시한다.
- 조건을 만족하지 않으면 이전 화면 블록을 표시한다.
- 블록 경계는 binary 선택이며 알파 crossfade나 bilinear 혼합을 넣지 않는다.
- 0.36초 이후 이전 화면을 렌더하거나 유지할 필요가 없다.

## 시간, 생명주기와 성능

- 메인 로비 전용 로컬 시계에 unscaled delta time을 누적한다.
- gameplay의 Time.timeScale과 장식 재생 시간을 분리한다.
- 로비 비활성, 다른 화면 진입, 앱 비활성 상태에서는 업데이트를 중단한다.
- 재진입 시 중복 coroutine, callback, 카메라, 렌더 텍스처가 생기지 않게 한다.
- 복귀 시 재시작 또는 이어 재생 정책을 하나로 정하고 보고서에 기록한다.
- 숨겨진 기간을 통째로 더해 테마가 갑자기 건너뛰지 않게 한다.
- PNG와 프레임 참조를 미리 준비하고 레이어·렌더 자원을 재사용한다.
- 프레임마다 로드, Instantiate/Destroy, hierarchy 재생성을 하지 않는다.
- 전환 시에도 현재·이전 두 화면만 처리한다.
- Dispose/OnDisable 등 프로젝트 방식에 맞게 소유한 자원을 정리한다.
- 기존 자산 로더를 사용하고 필요 없는 새 패키지 의존성을 추가하지 않는다.
