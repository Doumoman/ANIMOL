ANIMOL Unity 적용 명령 — 기억 극장 공중 무대 환경팩 V02

현재 프로젝트의 실제 씬, Tilemap, 렌더링 순서, 맵 점유/장치 데이터 구조를 먼저 확인한다.
ANIMOL은 가변 크기 정사각형 탑뷰 스와이프 퍼즐이다. 과거 횡스크롤 러너 기획으로 처리하지 않는다.
이번 작업은 기억 극장 환경 아트의 적용이다. 이동·코스트·방울·출구·카메라 추적·기존 11종 장치의
게임플레이 판정과 이벤트를 유지한다. 새 기믹이나 새 UI를 추가하지 않는다.

1. 입력 자료
ANIMOL_MEMORY_SKYTHEATER_V02/README_KO.txt, manifest.json, qa_report.json을 읽는다.
실제 개별 PNG는 tiles/*/blob47, props, animation, backgrounds에 있다.
source/inspection/examples/camera는 제작·검수 자료이며 자동으로 충돌 자산으로 등록하지 않는다.

2. 임포트
Texture Type Sprite, Single, PPU80, Full Rect, Point, Compression None, Mip Maps Off.
타일 피벗은 (0.5,0.5). 소품은 manifest.props의 pivot을 따른다.
80px 또는 80px 배수 캔버스를 자동 trim하지 않는다. 재보간/압축으로 색을 늘리지 않는다.
Sprite Atlas 회전과 Tight Packing을 끄고 패딩을 둔다. 최종 카메라 표시를 픽셀에 정렬한다.
원본을 임의 비율로 확대하지 않는다. 확대는 정수배 Nearest Neighbor로 한다.

3. 연결 타일
o=비어 있는 직교 이웃의 비트합, N1 E2 S4 W8.
i=두 직교 이웃은 있고 대각선 이웃만 비었을 때의 비트합, NW1 NE2 SE4 SW8.
oXX_iYY.png를 선택한다. 기존 시스템의 connected bitmask와 exposed bitmask를 혼동하지 않는다.
레벨 밖은 빈 칸으로 본다. 같은 바닥 위의 장치가 있다는 이유로 지형 이웃을 끊지 않는다.
각 방향의 광원 처리가 이미 들어 있으므로 통째로 회전/반전하여 다른 방향 타일을 만들지 않는다.
wood와 underside는 같은 구조 점유 맵을 사용한다. underside는 비충돌 시각 레이어다.
underside 전체를 먼저 렌더링하고 local Y=-0.175unit을 적용한 뒤 wood 전체를 그린다.
칸별로 윗면 다음 단면을 렌더링하면 위쪽 칸의 단면이 아래쪽 칸을 덮을 수 있으므로 금지한다.
velvet는 ground의 부분집합인 독립 카펫 마스크로 선택해 wood 위에 놓는다.
카펫 경계는 재질 변화다. 이동을 막거나 새로운 높이를 만들지 않는다.
inner4 직접 조립 시에는 manifest의 20×20 사각형 RGBA 전체를 교체한다. 단순 알파 합성을 쓰지 않는다.
기본 적용 방식은 사전 조립된 blob47이다.
선택 격자는 목재 #FFCD75 중앙에 #B13E53, 카펫 #B13E53 중앙에 #5D275D로 표시한다.
판자 구분선과 80px 정사각형 이동 격자를 혼동하지 않도록 유지한다.

4. 커튼 틀 프리팹
왼쪽 80×160 기둥 + N개의 80×80 가로대 + 오른쪽 80×160 기둥으로 만든다.
전체 너비는 (N+2)칸이며 최소 3칸이다. 가로대는 가로로만 반복한다. 높이를 늘이거나 기둥을 늘이지 않는다.
프리팹의 기준을 왼쪽 위로 잡는다면 왼쪽 기둥의 피벗 위치는 (0.5,-2),
가로대의 피벗 위치는 (1.5+k,0), 오른쪽 기둥은 (N+1.5,-2)unit이다.
좌/우 기둥 피벗은 아래 중앙(0.5,0), 가로대 피벗은 위 중앙(0.5,1)이다.
먼저 inspection/proscenium_3_cells.png, _5_cells.png, _9_cells.png와 같은 구성을 확인한다.
기둥 발과 오르간 받침은 실제 무대 외곽 데크에 닿게 놓는다. 공중에 독립 스티커처럼 흩뿌리지 않는다.

5. 장식 배치
오르간은 뒤쪽 장식 데크, 객석은 앞쪽 데크, 각광은 앞 무대 턱에 붙인다.
모든 소품은 기본 비충돌이다. 기존 장치를 가리거나 새로운 장애물처럼 보이는 곳에 놓지 않는다.
examples/map_layout.json의 좌표는 이미지 기준 X오른쪽/Y아래쪽이다.
소품의 top-left=(x,y), 캔버스=(w,h), Unity pivot=(u,v)일 때,
무대 왼쪽 위를 원점으로 한 피벗 위치는 ((x+u*w)/80, -(y+(1-v)*h)/80)이다.
walkableExample은 검수 맵의 예시다. 기존 레벨의 이동 가능 영역을 덮어쓰지 않는다.
현재 레벨에 장식 여유가 없으면 별도 시각 데크/바깥 림에 배치하고 실제 이동 칸 중심을 가리지 않는다.
화면 크기에 고정된 큰 극장 배경을 붙이지 말고 맵 좌표에 부품을 배치한다.

6. 애니메이션과 연출
curtain_left_idle, curtain_right_idle: 5프레임, 시간 [900,350,700,350,900]ms, 선택적 반복.
기둥과 가로대는 고정하며 천 영역만 최대1px 움직인다. root motion을 켜지 않는다.
footlights_reveal: [off,dim,on], 시간 [60,60,120]ms. 기존 테마 입장 시 1회, 이후 on 유지.
입력/이동/충돌마다 점멸시키거나 각광을 수집 목표처럼 강조하지 않는다.
아트 적용을 위해 화면 흔들림, 카메라 킥, 빛 번짐, 추가 파티클, 새 사운드/햅틱을 일괄 추가하지 않는다.
기존 사건의 입력→준비→행동→충돌/변화→결과→정착 연결을 유지한다.
새 환경 애니메이션이 기존 셔터·이동 무대 등 중요한 장치의 피드백을 방해하지 않아야 한다.

7. 배경과 카메라
Far -> Mid -> Near -> Underside -> Wood -> Velvet -> 격자 -> 장식/기존 장치/캐릭터 -> UI.
Far/Mid/Near는 모두 판 뒤의 배경이다. 960px 주기로 X/Y 양축을 반복한다.
기본 시차는 0.15/0.35/0.65이며 최종 오프셋은 정수 픽셀로 반올림한다.
음수 카메라 좌표는 floor-mod를 사용하고, 화면 밖까지 필요한 모듈 복사본을 배치한다.
카메라 위치 (0,0), (640,480), (-400,960)에서 틈이나 밝은 경계가 없는지 확인한다.
현재 프로젝트의 카메라 추적 로직과 UI 화면 좌표는 변경하지 않는다.

8. 완료 확인
한 칸 섬, 1칸 통로, 네 방향 끝점, 안쪽 구멍, 볼록/오목 모서리를 실제 씬에서 확인한다.
1x 및 정수4x 검사 시트와 비교하고, 알파 테두리/잘림/겹친 단면/두꺼운 연결선을 확인한다.
커튼 틀 3/5/9칸, 소품 피벗, 발과 데크의 접촉, 이동 칸 가림 여부를 확인한다.
모바일 세로 화면에서 코스트/방울/출구/기존 장치와 입력 동작을 확인한다.
수정 파일, 적용 씬, 확인한 항목과 미확인 항목을 보고한다. 실행하지 않은 테스트를 통과했다고 쓰지 않는다.
