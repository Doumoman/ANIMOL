ANIMOL 황혼의 바다 V01 실제 적용 지시문

이 문서 전체를 작업 지시로 읽고 현재 Unity 프로젝트에 실제 적용해라.
계획·예제만 제출하지 말고 자산 임포트·테마/프리팹 연결·현재 플레이 씬·실행 검수까지 수행해라.
입력: ANIMOL_TWILIGHT_SEA_V01.zip. 기존 테마와 사용자 변경은 보존한다.

1. 현재 프로젝트와 사건 조사
- AGENTS.md, Unity 버전, 실제 세로 탑뷰 퍼즐 씬, 테마 데이터, Grid 셀 크기를 확인한다.
- 유효 입력 확정→자동 연쇄→장치 갱신→결과의 실제 호출 지점을 찾는다.
- 공통 장치·스파이크·배·통·폭탄의 현재 구현 여부와 표현 누락을 코드에서 확인한다.
- 이 팩의 QA는 프로젝트 실행 검사나 완성 레벨 검사가 아니다.
- 스태미나 러너/플랫포머, 공격·피해·보상 등 요청하지 않은 규칙을 추가하지 않는다.

2. 읽을 파일과 임포트
- README_KO.txt, manifest.json, unity_import_manifest.json, QA_REPORT.json.
- data/DEVICE_RULES.json, data/MOTION_BINDINGS.json, DEVICE_EVENT_BINDINGS.csv.
- POLISH_REVIEW_KO.csv와 source/ADDED_DECISIONS_KO.txt의 우선순위를 확인한다.
- 테마 식별자는 twilight_sea. 기존 공통 장치 로직을 재사용하고 외형만 테마로 분리한다.
- sprites만 런타임 대상으로 임포트한다. source, reference, preview, 원화는 제외한다.
- 개별PNG 또는 시트 중 프로젝트가 쓰는 방식 하나만 연결한다. 중복 Sprite/클립 생성 금지.
- Point 필터, 압축 없음, Mipmap 없음, Full Rect. SpriteAtlas에서도 번짐·색 변경·잘림을 확인한다.
- 논리 셀80px, 일반 캔버스96×96. 폭발128×128, 장식64×64/64×96. 실제JSON을 읽는다.
- 한 셀 월드 크기s에 PPU=80/s. PPU32로 덮어쓰거나96px 간격으로 배치하지 않는다.
- 피벗은PNG 좌상단 픽셀 기준. Unity normalized=(pivotX/width,1-pivotY/height).
- 콜라이더·점유·Grid를 시각 여백이나 알파 윤곽에 맞춰 변경하지 않는다.
- 배경1024×1792, 권장 보드 영역(112,272,800,1280)은 배치 참고값. 기존 해상도 대응 레이아웃을 유지한다.
- 기존 토끼·분홍 비눗방울·출구·상단 일시정지/코스트/방울 수 UI 프리팹을 유지한다.

3. 공통 논리·시간 계약
- 유효 스와이프/밀기1회 비용1, 변화 없는 입력 비용0·장치 턴0.
- 한 행동 안의 자동 운반·반사·굴림·폭발 연쇄는 추가 비용0. 기존 방울3개 후 출구 유지.
- 이동 좌표·충돌·턴·비용은 기존 로직만 커밋한다. 애니메이션 프레임 이벤트로 중복 커밋하지 않는다.
- PNG에는 셀 간 root motion이 없다. from/to/실제 경로를 받아 시각 자식만 보간한다.
- JSON 프레임 durationMilliseconds를 누적한다. 모든 클립을 동일FPS로 덮어쓰지 않는다.
- 종료 상태를 manifest의 terminalState에 맞춘다. 비반복 클립이 idle로 임의 복귀하지 않게 한다.
- 프레임 반복·퓨즈 점멸·물결·해초가 장치 턴이나 코스트를 진행시키지 않게 한다.
- 시각 재생 때문에 전체 입력을 일괄 잠그지 않는다. 기존 입력 큐·취소·재시작 정책을 유지한다.
- 같은 행동ID/사건에 중복 구독·중복 사운드·중복 이펙트가 없는지 확인한다.

4. 공통 장치4종
- 07 무빙워크: e/s/w/n=화면 우/하/좌/상. 내부 벨트만 반복하며 실제 운반은 기존 사건에 연결한다.
- 09 단방향 문: 허용 통과 시작=open, 실제 통과 완료=close, 역방향 거부=blocked.
- 문 열림의 투명 중심을 채우지 않는다. 역방향 거부는 비용·턴0이며 문 통과를 허용하지 않는다.
- 18 튕김 모서리: nw/ne/se/sw는 벽 모서리 위치이며 열린 홈은 각각se/sw/nw/ne다.
- 투명한 안쪽 홈 유지. 기존90도 반사 확정에 impact 한 번만. 스프링 반동·추가 이동을 만들지 않는다.
- 19 제동판: 실제 강제 이동 정지에 brake. 쿠션 압축은 표현이며 논리 좌표를 튕기지 않는다.

5. 05 이탈 가시 발판
- 처음 밟아 점유되면 flat→arm→armed. 점유 중에는 작은 가시 끝만 보인다.
- 플레이어가 떠난 실제 사건에서 rise를 재생하고 raised를 유지한다.
- 통행 불가 커밋 시점을 애니메이션 종료까지 늦추지 않는다.
- raised 진입 거부는 짧은 blocked, 비용·턴0. 접촉 피해를 임의로 추가하지 않는다.
- 다시 낮아지는 조건은 기획서 미정. 자동 타이머·몇 턴 뒤 복구·재밟기 해제를 새로 만들지 않는다.

6. 11 조종 나룻배
- 승선→물 쪽 유효 스와이프마다 플레이어와 배가 같은 방향 한 칸 이동→유효 육지로 하선.
- 하선 뒤 배는 마지막 물칸에 남는다. 목적 물칸/육지가 막히면 무효, 배와 플레이어 모두 잘못 이동하지 않는다.
- 기존 조종 입력을 유지한다. 새 승선 버튼·자동 항해·연속 대시·경로 탐색을 추가하지 않는다.
- 탑승 중 공통 이동 루트를 공유한다. 시각만 별도 루트로 이동해 배와 승객이 벌어지지 않게 한다.
- wake < rear < 기존 플레이어 < front로 정렬한다. full 합성 Sprite를 동시에 켜지 않는다.
- rear/front는 같은 프레임 번호·같은 시간으로 재생한다. 둘을 별도 임의 위상으로 시작하지 않는다.
- seatAnchorTopLeft=(48,53), 중심 대비(0,+5)px. Unity에서는 y부호를 바꿔 기존 발 피벗을 맞춘다.
- passengerOffsetPixelsByFrame을 같은 프레임에 적용해1px idle bob도 승객과 동기화한다.
- board/row/disembark/blocked 각각의 앞·뒤 동기화 클립을 사용한다. 빈 배는 full 방식도 가능하다.
- row200ms는 시각 기준. 기존 이동시간을 바꾸기보다 현재 이동 보간에 클립을 동기화한다.

7. 12 구르는 통
- 첫 다음 칸으로 이동할 수 있을 때만 유효 밀기. 첫 칸이 막히면 start/자동 굴림을 시작하지 않는다.
- 한 번 밀면 실제 장애물 바로 앞 칸까지 자동 굴림. 각 추가 칸에 코스트를 붙이지 않는다.
- 플레이어는 통이 처음 있던 칸까지만 이동한다. 통의 전체 이동 경로를 플레이어 경로로 재사용하지 않는다.
- idle→start→방향별 roll→실제 최종 칸에서 stop→idle 순서로 연결한다.
- roll의8프레임 나뭇결과 실제 셀 간 이동을 동기화한다. Transform과 PNG에서 이동을 중복 적용하지 않는다.
- stop_preview는 실제 경로 계산의 최종 칸에 얇게 표시한다. 막힌 칸 안이나 임의 고정거리에 표시하지 않는다.
- 상태가 바뀌거나 입력이 취소되면 오래된 예측 실루엣을 제거한다.

8. 15 3턴 폭탄
- 첫 성공한 밀기 직후 arm과 숫자3. 그 점화 밀기에서2로 감소시키지 않는다.
- 이후 플레이어의 유효 행동 완료마다 3→2,2→1,세 번째 행동 뒤 폭발.
- 움직이지 못한 밀기/무효 스와이프/idle/오디오/애니메이션 종료가 카운트를 바꾸면 안 된다.
- push_*는 시각 반응만. 점화/턴 감소는 기존 상태 사건에서 한 번만 수행한다.
- 숫자는 실제 남은 턴 상태를 읽는다. count-up이나 초 단위 타이머를 추가하지 않는다.
- 해당 사건에서 explode330ms를 재생하고 cleared를 유지. 제거 시점은 기존 논리 커밋에 따른다.
- 범위 안의 실제 금 간 벽 파괴 사건에 cracked_wall_break를 연결한다. 모든 벽을 지우지 않는다.
- blast_boundary는 기존 범위 셀 집합에서 바깥 둘레만 계산한다. 1=N,2=E,4=S,8=W.
- blast_cell_preview는 대체 표시다. 범위 경계와 중복해서 시선을 방해하지 않는다.
- cracked_wall_target은 실제 범위 안 파괴 대상에만 표시한다. 범위가 바뀌면 함께 갱신한다.
- 폭발그림/128px캔버스로 십자·3×3·반경1 범위를 추론하지 않는다.
- 정확한 폭발 범위와 플레이어/일반 물체 영향은 기획서 미정. 기존 확정 코드가 있으면 사용한다.
- 확정 코드가 없다면 새 피해 규칙을 발명하지 말고 자산/사건 연결과 미정 항목 기록까지 완료한다.

9. 배경·해안·장식
- 평평한 바닥과 물을 먼저 배치하고 기존 지형 데이터에서 해안 mask를 계산한다.
- shore mask의 비트는 인접 물/부두 바깥에만 켠다. 육지 내부에 해안 테두리를 만들지 않는다.
-80px 셀 영역의 접합, 내부 물길 모서리, 가로/세로 연속 배치를 확인한다.
- 물결은1900ms대의 느린 반복으로 위상을 분산한다. 배 이동보다 강하게 깜박이지 않게 한다.
- 해초 idle은1px, 접촉은최대4px 시각 변형. 장식에 새 충돌체·비용·장치 턴을 추가하지 않는다.
- 배경과 장식은 플레이 오브젝트 아래, 목표/방향/충돌 경계를 가리지 않게 한다.

10. 연출 강도·중복 정리
- 일반 운반/배 이동은 짧은 기존 이동음. 가시 솟음/통 정지는 작은 단발음. 폭발과 벽 파괴가 가장 강하다.
- 일반 행동에 화면 흔들림·줌·히트스톱을 일괄 적용하지 않는다. 이 팩 기본값은 모두0이다.
- 폭발도 먼저 숫자/대상/소멸이 읽히도록 한다. 기존 중요 사건용 약한 햅틱이 있다면 한 번만 연결한다.
- UI 버튼은 기존 Press/Release/Disabled를 유지하고 모바일 Hover는 제외한다. UI를 새로 중복 제작하지 않는다.
- 승리/실패/방울 획득/출구는 기존 공통 시퀀스를 유지한다. 테마 적용을 이유로 중복 결과 연출을 만들지 않는다.
- 유지: 기존 장치 로직·입력 큐·공통 UI·공통 사운드 라우터·기존 객체 풀.
- 통합: 중복된 테마 재생기·방향 enum 변환·턴 알림·사건별 사운드 호출은 확인 후 공용 경로에 연결한다.
- 삭제 제안: 실제로 미사용인 중복Sprite/임시이펙트/중복 구독. 참조 검색으로 확인한 대상만 제거한다.

11. 완료 검수와 보고
- 첫 점화3, 다음 유효 행동2,다음1,다음 완료 뒤 폭발; 무효 입력에서는 숫자 불변을 검수한다.
- 가시 점유/이탈/재진입 거부와 재시작 상태 복원을 확인한다.
- 배4방향 한 칸, 탑승/하선, 막힌 물/육지, 플레이어·배 동기화, 앞/뒤 레이어를 확인한다.
- 통4방향, 첫 칸 막힘, 중간 막힘, 플레이어 원래 칸 정지, 비용1을 확인한다.
- 공통4종·자동 연쇄·취소/재시작에서 중복 비용/턴/사운드/이펙트가 없어야 한다.
- 밝은/어두운 바닥과 모바일 실제 크기로 누끼·구멍·잘림·해안 접합·숫자 가독성을 확인한다.
- 기존 테마를 전환해 이전 자산과 장치 동작이 유지되는지 확인한다.
- 실행한 검수와 실행하지 못한 검수를 분리해 보고한다. 프로젝트 실행 없이 상용 완성도를 보장했다고 쓰지 않는다.
- 우선순위: 즉시=턴/점유/이동 결과 연결; 저비용=예측 실루엣·단발음·물결/해초; 후순위=장식 타이밍 세부.
