배경·기초 부품
1024×1792 불투명 바다 배경, 모래/부두 바닥, 물2색, 잔물결, 해안16마스크, 벽·금 간 벽·파괴,
가로/세로 밧줄 난간·기둥·등·조개·해초·나무 상자를 포함한다.
해초 idle은2100ms, 접촉은300ms. 잔물결1920ms, 등1800ms. 장식은 비용·충돌·턴에 관여하지 않는다.
해초 접촉 클립은 이미 접촉을 알 수 있는 경우에만 붙인다. 새 충돌체나 상호작용 규칙을 뜻하지 않는다.

색상·규격
새 게임용PNG는 Sweetie-16 허용16색 중13색만 사용한다. 알파0/255, 투명픽셀RGB0. 배경은 불투명이다.
미리보기의 기존V04 UI/토끼/분홍 비눗방울과 생성 원화는 새 게임용PNG 색수 검수 대상이 아니다.
이 팩은 앞선 팩과 같은80px 논리 셀이다. 네이티브32×32팩이 아니다.
일반 캔버스96×96, 폭발128×128, 작은 장식64×64 또는64×96. 모든 캔버스 크기는32의 배수다.
셀 간격은80px이며96px 투명 여백을 이동거리나 충돌 크기로 사용하지 않는다.
한 셀 월드 크기가s면 PPU=80/s. Point/Nearest, 정수배 확대, 압축 없음, Mipmap 없음, Full Rect.
광원은 좌측 상단. 통의 원형 나뭇결은 고정된 외곽/띠 안에서만 회전한다.
팔레트 변환 후 작은 색 조각과 알파 경계를 정리했다. 원화의 짙은 내부 명암은 외곽선과 별개다.

좌표와 나룻배 레이어
JSON 피벗은 PNG 왼쪽 위 픽셀. Unity normalized=(pivotX/width,1-pivotY/height).
일반 중심은(48,48), 폭발(64,64). 장식 피벗도 JSON을 읽는다.
나룻배는 full 합성 Sprite 또는 rear/front 두 레이어 중 하나의 방식만 쓴다.
승객이 있으면 wake < rear < 기존 캐릭터 < front 순서. 동일 Transform/피벗/프레임 시각을 공유한다.
좌석 기준점은 원본PNG(48,53), 중심 기준 아래5px다. 기존 캐릭터의 발 피벗을 여기에 맞춘다.
PNG y는 아래로 증가하므로 Unity 좌석 y오프셋은 -5/PPU다. 기존 프리팹의 발 피벗을 먼저 확인한다.
idle/row/board/disembark의 passengerOffsetPixelsByFrame도 캐릭터 시각 자식에 같은 프레임으로 적용한다.
rear/front 분할선은y=63이며 두 레이어는 중복 없는 완전한 원본 분할이다.
프레임별 합성 결과와 시간 일치를 검수했다. full Sprite와 두 레이어를 동시에 그리지 않는다.
승선/하선/거부 클립의 종료 상태는 기존 논리 사건이 결정한다. 그림이 먼저 하선을 허가하지 않는다.

루트 이동·턴 계약
셀 간 위치 이동은 PNG에 굽지 않았다. 배·통·폭탄 이동은 기존 from/to/경로를 시각 자식으로 보간한다.
나룻배 한 칸 row 클립200ms. 통 굴림은280ms 주기이며 실제 이동시간/거리와 동기화한다.
통의 시작 밀기가 유효해지면 플레이어는 원래 통 칸으로만 간다. 통을 따라 끝까지 이동시키지 않는다.
통의 예상 정지 실루엣은 기존 경로 계산 결과의 최종 칸에만 둔다.
가시 솟음190ms. 논리 통행 불가 시점은 이탈 사건이며 애니메이션 종료를 기다려 지연하지 않는다.
3턴 폭탄: 첫 성공한 밀기3 → 다음 유효 행동2 → 다음 유효 행동1 → 다음 유효 행동 완료 뒤 폭발.
점화 밀기에서 바로2로 줄이면 안 된다. 이동 못한 밀기는 점화·턴 감소 모두 없다.
push_*는 밀기의 시각 반응만 제공한다. 그 클립 자체가 점화나 숫자 감소를 커밋하지 않는다.
폭발330ms의 마지막 cleared 프레임은 완전 투명인 정상 상태다. 금 간 벽 파괴 마지막도 정상 투명.
숫자와 퓨즈의 idle이 논리 턴이나 타이머를 진행시키면 안 된다.
유효 스와이프/밀기1회 비용1, 변화 없는 입력 비용0·장치 턴0, 자동 연쇄 추가 비용0.
방울3개 후 출구 규칙과 기존 UI·캐릭터·분홍 비눗방울을 유지한다.

범위·해안 마스크
shore_00~15와 blast_boundary_00~15: bit1=N,2=E,4=S,8=W.
shore는 인접 칸이 물/부두 바깥이면 해당 비트를 켠다. 지형 판정은 현재 레벨 데이터에서 받는다.
연결된 육지끼리의 경계에는 해안선을 그리지 않는다. 모든 해안 셀의80×80 영역은 빈틈 없이 채워져 있다.
blast_boundary는 실제 폭발 범위 셀의 바깥 둘레만 표시하도록 이웃 범위 셀 존재 여부로 마스크를 계산한다.
blast_boundary_00은 내부 칸의 빈 테두리이므로 완전 투명이 정상이다. blast_cell_preview는 선택 가능한 칸별 대체 표시다.
범위 테두리와 칸별 표식을 동시에 중복 표시하지 않는다. cracked_wall_target은 실제 범위 안 금 간 벽에만 표시한다.
폭발의 시각 실루엣/128px 캔버스는 폭발 범위·피해 모양을 정의하지 않는다.
폭발 범위 수치·모양, 플레이어/일반 물체 영향, 가시 재하강 조건은 기획서 미정이다. data에null로 기록했다.
기존 프로젝트에 확정 구현이 있으면 그 정책을 읽고 시각만 연결한다. 없으면 자산 연결과 확인 필요 항목까지만 완료한다.

검수 범위
색상·알파·숨은RGB·캔버스·잘림·구멍·프레임 시간·시트 일치·고정 프레임·완료 상태를 파일 수준에서 검수했다.
통4방향 각각8개 다른 굴림 프레임, 나룻배20개 앞/뒤 클립쌍, 해안 연결·폭탄 상태 계약도 확인했다.
윤곽/Jaggies는 실제 크기와2배 접사로 확인했다. 모든 형태를 자동으로 판정하는 검사라고 주장하지 않는다.
PREVIEW_QA.json은 Node VM의 선택/재생/정지/시간 경계 검사이며 실제 브라우저 렌더링 검수가 아니다.
Unity 프로젝트가 없어 실제 임포트·SpriteAtlas·Shader·PlayMode·모바일/PC 빌드는 실행하지 않았다.
PLAYFIELD는 아트 배치 예시이며 풀 수 있는 완성 레벨이 아니다. GIF는50ms 간격 시연으로 게임의 자동 턴 진행을 뜻하지 않는다.
새 오디오·햅틱 바이너리는 포함하지 않는다. 기존 오디오/햅틱과 사건을 동기화하는 적용 지침을 제공한다.
생성 원화에는 팔레트 밖 색과 반투명 경계가 있을 수 있다. 게임에는 sprites 안의 최종 PNG를 사용한다.
