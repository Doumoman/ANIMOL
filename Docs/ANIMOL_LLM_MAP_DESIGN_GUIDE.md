# ANIMOL 맵 제작 가이드

> 2026-11-10 정본 갱신: 아래 25개 맵 분석과 기존 LLM ZIP/JSON은 이전 배치의 참고 자료다. 현재 SW03/SW05 이름 이동·새 SW05 배치·ET-11까지의 현존 맵은 [최신 배치 보고서](ANIMOL_MAP_LAYOUT_REPORT.md), [별길 목장 최단 경로](STARWAY_SHORTEST_PATHS.md), [잔영 극장 최단 경로](ECHO_THEATER_SHORTEST_PATHS.md)를 우선한다. 가중치는 제작 제안이며 실제 입력 비용을 바꾸지 않는다.

다른 LLM에 새 맵을 의뢰할 때는 **배치 좌표, 장치 상태, 정답 입력, 장치 사용 의도**를 함께 전달한다. 기존 별길 목장 SW00~SW19와 잔영 극장 원본 ET-00~ET-05 범위의 실제 맵 25개를 기준으로, 배치 패턴과 행동 가중치를 정리했다. 원본 ET-02는 없고 화면 ET-02가 원본 ET-00을 사용한다. 별길 목장의 화면 SW01~SW20은 원본 SW00~SW19에 대응한다.

새 맵은 핵심 장치 하나의 인과관계를 먼저 정하고 보조 장치 하나를 결합하는 방식으로 설계한다. 최단 입력 수는 이동 예산의 기준으로, 행동 가중치는 조작과 사고 부담을 비교하는 별도 지표로 사용한다. 두 값을 합쳐 게임 코스트를 바꾸지 않는다.

LLM에는 [복사해서 쓰는 제작 요청문](ANIMOL_LLM_MAP_DESIGN_PROMPT.md)과 이 가이드, [전체 맵 데이터](ANIMOL_LLM_MAP_REFERENCE.json)를 전달하면 된다. [맵별 제작 참고표](ANIMOL_MAP_DESIGN_ATLAS.md)는 각 맵의 배치도와 정답 경로를 연결한다. 첨부 파일 하나로 전달하려면 [자료 묶음](Exports/ANIMOL_LLM_Map_Design.zip)을 사용한다.

배치의 바닥 수와 정적 연결 영역은 지형과 장식 점유만 반영한다. 다리·수문·풀·병아리·카트·문·바람이 만드는 실제 도달 가능성은 전체 상태 판정으로 확인해야 한다. 정적 영역이 여러 개여도 자동 이동으로 연결될 수 있고, 한 영역이어도 물체 때문에 해답이 없을 수 있다.

기존 이름에 나오는 장치가 현재 배치에 반드시 존재하지는 않는다. 예를 들어 ET-04의 제목은 ‘책장 뒤 첫 방울’이지만 현재 장치는 주사위·카트·겁쟁이 인형이다. ET-05의 제목은 ‘숫자를 돌리는 첫 길’이지만 현재 배치는 석상·유리·도미노다. LLM은 제목보다 좌표 데이터와 현재 판정을 기준으로 삼아야 한다.

## 게임 코스트와 이동 거리

현재 비용은 `g = 받아들여진 방향 입력 수`다. 최단값 `L`도 이 비용을 최소화한 값이다.

| 행동 | 실제 입력 코스트 | 맵 설계에서 고려할 점 |
|---|---:|---|
| 보통 한 칸 이동 | 1 | 이동 후 장치 턴이 진행된다 |
| 상자·별돌·양 밀기 | 1 | 플레이어가 제자리에 남아도 비용이 든다 |
| 수문 A/B 교차 | 1 | 플레이어 이동과 물 위치 교환이 한 행동이다 |
| 풍차 단계 변경 | 1 | 꺼짐→3→6→9칸→꺼짐 순환이며 무료 기다리기가 아니다 |
| 주사위 굴리기·도미노 접기 | 1 | 방향·면·막힘 조건을 만족한 입력만 받아들인다 |
| 문·반사·무빙워크·바람으로 한 입력 안에서 연속 이동 | 추가 0 | 한 입력의 실제 이동 칸 수가 1보다 클 수 있다 |
| `○` 또는 `.`로 기록한 별도 바람 자동 이동 | 0 | 유효한 `AdvanceWind` 전이이며 장치 전체를 진행시키는 범용 대기가 아니다 |
| 벽에 막힌 거절 입력 | 0 | 턴을 진행시키는 방법으로 사용할 수 없다 |

풍차 조작처럼 이동 이벤트가 없는 유효 행동 뒤에는 런타임이 즉시 바람을 진행시킬 수 있다. 이때 다음 입력을 끼워 넣는 경로를 만들면 안 된다. 이동 애니메이션 중의 예약 입력은 다음 바람 처리보다 먼저 실행될 수 있다. 바람 맵은 이 순서를 반영한 현재 `SearchStep` / `ReplayRuntimeInput`으로 확인한다.

플레이어가 같은 칸에 돌아왔다고 상태가 같아지지는 않는다. 양 소멸, 풀 제거, 물의 A/B 상태, 병아리의 지연 경로, 주사위 면, 셔터 위상, 카트 위치, 석상 조준 상태가 달라질 수 있다. 좌표만 방문 처리하는 미로 탐색으로 정답을 검증하지 않는다.

## 배치 패턴과 결합 방법

아래 패턴은 기존 배치에서 읽은 제작 용도다. 예시 맵의 모든 장치가 모든 최단 해답에 필수라는 뜻은 아니다. 각 맵의 선택한 최단 경로에서 실제로 일어난 행동은 참고표와 재생 데이터에 따로 적었다.

| 패턴 | 배치 방법 | 플레이어가 결정할 것 | 대표 원본 |
|---|---|---|---|
| P01 분기 수집과 합류 | 시작·목표 별·출구 사이에 갈림길과 재합류점을 만든다 | 목표 수만 채울지, 어느 별부터 가져올지 | SW03, SW05, SW16 |
| P02 제자리 밀기와 돌아가기 | 물체 이동축 옆에 접근로·우회로를 두고 밀어야 할 면을 바꾼다 | 밀기 횟수와 뒤편으로 돌아가는 순서 | SW00, SW02, SW17 |
| P03 번호 열쇠와 통로 공개 | 같은 번호의 별돌/소켓을 연결하고 돌의 밀기 축을 제한한다 | 맞는 돌을 먼저 넣고 열린 공간을 재사용하기 | SW00, SW12, SW15 |
| P04 소모 자원 배정 | 양과 풀을 여러 갈래에 두고 일부 풀 뒤에 별이나 길을 둔다 | 어느 양을 어느 풀에 쓸지 | SW02, SW16, SW17 |
| P05 지연 추종과 둥지 정리 | 병아리 이동 이력과 둥지 접근을 고려한 작은 고리·진입로를 둔다 | 따라오는 순서와 통로를 비우는 시점 | SW11, SW14, SW18 |
| P06 수문 A/B 교환 | 인접한 A/B 칸의 건조 상태가 다음 진입을 바꾸도록 연결한다 | 건넌 뒤 반대편 접근로를 확보하기 | SW00, SW05, SW08 |
| P07 바람 범위와 방향 전환 | 풍차 접근면, 3/6/9칸 도달점, 반사판의 열린 면과 정지점을 맞춘다 | 켤 단계와 예약 입력·바람 대기의 순서 | SW06, SW09, SW10, SW19 |
| P08 셔터 홀짝 맞추기 | 셔터 앞에 유효한 왕복 이동이나 유용한 조작 공간을 둔다 | 진입 시 열림 상태를 맞추기 | ET-00, ET-01 |
| P09 주사위 면과 접근 방향 | 주사위의 회전 경로와 밀 수 있는 면을 설계하고 목표 숫자를 지정한다 | 같은 위치라도 맞는 면으로 도착하기 | ET-00, ET-01, ET-03 |
| P10 카트와 입력 시점 | 순서가 있는 레일과 플레이어 횡단로를 교차시키고 밀림 착지점을 확보한다 | 조작 뒤 카트가 어느 칸을 점유할지 | ET-01, ET-03, ET-04 |
| P11 방향성 도미노 연쇄 | 밀 수 있는 방향과 접힌 뒤 생기는 통로를 맞춘다 | 올바른 쪽에 접근해 한 번에 통로 열기 | ET-00, ET-01, ET-05 |
| P12 석상 조준과 유리 파괴 | 조준 직선, 다음 행동의 피신 칸, 유리 바로 앞 정지 칸을 함께 설계한다 | 조준을 유도하고 다음 유효 행동에서 피하기 | ET-05의 배치에 존재하나 선택한 최단 경로의 유리 파괴는 0회 |
| P13 인형 퇴로 만들기 | 인접하면 물러나는 방향의 빈칸과 플레이어 접근면을 조절한다 | 인형을 막거나 원하는 쪽으로 물러나게 하기 | ET-04 |

핵심 장치 두 개를 결합할 때는 서로의 상태가 다음 행동을 바꾸도록 배치한다. 예를 들어 주사위 밀기가 끝난 뒤 카트가 접근로를 막거나, 양을 소모해 열린 칸이 병아리의 둥지 진입로가 되도록 만든다. 서로 떨어진 두 퍼즐을 차례대로 푸는 구성은 장치의 종류만 늘어난 결합이다.

### 현재 판정을 그대로 써야 하는 장치

양은 풀을 먹으면 사라진다. 양 한 마리를 서로 다른 필수 풀 두 곳에 배정하지 않는다. 직접 밀 때 플레이어는 제자리에 남으며, 병아리도 플레이어가 떠난 칸이 없는 입력에서는 일반 이동처럼 전진하지 않는다. 바람으로 양이 이동하거나 풀을 소비하는 경우도 있다.

수문은 단순한 ON/OFF 문이 아니다. 인접한 두 칸 중 한 칸이 젖어 있고, 올바른 건조 칸에서 짝 칸으로 건너갈 때 물 위치가 교환된다. `rightState=true`는 A가 젖었다는 기존 데이터 의미를 유지한다.

잔영 극장의 `MovingStage`는 현재 레일 카트 판정이다. 플레이어 이동 이벤트가 있는 행동 또는 극장의 제자리 밀기 뒤에 움직인다. 카트의 다음 칸에 플레이어가 있으면 한 칸 밀거나, 밀림이 막힌 경우 가능한 입력 시작 칸 P0로 되돌린다. 둘 다 불가능하면 카트가 멈춘다. 닫힌 레일은 순환, 열린 레일은 왕복하며 순서가 중요하다.

주사위 면 순서는 `[위, 아래, 북, 남, 동, 서]`다. 목표 숫자와 맞아 흡수되면 주사위가 제거되고 목표 상태가 바뀐다. 단순히 ‘그 숫자를 표시’하는 장치로 모델링하지 않는다. 도미노는 놓인 방향으로 밀어야 접히며, 한 입력으로 여러 조각이 접혀도 추가 코스트는 없다.

석상은 플레이어를 조준한 다음 유효 행동에 돌진한다. 잔영 극장의 유리를 부수면 **유리 칸에 진입하지 않고 바로 앞에서 이번 돌진을 끝낸다.** 이후 재조준과 재돌진은 가능하다. 기다리는 애니메이션 시간이나 벽에 막힌 입력으로 다음 턴을 만드는 설계는 맞지 않는다.

상세 장치 규칙과 정책 필드는 [현재 장치 판정](ANIMOL_DEVICE_RULES_CURRENT.md)을 따른다. 이 분석 범위에서 실제로 사용된 역할과 그 밖의 지원 장치를 구분하고, 분석에 없던 포털·폭탄 등의 조합은 해당 규칙을 확인한 뒤 별도로 검증한다.

## 행동에 줄 설계 가중치

다음 값은 **LLM의 초안 비교를 위한 제안 계수**다. 플레이 테스트로 보정한 난이도 모델은 아니다. 실제 코스트는 계속 방향 입력 1, 무료 바람 0으로 둔다.

| 직접 조작 분류 | 기본 가중치 b | 부여 이유 |
|---|---:|---|
| 보통 이동 또는 아래 분류 밖 행동 | 1.00 | 기준 조작량 |
| 상자·별돌 등 물체 밀기 | 1.50 | 물체 위치와 이후 접근면 관리 |
| 양 밀기 | 1.50 | 물체 이동을 제어하는 기본 부담 |
| 수문 건너기 | 1.75 | 물의 A/B 상태까지 갱신 |
| 도미노 밀기 | 1.75 | 접근 방향과 연쇄 결과 확인 |
| 풍차 단계 변경 | 2.00 | 범위와 자동 이동 결과 예측 |
| 주사위 굴리기 | 2.50 | 위치와 면 방향을 함께 관리 |
| 거울 회전 | 2.00 | 새 맵에서 사용할 때의 제안값이며 이번 25개 재생 표본은 0회 |
| 무료 바람 전이 자체 | 0.00 | 조작량 합계에는 더하지 않고 앞선 결정의 결과로 설명 |

우선 각 유효 입력에 직접 조작 분류 하나를 부여하고 `W0 = Σ b`를 계산한다. 한 입력의 직접 조작을 두 번 합산하지 않는다. 참고표의 W0는 이 방식으로 계산했으며, `보통 이동 또는 기타`에는 위험 회피나 장치의 자동 반응을 포함한 이동도 들어간다.

사고 부담은 정답의 **중요한 결정 입력**에만 아래 수정치를 더한다. LLM은 수정치를 붙인 입력 번호, 다른 선택이 실패하는 이유와 영향을 받는 상태를 적어야 한다.

| 수정치 | 추가 점수 | 붙이는 조건 |
|---|---:|---|
| T 위상 맞추기 | +0.50 | 그 입력의 셔터·카트 위상이 실제 선택을 제한함 |
| H 이력 관리 | +0.75 | 병아리 지연 경로나 주사위 이전 회전 이력이 결정에 필요함 |
| R 되돌릴 수 없는 확정 | +0.75 | 양 소모, 영구 통로 변화 등 잘못 선택하면 Undo/재시작이 필요한 상태 전환 |
| C 장치 사이 의존 | +0.50 | 서로 다른 두 규칙의 결과를 함께 만족해야 함 |

`wᵢ = min(3.50, bᵢ + 0.50Tᵢ + 0.75Hᵢ + 0.75Rᵢ + 0.50Cᵢ)`, `W = Σ wᵢ`로 제안한다. 각 수정치는 같은 입력에 한 번만 적용한다. 주사위 기본 가중치에 이미 포함된 ‘면 확인’만으로 H를 다시 더하지 않는다. 석상 하나가 움직였거나 병아리 하나가 따라왔다는 이유만으로 매 입력을 가중하지도 않는다. 유리 파괴를 위해 조준·회피를 맞추는 결정처럼 그 상태가 선택을 제한한 근거가 필요하다.

예를 들어 이동 24회와 상자 밀기 6회는 `L=30`, `W0=33`이다. 그중 두 번의 밀기에만 위상 조건이 있으면 W는 34가 된다. 양을 먹이는 한 입력의 기본값 1.50에 소모 확정 R 0.75를 더하면 2.25다. 비용을 2.25턴으로 변경하지 않는다.

같은 L의 맵을 비교할 때 W0, 중요 결정 수, 비가역 분기 수, 동시에 기억할 상태 수를 함께 본다. 가중치를 높게 주기 위해 장치를 반복 조작시키거나 안전한 복도를 늘리지 않는다. 탐색기의 방문 상태 수·계산 시간은 알고리즘과 상태 표현의 영향도 크므로 사람의 난이도 점수로 사용하지 않는다.

## 길이와 난이도 진행 제안

현재 별길 목장은 22~77입력, 잔영 극장은 26~49입력이다. 기존 순서는 최단 입력 수가 단조롭게 증가하지 않는다. 새 맵의 목표 구간은 다음처럼 초안을 잡고 실제 풀이와 플레이 테스트로 조정한다.

| 제작 단계 | 목표 L | 핵심 구성 | 결정 부담 관리 |
|---|---:|---|---|
| 규칙 소개 | 24~35 | 핵심 규칙 1개, 눈에 보이는 결과 | 핵심 판단 1~2곳, 치명적 분기 전 안전한 확인 공간 |
| 규칙 응용 | 35~50 | 핵심 1개와 보조 1개 | 판단 2~4곳, 돌아와 상태를 재사용하는 구간 |
| 복합 문제 | 50~70 | 앞서 배운 규칙 2~3개 | 자원 배정 또는 이력 관리 1개를 중심으로 결합 |

이 구간은 기존 최솟값·최댓값을 그대로 난이도 등급으로 바꾼 결과가 아니다. SW14는 22입력이지만 병아리 3마리가 있고, SW02는 77입력 중 양 밀기 14회와 물체 밀기 6회가 있다. 길이와 장치 수만으로 튜토리얼이나 어려운 맵으로 분류하지 않는다.

이동 예산은 최단성 확정 뒤 정한다. ‘정답 그대로 풀기’가 목표면 예산 `B=L`, 탐색 여유를 주려면 예시로 `B=L+ceil(0.15L)`를 제안할 수 있다. 여유 비율은 별도 제품 결정이며 이번 작업에서는 HUD나 기존 예산을 바꾸지 않았다. 인지 가중합 W를 이동 예산 B로 사용하지 않는다.

## 맵을 만드는 순서

1. 플레이어가 배울 인과관계를 한 문장으로 쓴다. ‘양 2마리를 필수 풀 2곳에 배정하고 둥지 앞을 비운다’처럼 관찰 가능한 결과로 적는다.
2. 별 목표 수, 출구 조건, 필수 장치 사용 사건을 정한다. 선택 별이 있으면 목표 수와 배치 수를 다르게 명시한다.
3. 핵심 장치의 접근면·작동 칸·결과 칸부터 놓고, 시작과 출구를 연결한다. 장식은 통행을 바꾸므로 점유 칸까지 기록한다.
4. 후보 정답을 먼저 적고 입력별 상태 변화를 기록한다. 제자리 밀기와 자동 이동을 포함해 비용을 센다.
5. 잘못된 선택 두세 가지와 돌아오는 방법을 설계한다. 양 소모 등 비가역 선택은 Undo/재시작이 필요한 지점도 밝힌다.
6. 우회 해답과 장치 미사용 해답을 탐색한다. 의도보다 쉬운 해답이 있으면 필수 통로·목표 조건을 다시 설계한다.
7. 원래 런타임 판정으로 경로를 재생하고 정확 탐색으로 L을 확정한다. 초안 길이와 L을 비교해 불필요한 왕복을 줄인다.
8. L과 별도로 행동 가중합과 중요 결정 근거를 검토하고, 최종 예산과 난이도는 플레이 테스트로 조정한다.

## 필수 장치를 검증하는 기준

현재 25개 맵의 `goals` 목록은 모두 비어 있다. 승리는 필요한 별 수와 출구 도달로 정해진다. 주사위 목표·둥지·유리 등의 사용을 필수로 의도했다면 그 장치가 길을 여는 배치인지, 또는 별도의 지원되는 목표 조건이 필요한지 확인해야 한다.

선택한 최단 경로에서 ET-04는 주사위를 한 번 밀지만 `dice_goal_absorbed`는 0회다. ET-05는 석상 돌진이 한 번 발생하지만 유리 제거는 0회다. 이 결과만으로 해당 장치가 모든 해답에서 불필요하다고 단정할 수는 없지만, 그 장치의 완료를 요구하지 않는 승리 경로가 존재함은 확인된다.

필수 행동을 증명하려면 탐색 상태에 ‘이 사건을 수행했는가’를 추가하고 **그 사건을 한 번도 수행하지 않은 승리 경로가 있는지** 검사한다. 장치 그림을 지우거나 통로를 막는 실험만으로 필수 사용을 증명하지 않는다. 현재 자료 묶음은 기존 정답의 사건 횟수를 제공하며, 이 별도 제약 탐색을 실행한 결과로 표시하지 않는다.

새 맵 검수에는 다음을 포함한다.

- 구조: 경계 안 좌표, 지형/장식 점유, 시작 가능 여부, 고유 장치 ID, 유효한 그룹·번호·둥지·레일 연결.
- 경로: 모든 입력 수락, 실제 비용 일치, 별 수와 추가 목표 충족, 출구에서 승리.
- 의도: 핵심 장치 미사용 승리 검사, 선택 별 때문에 생긴 우회, 양과 풀의 중복 배정, 주사위 면 생략, 카트의 입력 시작 칸 복귀.
- 실패와 복구: 유효 행동으로만 타이머가 진행되는지, 자원 소모 후 막힘, Undo 복원, 입력 예약·무료 바람 순서.
- 최단성: 정확 BFS/0-1 BFS 또는 과대평가하지 않는 하한을 쓰는 A*. 상한·취소는 미확정, 전체 상태 소진만 도달 불가로 기록.

LLM이 적은 경로는 실행 전까지 `candidate`다. 단순 경로 재생 성공은 `replay_verified`, 정확 탐색으로 더 짧은 해답이 없음을 확인한 경우에만 `optimal_confirmed`로 구분한다. 이 상태명은 제작 의뢰용 표기이며 기존 런타임 카탈로그의 저장 형식을 바꾸지 않는다.

## LLM이 반환할 제작 명세

요청문에는 새 제안 ID, 테마, 격자 크기, 목표 L 범위, 핵심 패턴, 필수 사용 사건, 보조 규칙 수를 지정한다. LLM은 다음 결과를 하나의 완결된 제안으로 반환한다.

| 항목 | 요구 내용 |
|---|---|
| 제작 의도 | 배울 규칙, 핵심 결정, 비교한 기존 원본 ID |
| 전체 배치 | width/height, terrain, start/exit, bubbles/targetBubbles, 장식 점유 좌표 |
| 상태와 연결 | devices의 역할·방향·변형·숫자·면·그룹, ranchV13Art, nests, railPaths, water, goals, 정책 기본값 |
| 후보 정답 | NESW와 필요 시 `.`를 사용한 입력열, 유효 입력 수, 중요 입력의 전후 상태 |
| 행동 원장 | 입력별 직접 조작 분류, 기본 가중치, 수정치의 근거, W0와 W |
| 잘못된 선택 | 최소 2가지의 상태 변화와 회복 방법 |
| 검증 상태 | 실제 실행한 검사와 요청할 검사, 미확정 최단값을 확정으로 쓰지 않기 |

새 명세는 `ANIMOL_MapProposal_v1`이라는 **제안용 데이터 규약**으로 전달한다. Unity .asset/.meta를 생성하거나 곧바로 가져오는 설치기는 포함하지 않는다. 기존 맵 ID와 제공 GUID를 복사해 덮어쓰지 않으며, SW00을 포함한 현재 원본은 유지한다. 맵 제작 범위에서 UI·입장·재화·저장·카메라·피드백 정책을 변경하지 않는다.
