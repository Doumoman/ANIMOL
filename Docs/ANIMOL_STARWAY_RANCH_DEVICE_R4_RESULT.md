- `MCP_INBOX/ANIMOL_STARWAY_RANCH_CHICK_NEST_RETURN_R4_PATCH.zip`의 기준 R3 카탈로그 SHA-256 `5c82bb2c11ae11911f59291bd23c6421810a50a140a62e3084cac030b63db933`가 기존 설치본과 일치했다. 기존 `Assets/ANIMOL/Art/ANIMOL_STARWAY_RANCH_DEVICES_V13`에만 패치를 병합했고, 기존 `.meta`와 GUID는 보존했다. 해시가 일치한 구 `.tmp` 7개만 제거했다.
- R4 카탈로그와 Pin은 `513a878cdaa6efe7a88aa5877acda3f198433f4d43618e6f1319d1c37643ab0a`로 일치한다. 실사용 PNG 373개, 카탈로그 클립 170개다. 기존 빌더의 검사 프리팹 소유권 호환 수정은 유지하고 `SHA256SUMS.txt`의 빌더 항목을 설치된 파일 해시로 맞췄다. 443개 항목 모두 파일 해시와 일치한다.
- 원 프로젝트 Unity Editor에서 `RanchDevicesV13Builder.Build`를 실행했다. `_GeneratedV13/RanchDevicesV13Catalog.asset`은 `Validate`를 통과했고 Sprite 373개, 클립 170개, `InspectionOnly_AllClips.prefab`의 전용 시각 170개를 확인했다. 기존 생성 에셋 GUID를 보존하고 `.anim` 170개 및 새 에셋의 `.meta`를 반영했다.
- `PuzzleDeviceSession.EnterNest`가 귀환 성공을 확정한 뒤에만 `ChickReturned` 시각 이벤트를 낸다. 실제 이동 이벤트에서 접근 경로를 기록하고, 최종 이동 벡터·둥지 셀 ID·방향을 전달한다. 추종 해제와 위치는 기존 세션 스냅샷, Undo, Reset 권한에 그대로 남는다. 연출은 코스트나 장치 턴을 추가하지 않는다.
- `PuzzlePrototypeController`는 병아리의 기존 V12 이동이 둥지에 도착한 후 원래 렌더러를 숨기고 R4 도착 연출을 시작한다. 보드 세대와 행동 번호를 포함한 이벤트 ID를 사용하며, Undo/Reset/Load의 오래된 코루틴은 세대 검사를 통과하지 못한다.
- `PuzzleMapView`는 둥지 셀마다 전용 `RanchChickNestReturnVisualR4`와 자식 `RanchDeviceVisualV13` 하나를 생성한다. 같은 이벤트를 중복 재생하지 않고, 바쁜 둥지의 다른 귀환은 표현 큐에 둔다. 복원과 재활성화 때 현재 병아리 상태와 저장된 방향으로 `nest/idle` 또는 `nest_return/<방향>/occupied`를 적용한다. 마지막 접근이 인접한 실제 이동이 아니면 임의 도약 경로를 만들지 않고 확정된 앉은 자세를 표시하며 진단을 남긴다.
- 병아리 자체는 V12 추종·길막 판정을 유지한다. 맵 제작기는 기존 병아리가 있으면 둥지 목표 칸을 바로 연결하고, 병아리가 없으면 둥지 칸 선택 후 병아리 시작 칸을 선택해 같은 시나리오에 저장한다. 수로 R3와 양 R2의 판정·표현은 유지했다.
