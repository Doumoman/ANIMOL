# 별길 목장 1-1~1-3 맵 설계 분석 보고서

대상은 1-1=SW01, 1-2=SW02, 1-3=SW03이다. 맵을 새로 설계하거나 배치를 수정한 문서가 아니다. 근거는 `Assets/ANIMOL/StarwayMapPack/Editor/Data/UnityInput/SW01~SW03.json`의 최종 입력, 같은 폴더의 `UnityReplay` 단계 기록, 현재 네이티브 `SW01~SW03_MapData.asset`, 그리고 `PuzzleDeviceSession`이다. 좌표는 오른쪽이 +x, 위가 +y이며 N/E/S/W는 위/오른쪽/아래/왼쪽 입력이다.

## 공통 규칙과 설계 관찰

- 방울 세 개를 순서와 관계없이 모은 뒤 출구 칸에 도착하면 클리어한다. 세 맵 모두 `targetBubbles=3`, `goals=[]`, `costLimit=0`이다. 양을 풀에 보내는 일은 통로와 방울을 여는 과정이며 별도의 승리 조건이 아니다.
- 세 맵 모두 18×20 크기의 불규칙 통행 지형이다. 격자 전체를 바닥으로 채우지 않는다. 플레이어는 짧은 국소 이동으로 병아리의 추종 위치를 조정한 다음 긴 경로로 방울과 출구를 잇는다.
- 세 맵의 입력 데이터에는 나무·금속 박스가 없다. 따라서 이번 박스 밀기 규칙 변경은 이 세 맵의 **패키지 참고 경로**를 직접 바꾸지 않는다.
- 다음 설계 철학은 배치와 참고 경로에서 추론한 것이다. 병아리의 이동을 초반 안전한 순환 동선에서 가르치고, 멀리 놓인 양·풀·방울을 향해 맵 전체를 가로지르게 한다. 방울 3개의 위치는 출구로 바로 달리는 경로를 막고, 마지막 방울을 얻은 뒤 출구로 복귀하는 흐름을 만든다. 세 맵은 같은 장치 조합을 서로 다른 시작 방향과 동선으로 변주한다.

## 맵별 배치와 패키지 참고 해법

| 스테이지 | 시작 / 출구 | 방울 좌표 | 병아리 → 둥지 | 양 → 풀 | 참고 입력 / 성공 수 |
|---|---|---|---|---|---|
| 1-1 SW01 | (4,8) / (14,15) | (4,6), (8,9), (12,16) | (4,7) → (2,8) | (12,15) → (12,16) | `NWSESSNNNNEEEESNNNNNEEEENNNSSEEN` / 32 |
| 1-2 SW02 | (10,18) / (2,9) | (12,18), (2,10), (2,14) | (11,18) → (10,16) | (2,13) → (2,14) | `SWNEEEWWSWSWWWSSWWSSWWNNNSSSSS` / 30 |
| 1-3 SW03 | (4,4) / (13,10) | (2,4), (12,8), (12,12) | (3,4) → (6,3) | (12,11) → (12,12) | `ESWNWWEENNEEEESSEENNEENNNNNNNSSE` / 32 |

`UnityReplay`의 입력별 상태 기록에서 SW01은 6·15·27번째에 방울을 얻고 25번째에 양이 사라진다. SW02는 6·25·29번째에 방울을 얻고 23번째에 양이 사라진다. SW03은 6·24·29번째에 방울을 얻고 27번째에 양이 사라진다. 각각 마지막 입력에 출구에 도달한다. 이는 제공된 설계 자료의 기록이지, 현재 열려 있는 Unity 맵에 대한 이번 실행 통과 결과가 아니다. 최단해라는 근거도 없다.

## 현재 에셋과 검증 상태

2026-10-29 Unity 6000.3.8f1에서 `Starway20NativeTests`를 실행했다. 2개 중 1개가 실패했으며, 전체 재생은 `SW01 step 1: playerBefore`에서 중단됐다. 패키지와 디스크의 SW01 시작은 (4,8)이지만 **열려 있는 Unity Editor의 메모리 에셋 시작은 (2,11)**이었다. SW03도 패키지·디스크 (4,4)와 Editor 메모리 (5,10)이 다르다. SW02는 (10,18)로 같았다. 현재 Editor에는 저장되지 않은 맵 편집 상태가 있으므로 패키지 정답을 현행 맵의 검증된 정답으로 표시할 수 없다. 해당 편집 상태를 덮어쓰거나 저장하지 않았다.

AI 학습 자료에서는 위 표의 배치와 해법을 **패키지 기준 사례**로만 사용해야 한다. 새로 편집한 SW01·SW03을 학습 대상으로 확정하려면 먼저 그 에셋을 저장한 후 실제 `PuzzleDeviceSession`에서 입력별 수집·병아리·양 상태와 승리를 다시 계산해야 한다. 현재 보고서로는 그 두 맵의 새 정답 움직임을 확정하지 않는다.
