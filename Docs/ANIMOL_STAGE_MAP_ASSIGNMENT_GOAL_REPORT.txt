1. 결론

새 Scene 맵 에디터는 구현되어 있다. 하지만 제작한 맵을 원하는 캠페인 스테이지에
할당하는 제작용 UI/transaction은 아직 없다.

스테이지 선택 UI → StageLaunchUseCase → CampaignLaunchContext → 런타임 loader의
기본 코드 경로는 이미 존재한다. 따라서 전체가 미연결인 것은 아니다.
현재 부족한 것은 맵 제작과 스테이지 데이터 할당을 연결하는 제작 흐름,
운영 실행 준비, 그리고 실제 스테이지 선택 화면부터 플레이까지의 통합 검증이다.

맵 저장 완료, 스테이지 할당 완료, 운영 Ready는 각각 다른 상태로 취급해야 한다.
V4의 시험 플레이 성공으로 운영 Ready 또는 보상 자격이 생기지는 않는다.

2. 새 에디터를 여는 위치

Unity 상단 ANIMOL > Map Editor > Open Scene Editor V4
단축키: Ctrl+Shift+M
창 제목: ANIMOL · Map V4

Project에서 Assets/ANIMOL/Data/Campaign/Maps/T01-S02.asset 같은
StageMapDefinition을 선택한 뒤 위 메뉴를 실행한다.
Maps 폴더는 실제 맵 데이터이고, Stages 폴더는 캠페인 슬롯 정의이다.

맵 선택 창의 Open/Create는 맵을 선택/생성한다.
그 뒤 '새 맵 제작기 열기'로 Scene View 편집기에 들어간다.
선택/생성 또는 저장만으로 Stages의 mapDefinition이 자동 할당되지는 않는다.

이번 조사에서 T01-S02를 새 창으로 직접 열었다.
Play Mode=False, 창 활성=True, 해당 맵 hash/revision 불변을 확인했다.
별도의 설치 프로그램이나 게임 내 사용자용 편집 화면은 아니다.

3. 실제 프로젝트 데이터 확인 결과

Unity Editor API로 현재 CampaignCatalog 및 100개 Stage asset을 읽었다.

- 테마 5개 × 스테이지 20개 = 100개.
- mapDefinition 참조가 있는 스테이지: 1개, T01-S01.
- ContentAvailability.Ready: 0개.
- T01-S01 참조:
  Assets/ANIMOL/Data/Campaign/Maps/T01-S01.asset
  mapTemplateId=DEV-T01-S01-PROTOTYPE, map revision=199.
  현재 availability=Invalid.
  실제 차단 사유:
    Fast-clear reward policy is not approved.
    Replay reward policy is not approved.
    Human completion review for this exact version/hash is missing.

다음 7개는 같은 StageId의 맵 asset이 존재하지만 stage.mapDefinition은 비어 있다:
  T01-S02, T01-S03, T01-S04, T01-S05, T01-S06, T01-S07, T02-S01.
맵 asset의 존재를 맵 완성/운영 적합 판정으로 해석하지 않았다.

Lobby.unity를 저장하지 않는 preview scene으로 읽어 확인한 사항:
- UI_CommonRoot의 CampaignUiPresenter 1개.
- 위 presenter의 catalog는 실제 CampaignCatalog.asset에 연결됨.
- StageCard 버튼 20개, StageStartButton 1개.

ThemeRuntime_T01~T05 실제 씬 asset을 같은 방식으로 확인한 사항:
- 5개 모두 Build Settings에서 enabled=True.
- 각 씬 StageMapRuntimeLoader 1개, CampaignRuntimeBootstrap 1개.
- 각 씬에 DevPlayerController 0개.
- 각 loader의 objectTypeRegistry 참조가 비어 있음.
현재 Bootstrap은 기존 플레이어를 찾아 roster를 설정할 뿐 생성하지 않는다.
따라서 loader 호출 코드가 있다는 사실만으로 완성된 운영 플레이 흐름이라고
판정할 수 없다. 개발 시험 세션과 운영 씬의 구성을 각각 연결/검증해야 한다.

4. 이미 존재하는 연결 경로

CampaignCatalog.Themes → ThemeDefinition.Stages
  → CampaignStageDefinition.MapDefinition
  → CampaignUiPresenter의 StageStartButton / LaunchSelectedStage
  → ContentAvailabilityResolver + progression unlock 검사
  → StageLaunchUseCase.Launch
  → CampaignRunSetup.Map = stage.MapDefinition
  → CampaignLaunchContext.Set
  → ThemeRuntime_{ThemeId} 씬 로드
  → CampaignRuntimeBootstrap.Awake / Consume
  → StageMapRuntimeLoader.Load(Launch.Setup.Map)
  → 기존 v3 구조물 점유/아트/operational physics owner 경로

즉 이미 연결된 정본 맵을 편집하면 같은 참조를 통해 읽을 수 있는 구조다.
독립적인 신규 맵이나 미할당 슬롯을 저장하는 것까지 자동 연결하지는 않는다.

현재 제작 경로:
  TerrainEditorSceneEditor → TerrainEditorAdapter → Bridge/Integration
  → StageMapDefinition 저장.
TerrainEditorAdapter.Save는 맵을 검증/저장하며 CampaignStageDefinition을 수정하지 않는다.
CampaignMapEditorWindow.SelectOrCreate도 규칙 경로의 맵을 생성/선택할 뿐 할당하지 않는다.
기존 UiBuildPipeline.M7/M8에는 T01-S01용 특정 데이터 연결 코드가 있지만
일반적인 '임의 제작 맵을 선택한 스테이지에 할당' 서비스/UI는 아니다.

5. 다음 구현 목표와 작업 순서

목표: Scene에서 제작한 정본 맵을 캠페인 슬롯에 명시적으로 할당하고,
기존 스테이지 진입 UI에서 그 맵이 정확히 로드되도록 연결한다.
기존 저장 schema/catalog v3, 점유/충돌, 고정 동물, 진행 잠금, 보상/Ready 정책은 유지한다.
플레이어가 보는 스테이지 선택 화면에 제작용 asset 선택 기능을 넣지 않는다.

AS01. 할당 상태 조회와 데이터 계약
- 스테이지 ID, 현재 할당 맵, 선택한 제작 맵, theme, version/hash, 차단 사유를 표시한다.
- 경로/파일명으로 런타임 맵을 추측하지 않고 실제 asset 참조를 사용한다.
- stageId/themeId 불일치와 한 맵의 의도치 않은 중복 사용을 검증한다.
- 규칙 경로의 맵과 실제 할당 참조가 다르면 조용히 다른 맵을 편집하지 않게 표시한다.
- mapTemplateId와 runtimePolicy/고정 동물/시간/보상 설정의 실제 저장 주체를 대조한다.
  현재 stage와 map 양쪽에 있는 관련 데이터를 임의 기본값으로 덮어쓰지 않는다.

AS02. 제작용 '스테이지에 할당' 기능
- 맵 선택 창 또는 V4 정보 패널에서 대상 테마/스테이지를 선택한다.
- 현재 참조와 새 참조의 변경 내용을 보여주고 명시적 할당 명령으로 적용한다.
- 기존 할당 교체는 일반 맵 저장과 분리한다.
- 변경 전 백업, 모든 변경 asset의 Undo, 후보 검증, 실패 시 원상복구를 갖춘
  단일 authoring transaction으로 저장한다.
- 참조 할당만으로 맵의 지형 revision을 불필요하게 증가시키지 않는다.
- 저장하지 않은 candidate나 DEV-UI-V4 같은 검증 fixture를 자동 등록하지 않는다.
- 할당은 제작 중인 맵에도 가능하되 운영 진입은 기존 Ready 조건으로 계속 차단한다.

AS03. 기존 스테이지 UI와 준비 상태 연결
- 기존 CampaignCatalog/StageId 기반 카드와 상세 화면을 그대로 사용한다.
- 미할당, 할당됨/검증 미완료, Ready, 진행 잠김을 구분해 표시한다.
- 시작 버튼은 Ready와 progression unlock을 모두 만족할 때만 활성화한다.
- 현재 RefreshStageCards/RefreshThemeCards의 '제작 중' 고정 문구를 실제 상태와 연결한다.
- 맵 수정으로 기존 완주 검증이 무효화되면 해당 version/hash의 재검증 필요를 표시한다.
- 보상 정책 승인이나 사람의 완주 증거를 자동 생성하지 않는다.

AS04. 운영 진입과 재도전 통합
- ThemeRuntime 씬의 플레이어/PlayerStart, 객체 registry, 카메라, 입력, HUD와
  방울/체크포인트/출구/타이머/결과 서비스를 실제 운영 흐름에 맞게 연결한다.
- Bootstrap.Awake의 Load와 loader.Start의 Load가 한 진입에서 중복 실행되지 않는지
  확인한다. 현재 두 호출 위치가 있으므로 초기화/객체 중복 생성 방지를 검증한다.
- 스테이지에서 전달된 동일한 Map asset, instanceId, maskHash, owner/충돌을 복원한다.
- 재시작·다음 스테이지·로비 복귀에서 이전 맵/동물/객체 상태가 남지 않게 한다.
- 기존 개발 시험 플레이와 운영 보상 지급 경로를 혼동하지 않는다.

6. 완료 기준

1) 제작 맵 선택 → 대상 슬롯 할당 → 저장 → 에디터 재오픈 후 동일 참조 복원.
2) 할당 교체/취소/Undo/Redo가 관련 asset 전체에서 일관되고 기존 맵 내용은 보존됨.
3) 맵이 없는 슬롯, 다른 테마/ID, 손상된 hash/version/owner, 유효하지 않은 객체는 차단됨.
4) 맵 파일만 있는 슬롯과 실제 할당된 슬롯의 상태를 UI에서 구분할 수 있음.
5) 로비 → 테마 → 스테이지 → 상세 → 시작으로 정확한 맵이 실행됨.
6) 실행 맵의 구조물/일반 셀/장식/객체/PlayerStart와 충돌이 정본과 일치함.
7) 고정 동물, 3개 방울, 출구, 체크포인트, 제한시간, 재도전 seed가 기존 규칙을 따름.
8) Ready 미달과 진행 잠김을 우회할 수 없고 시험 플레이가 운영 보상을 지급하지 않음.
9) 기존 스테이지 100개와 사용자 맵의 데이터, 로비 UI/배경은 의도한 할당 외 보존됨.
10) Unity compile, 관련 EditMode/PlayMode, 실제 UI 버튼을 통한 진입/복귀를 검증하고
    맵 ID/version/hash와 결과 화면을 기록함.

검증 대상으로 기존 CampaignCoreTests, M7CampaignMapRunTests,
M7MapEditorTests, TerrainStructureIntegrationTests, TerrainStructurePlayModeTests와
신규 할당 transaction/UI→runtime 통합 테스트를 포함한다.
새 입력 거절/성공 연출을 추가하면 CommercialPolishPolicyTests도 실행한다.
